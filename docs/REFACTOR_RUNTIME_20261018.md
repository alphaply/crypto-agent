# 运行与交易重构（2026-10-18）

本次范围由需求访谈逐项确认，变更记录为 `refactor-trading-runtime-and-storage`。完整验收由用户进行，开发期间仅运行针对性小测试、语法检查和构建。

## 任务排队

运行名额满后，已受理的定时、新闻和定投任务进入 PostgreSQL 队列，不因等待超时跳过，也不合并不同触发。每个真实触发有固定身份，重复轮询同一触发不会再入队。一个策略的上一轮未结束时，下一轮继续等待；其他可运行策略可以使用空闲名额。

定投每个已入队时槽保留原身份；积压三轮会依次执行三轮，各自仍受对应周期预算、任务总预算及账户余额约束。运行时读取最新模型、策略参数、金额、行情和账户状态。暂停或删除任务、修改交易账户/交易所/标的/模式会取消尚未开始的旧项。已经发出的订单不受清理队列影响，仍按原身份核验。

尚未开始的项在重启后继续排队。已经开始但中断的轮次不会直接整轮重跑，以免模型生成新的工具调用身份重复下单；原交易账本继续核对已尝试的操作。本次没有新增停机期间未入队时点的补建，也没有新增跨机器调度。

删除或更换账户后，未完成交易的证据仍保留。继续向交易所核对需要原账户授权仍然有效；原授权不可用时保留未知状态，不借用新账户查询，也不换身份重发。队列取消和删除任务不代表交易所订单已撤销。

页面把当前运行与等待数量、下一等待项分开展示。后续排队项不会覆盖当前运行的分析和工具进度。

## 人工与 Agent 共管

旧 `strict_owned`、`exclusive_scope` 配置统一为可信交易授权范围内共同管理。原创建者与来源仍用于历史审计，不构成独占权限。不同账户、市场和用户模拟资金继续隔离。

独立退出模式中，人工加减仓、全平、重开及挂单变化更新真实状态和历史。发现变化本身不授权后台撤单、补仓、补平或缩量。Agent 下一次运行仍可按最新状态决策。固定数量超过实际可执行数量时明确返回冲突；显式全部平仓使用其既有交易所语义。

强制止盈止损模式继续维护系统中最新成功保存的目标。Agent 和已登录前端都能调整，无需额外输一次密码。外部在交易所修改或撤掉保护单，不替换系统保存的目标。前端和 Agent 成功保存的新设置替代旧设置；本次没有额外增加“已保存目标不可清除”的产品限制。

## 内部职责

- 旧工具入口保留，内部复用相同的执行和权限边界；重复的入口检查收敛，实际金融写入前需要的最新事实仍须核验。
- 未知下单结果保留原操作与订单身份，不通过换 ID 重发。交易所受理、实际成交、后台核验分别记录。
- PostgreSQL 继续使用现有连接池和增量迁移；数据访问与统计计算按业务拆分，保留原值、来源、金额、时间及收益口径。
- 看板批量读取最新运行/摘要状态。现货订单同步与展示计算分开，订单状态和累计成交共用一次事务，刷新时机及失败信息保留。
- 数据库结构检查不再顺便删除孤立保护历史；历史清理保留仍被排队/执行引用的运行记录。
