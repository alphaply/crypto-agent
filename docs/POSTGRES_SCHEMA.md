# PostgreSQL 存储结构与开发说明

运行数据库固定为 PostgreSQL 17。空库初始化只执行编号迁移和 LangGraph setup，不连接或读取 SQLite 文件。数据库连接只来自 `DATABASE_URL`；业务模块和配置单例不参与迁移。导入模块不加载 `.env`，只有 CLI 显式读取当前目录 `.env`，且不覆盖进程/Compose 环境变量；测试通过 `PYTHON_DOTENV_DISABLED=1` 禁止读取。

## 结构版本与部署

```sh
python -m backend.storage.migrate
python -m backend.storage.migrate --check
```

迁移文件位于 `backend/storage/migrations/`。`public.schema_migrations` 保存文件版本、文件名、SHA-256 和成功时间；校验前只规范化 Windows/Linux 换行，防止同一 Git 源码跨系统构建出现假冲突。每个应用迁移及其版本记录同事务提交；失败版本整笔回滚，已完成版本保留。已应用文件不能修改，升级必须增加下一编号文件。结构缺失、版本超前、校验和改变均明确失败。

部署迁移器使用 PostgreSQL session advisory lock。等待者循环执行 `pg_try_advisory_lock`，每次查询立即结束事务，避免阻塞 LangGraph 的 `CREATE INDEX CONCURRENTLY`。默认等待最多 60 秒。Web/scheduler 只调用 `check_schema(conn)` 检查版本，不执行 DDL。

业务表固定在 `public` schema；迁移会显式选择 public，应用启动检查当前 schema 也是 public。如果数据库角色或 URL options 指向其他 schema，启动明确拒绝并要求修正，不静默覆盖目标连接的配置。检查点在独立 `checkpoints` schema，使用已锁定的 `langgraph-checkpoint-postgres` 原生结构。依赖 setup 需要 autocommit（包含并发索引），因此和应用迁移分阶段记录。`public.schema_migration_stages` 保存检查点包版本、迁移内容校验和及 running/failed/complete；失败时整体命令非零退出。重试会延续依赖已完成版本，只有全部完成才允许应用启动。

## 类型与身份

- 毫秒、计数、原整型布尔使用 `BIGINT`；价格、数量与原 SQLite REAL 使用 `DOUBLE PRECISION`。
- 原 JSON payload 保留为 `TEXT`，不重新排序参与哈希的文本；查询按需转换。检查点二进制使用 `BYTEA`。
- 原 `INTEGER PRIMARY KEY` 保留字段名并使用 `BIGINT GENERATED BY DEFAULT AS IDENTITY`。其 `storage_id` 为同一主键的 stored generated alias，保留 API 身份。
- 其他表追加独立 `storage_id BIGINT GENERATED BY DEFAULT AS IDENTITY UNIQUE`。原业务复合键与唯一约束保持；不得用 `ctid` 或序列顺序代表提交顺序。
- INSERT 使用明确列清单；不得复制 `SELECT *` 到含 generated 字段的目标。自增 ID 使用 `RETURNING` 取得。

## 来源版本与触发器

| 机制 | 来源 | 同事务作用 |
| --- | --- | --- |
| `protection_activity_write` | `real_protection_plans` INSERT/UPDATE/DELETE | 更新/删除活动投影；非法或超过预算 payload 保持 UNKNOWN |
| `paper_*_audit` | Paper accounts/orders/events/batches INSERT/UPDATE | 对相同原始记录增加 `paper_raw_versions.revision` |
| `execution_*_revision` | execution fills/order links、protection events INSERT/UPDATE/DELETE | 对原账户/标的增加 `execution_source_revisions.revision` |
| `plan_*_revision` | orders、protection plans/events INSERT/UPDATE/DELETE | 按原扫描 symbol 范围增加 `plan_source_revisions.revision` |
| `paper_operations_revision` | paper operations INSERT/UPDATE/DELETE | 对 namespace/user 增加 `paper_source_revisions.revision` |

更新影响旧、新范围时两者都递增，范围按字典序加锁。较小 identity 晚提交、旧行更新和删除都能改变来源版本。读方仍需在一致快照内记录版本并在发布时锁定复核，或保留原循环扫描；版本本身不替代业务去重，也不触发交易重放。

保护触发器读取连接级 `crypto.capacity_enabled` 与 `crypto.max_record_bytes`，由连接入口映射已有 `RUNTIME_CAPACITY_ENABLED`/`RUNTIME_MAX_RECORD_BYTES`。默认 true/4194304；不改变原预算开关含义。全新库投影进度直接 complete；后续模式变化沿用运行期 DML 重扫。

`0003` 补齐 JSON 转换的 `22P05` 错误处理：原始 JSON 文本含 `\u0000` 等 JSONB 无法表示的转义时，保存原文，保护活动投影标记 UNKNOWN，不让投影维护拒绝原始记录。已应用的 `0001`/`0002` 文件保持不变。

`0004` 补齐这类保护事件的来源版本：JSONB 无法解析时，按原事件行的 symbol（包含原有合约后缀等价关系）及已有 order link 的 config 关联，保守递增已经存在的相关账户版本。它只让既有快照重新校验，不推断新归属、不修改 Python 的业务过滤和重建查询。正常 JSON 仍只递增 payload 明确的账户/标的。专用真实 PostgreSQL 回归 5 项通过，覆盖新增、更新、删除、事务回滚、无关标的不失效，以及 symbol 不一致时的旧快照发布防护。

## 隔离验证

测试不读取生产 `DATABASE_URL` 或项目 `.env`。显式设置 `TEST_POSTGRES_URL` 指向临时 PostgreSQL（测试账号需 CREATEDB），然后运行：

```sh
python -m pytest tests/test_postgres_migrations.py -q
```

每个测试创建随机 `crypto_migration_test_<uuid>` 数据库，最后仅删除本次创建的确切数据库；不会删除传入连接所指向的库。覆盖空库全表、重复迁移、双迁移者、锁等待上限、文件校验和、中途 DDL 回滚、检查点失败/重试、类型/身份/唯一性、保护投影事务、来源版本迟提交/更新/删除、Paper 审计版本。

数据库备份恢复包含 public 与 checkpoints schema；Prompt、宿主 env 和安全密钥另行备份。编号 SQL 只解决结构，不迁移历史数据或恢复交易所管理责任。
