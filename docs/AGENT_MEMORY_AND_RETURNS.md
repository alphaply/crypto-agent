# Agent 记忆、操作记录与现货收益

## 记忆里有什么

每轮完成决策和交易工具调用后，摘要模型整理策略摘要，再将最近 4 小时有效摘要、上一版记忆、当前任务的历史统计交给记忆模型。短期记忆建议 300–500 字、约 400 字，按以下四部分组织；空部分省略，关键条件不硬截断：

1. 策略判断：仍然有效的方向、依据与关键价位。
2. 近期操作：操作及实际结果，区分受理、成交、失败与待核验。
3. 有效教训：具体、可用于下一轮判断的经验。
4. 后续条件：触发条件、来源时间与失效条件。

实时持仓、余额与挂单仍来自最新账户输入。记忆中的旧计划不是当前事实。模型调用失败、空输出或输出不完整时，保留上一版，重试记忆整理不会重放交易。

决策读取最新记忆后，最近三轮摘要只补充 `source_summary_ids` 尚未覆盖的内容。去重依据保存的来源 ID，不做文字相似度猜测；执行引用仍完整保留。统计由程序统一计算，最近 7 天、全部本地历史各注入一次；记忆不反复复写数字，也不携带全部成交明细。原始决策、摘要、记忆版本仍可按需查看。

## 统计口径与范围

工作台和模型上下文共用 `task_performance`。范围限定当前任务和配置标的；实盘进一步限定当前账户。不混入其他任务、人工或无法明确归属的成交。旧账户范围 `/api/stats/performance/{config_id}` 保留兼容，其范围不等于新的任务战绩。

| 指标 | 口径 |
| --- | --- |
| 开仓 / 加仓次数 | 实际成交的逻辑订单数；同单部分成交及已知改单链只算一次。7 天次数按首次成交时间筛选。 |
| 多空比例 | 实际成交的开多订单数 : 开空订单数；只有多单时显示如 `3:0`，没有方向样本时显示未知，现货买入不算开空。 |
| 胜率 | 按平仓成交订单的已实现盈亏扣该单手续费计算；盈利订单数 / 盈亏明确的平仓成交订单数（含保本）。同单分批成交合并，全亏显示 0%。不要求开仓历史完整，也不分摊未知开仓费。 |
| 平均盈亏比 | 平均扣费后盈利 / 平均扣费后亏损绝对值；无亏损样本时明确标注。 |
| 取消率 | 该期间已受理订单中，当前已确认成功撤销的订单数 / 已受理订单数；失败调用与重复调用不增加计数，待核验撤单不算成功。按订单受理时间归期。 |
| 已实现盈亏 | 按期间成交时间统计，包含部分平仓；费前和可确认的扣费后金额分别提供。 |
| 手续费 | 保留原币种、已知金额及缺失数量；不自行换算币种，不把缺失当零。 |

“全部历史”是数据库中实际可查询的归属记录，不承诺交易所开户以来全部数据。响应提供记录起点、统计截至时间、7 天同步覆盖和周期扫描完整性。没有成交时间的记录保留在全部历史，不能猜入最近 7 天。平仓订单以最后一笔已记录成交时间归期，合并该订单此前的成交盈亏与该单费用；期间已实现盈亏仍按每笔成交时间统计。完整周期保留为诊断信息。

币安实盘收益率曲线与收益详情另按账户权益核算，剔除合约资金转入、转出后，以区间起点权益为分母；回撤使用同一调整序列。划转不改变成交统计、胜率或任务已实现盈亏。真实划转流水尚未同步完整时显示“待核对”；原始权益金额仍可查看。详见 [账户收益与划转](agent-performance-context.md)。

模拟历史未记录手续费时，费前盈亏仍可显示，扣费后胜率保持未知。多币种费用无法确认统一金额时，净收益保持未知。未知值在页面显示“—”。

## 原始操作理由与结果

止盈、止损由交易所或模拟撮合自动触发时，也显示在“最近操作”和历史记录，标记为“自动触发 · 止盈／止损”。已触发但执行子单或成交量尚未核验时显示待确认，不能据此声称成交。重复查询更新同一条事件；自动事件与模型原始调用分别保留，不伪造模型理由。历史记录从已有计划、成交账本和模拟触发证据建立索引。无法取得真实触发时间时显示“发现时间”。

内部五个交易工具的原始 `reason` 保存到 `agent_trade_calls`，包括开仓 / 加仓、平仓 / 退出、改单、撤单和保护设置。记录关联任务、标的、工具名、工具调用 ID、操作 ID，以及参数与订单回执。当前内部调用使用工具调用 ID 作为执行操作 ID。

原始理由与回执分别保存。参数错误、用户拒绝、未执行也留存原始输入；长理由不裁切。待审批、已受理、已成交、失败、待核验、拒绝和未执行分别展示。“已受理”不表示已经成交。后台核验刷新同一操作的结果，不改理由、不生成新交易、不补执行已跳过的后续操作。

历史补齐只读取实际保存的 v3 原始请求；批量历史保留原子操作身份或明确的历史索引，不重放请求。无原始理由时显示“历史未记录”。这些记录不依赖会清理的模型运行日志。

## 工作台布局

登录后的 Agents 工作区分为任务概览、决策与操作、策略与记忆、历史记录。概览提供 7 天 / 全历史统计、最新持仓、普通 / 条件 / 保护订单、存在的待核验操作、最近操作和行情；历史可按日期、动作、状态筛选，每页 20 条。日期采用浏览器本地日期边界，提交时换成 UTC。统计、决策与记忆独立于交易所账户和行情加载。

手机端顶部次要操作收进菜单，指标两列，交易记录使用纵向卡片。理由可展开，原始参数和完整结果放入详情。记忆保留版本、来源时间、编辑与原文查看。公开页面沿用现有权限，不请求新增的受保护统计及操作详情接口。

## 现货成本与收益

**持仓收益率 =（当前市值 − 剩余持仓成本）/ 剩余持仓成本 × 100%。**

例如成本从 100 校准成 1300，当前市值为 1430，收益率是 10%；不会把投入增长解释为 1200% 收益。

- 手工修改持仓成本建立带版本的新基准，不创建买单、资金流或利润，不增加交易次数。
- 基准记录已经覆盖的买卖成交；迟到的旧成交不重复累加。未完成订单只计算校准后的新增成交。
- 后续真实买入更新加权成本，卖出按对应数量扣减剩余成本，单独记录已实现盈亏。已知基础币手续费影响实际数量，计价币手续费影响成本 / 到账；第三币种费用保留原币种，净金额不能确认时保持未知。
- 重复校准保留先前可确认的已实现盈亏，不能靠修改剩余成本重新计算历史利润；无法恢复的历史盈亏继续未知。
- 多资产按共同计价币汇总市值和剩余成本，不直接平均各资产收益率，也不相加不同基础币数量。

页面分别显示累计成交买入额、剩余持仓成本、当前市值、持仓收益率与已实现盈亏。累计成交买入额不包含手工成本校准。没有有效价格、零成本或买卖证据不足时，显示具体原因，收益率为未知。

新日快照保存市值、剩余成本、收益率、已实现盈亏、成本版本和估值状态；图表用虚线标记有记录的人工校准日，并通过版本关联精确校准时间，当前交易区也展示校准时间。旧快照只有 `total_invested` 时，仅能显示旧投入记录，不生成历史收益率。日快照仍是一天一条，不伪造日内轨迹。

## 接口和升级

- `GET /api/stats/task-history/{config_id}`：任务范围的 `seven_days`、`all_history`、覆盖时间、完整性与指标定义，需登录。
- `GET /api/history/trade-calls?config_id=...`：`page`、`per_page`、`action`、`status`、`start`、`end` 筛选，需登录。时间筛选必须携带时区；`status=unresolved` 包含待审批、执行中与待核验记录。
- 现货仪表盘新增 `remaining_cost`、`recorded_investment`、`realized_pnl`、`fees_by_currency`、`fees_complete`、`cost_basis_revision`、`valuation_status`、`return_basis`。原字段仍保留兼容；新客户端使用明确命名的字段。
- 现货图表数据源为 `spot_holding`；点提供 `equity`（市值）、`invested`、`remaining_cost`、`holding_return_pct`、`cost_basis_revision` 与 `calibrated`。历史未知值为 `null`。

版本化迁移 `0014_workbench_history.sql` 增加操作索引、成本基准版本与快照估值字段，保留旧记录。迁移只修改本地数据，不提交交易。外部 MCP 工具契约和交易执行、审批、恢复机制不变。
