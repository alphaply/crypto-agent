# 工作台配置与运行流程

## 页面与升级兼容

前台 Agents 页和后台记忆管理都支持编辑短期记忆。登录、退出和凭证更新会同步到同一浏览器的其他标签页，无需整页刷新。保存成功立即显示已保存正文，后续 Agent 使用相同内容；保存失败会在编辑框显示原因并保留输入，登录失效时重新登录后重试。修改正文不改变成交事实快照。

Dashboard 展示全部任务的数据总览，包括启用任务数、24 小时运行结果、消息更新时间、今日已知模型费用、收益与任务列表。独立的「Agents」页（`/agents`，管理入口 `/console/agents`）展示任务运行状态、K 线、持仓、决策原文、工具调用、策略摘要和短期记忆；只加载当前选中任务的工作区。现货组合可切换标的和周期，移动端使用同一套选择器。旧 Dashboard 的 `symbol` 过滤及任务深链继续保留兼容。

新建聊天任务及单标的交易任务使用交易所市场目录：先选账户和现货/合约市场，再按币种、完整交易对或计价币搜索，支持分页。切换账户或市场会重新核验选择，不能继续使用上一个市场的无效标的。现货组合仍可多选。

配置页按任务与调度、消息聚合、模型与价格、交易账户、MCP、短期记忆、提示词及系统数据组织。管理员登录后能查看、复制、修改明文凭据；数据库继续加密保存。管理配置响应使用 `Cache-Control: no-store`。公开页面、普通消息接口和 MCP 工具不提供密钥。

升级保留已有运行间隔、自定义时段、显式行情周期、杠杆和交易记录。新建合约任务默认 60 分钟与 `hourly` 行情预设；内部 Agent 没有新增杠杆上限。MCP 的默认 5x 限制仅作用于外部 MCP 交易配置。

## 聊天标题与任务删除

聊天自动压缩较早上下文后，会根据会话内容总结标题；「当前会话记忆 → 整理」手动压缩成功时也会触发。同一批已压缩内容只尝试一次，没有新增可压缩内容时不重复调用。命名沿用当前会话的模型、兼容模式和 reasoning 配置，只采用完整最终回答；仅返回推理、回答截断或请求失败时保留原名。更新后的标题直接显示在会话列表与聊天顶部。

删除交易任务：进入「配置 → 任务与调度」，找到任务并点击「删除」，或使用任务编辑抽屉右上角的删除按钮。已认领管理范围的任务须先在管理面板核验并明确释放，或完成接收方接受的交接；即使已经空仓、周期结束或暂停，管理权也不会自动释放。活跃仓位、挂单和未知写入会阻止普通释放及静默删除，原记录保持可查。删除不会替你卖出现货、平仓或撤销交易所委托。只想暂停决策可关闭启用开关，后台仍保留原管理责任。

修改交易账户/模式、缩减持仓标的及通过整份配置保存或导入移除任务同样核验管理责任。原已核验释放或已接受交接的资源允许任务退休，交接所需原操作身份和证据继续保留。未建立管理关系的旧现货任务沿用专用删除入口的明确清理语义，不能借该入口绕过已认领资源的保护。

## 配置共享消息

1. 在「模型与价格」新增 Jev 渠道。选择 **TypeSafe · Jev 官方**，填写 TypeSafe API Key，默认 Base 为 `https://api.typesafe.ai/v1`、模型为 `jev-latest`，调用 `POST /v1/systemone`（[官方接口文档](https://api.typesafe.ai/docs)）。B.AI 用户选择 **BAI · Jev**，保留 `https://api.b.ai/v1`、`jev-1.13.0` 和 `POST /v1/decisions`。两者凭据独立；已有 B.AI 配置不自动切换。连接信息填写完成后自动查询账户的 Jev 模型，无需先保存或填写模型名；也可手动填写模型 ID。Jev 只能用于结构化评分。
2. 另配一个生成式模型作为摘要渠道。
3. 在「消息聚合」选择评分方式（关闭 / Jev / 普通 LLM）及摘要渠道。关闭评分无需 Jev，按时间选择消息；普通 LLM 每批最多 20 条并缓存结果。抓取最短 1 分钟，按北京时间每天 00:00 起对齐：默认 60 分钟在整点运行，改成 30 分钟在整点和半点运行；启动或改间隔后等待下一定点，不补跑。摘要可单独设置最小间隔，默认最近 24 小时、0–100 分阈值 60。
4. 在「消息聚合 → 律动 BlockBeats API Key」填写独立律动密钥，可从[律动官方 API 文档](https://www.theblockbeats.info/apiDoc)申请。服务以 `api-key` 请求头调用 `https://api-pro.theblockbeats.info/v1/newsflash`，按页获取 JSON 快讯，不使用律动 RSS。密钥加密保存，可以修改或清除；旧默认律动 RSS 来源自动迁移为 API，保留原名称、语言和启用状态。缺少密钥显示待配置；请求失败会标记来源异常并在可用时使用历史缓存，不会退回 RSS。原有宏观与加密来源、Polymarket 保留。
5. 币安公告使用官方签名 WebSocket 持续收集，需选择已保存 Binance 凭据；缺少凭据显示待配置。
6. 等待自动保存完成后点击「立即刷新」。处理监控显示采集、评分、过滤、摘要、发布各阶段，当前阶段进度、耗时、成功/失败/缓存/入选数量、相关度分布和各来源结果。运行时约每 2 秒更新，空闲时约每 10 秒更新；查看页面不会重新评分。

流程为采集 → 清洗去重 → 可选评分 → 筛选 → 普通模型摘要 → 原子发布快照。支持旧摘要加当前原文的滚动更新，无变化复用摘要；等待摘要间隔时保留旧引用。新消息独立进入触发观察，可给任务配置专用低价模型、关键词/来源/类别、冷却与每日上限。详见 [输入输出、时效与触发配置](NEWS_PIPELINE.md)。即使交易调度关闭或无启用 Agent，全局聚合仍由运行中的调度器维护；部署为独立调度进程时必须保留该进程。

部分来源失败发布降级快照并列出缺失来源；评分全部失败或摘要失败保留上份成功快照并标记过期。Agent、Chat、Dashboard 和 MCP 只读取已完成快照，不在页面或任务切换时重新评分。

条目明细可按失败、入选等状态筛选并搜索标题，查看每条实际模型请求、响应及错误。评分按返回概率的加权期望校验，并考虑响应数字的小数精度；超出可解释舍入区间的响应继续拒绝，记录原始分数、加权分数及允许区间，便于定位服务商返回不一致的问题。网络或服务端临时错误有限重试，结构错误不会无限重试。

消息 LangSmith 追踪默认关闭，仅保留本地记录；开启全局追踪后可为消息选择「每轮一条概要」或「完整追踪」，管理员可从监控页打开链接。Agent 决策、策略摘要、短期记忆和聊天跟随全局追踪开关，其他辅助调用默认不上传。追踪不可用不影响正常处理。内部追踪链接及调用 ID 不进入公开消息快照。处理历史保留最近 20 轮；新闻模型调用保留最多 12,100 条、最长 30 天，普通 Agent 仍为每任务最近 100 次、最长 30 天。进程中断后会将过期运行标记为中断，避免一直显示处理中。

相关接口：`GET /api/news`（安全快照）；管理员接口包括 `GET /api/news/status`、`POST /api/news/refresh`、`GET /api/news/sources`、`GET /api/news/runs`、`GET /api/news/runs/{run_id}` 和 `GET /api/news/scorer-models?provider_id=...`。

## 决策、摘要和记忆

Agents 默认「运行过程」按顺序展示三步：决策模型的正文与推理、工具调用参数及真实回执；结束后的纯文本策略摘要；短期记忆更新结果。行情、账户和委托放在「行情与账户」，历史成交放在「交易记录」。

每轮决策与工具调用完成后，配置的摘要模型按策略 Prompt 生成一次纯文本摘要。保存的决策正文不再被摘要或报告替换；调用顺序、参数和回执直接记录在 `decision_json`，不调用模型整理。已移除 TradeReport schema、格式修复和渠道报告能力设置。旧 `report_json` 仅用于兼容读取已有原文与回执，不重新生成。

成功摘要和记忆更新任务一起持久化；决策或摘要失败时保存原始证据，不排入本轮记忆更新。短期记忆按 `config_id + run_id` 去重，同一 Agent 顺序处理：最近 4 小时内含本轮的全部有效压缩摘要、旧版 7 天成交/平仓操作记录、上一轮有效短期记忆；本轮摘要只计一次，不另外获取新闻或拼接最新工具回执。模型输出一份完整纯文本摘要，程序保存窗口、来源和版本。失败保持旧记忆，后台重试仅处理记忆。短期记忆模型不使用规则工具；纯分析聊天不能写交易 Agent 记忆。

Daily memory 以及旧固定四小时批次已停用，历史数据保留归档。现有日报生成 HTTP 接口返回 410。

独立退出模式读取最近一份有效已发布短期策略记忆与最近三条已发布摘要，并标注各自真实截至时间。新来源整理、失败或重试时继续使用这些内容；执行证据读取失败不会清空策略正文。人工改写/删除使对应派生视图失效，其他有效内容仍可用；未有任何可用视图时才说明“尚无已发布…”，不回退注入带旧执行禁令的原文。

管理员在「短期记忆」选择具体任务后，可查看“决策可用记忆”的发布截至时间、当前记忆任务的待整理/失败数，以及整理错误。“重试失败整理”只重新排队仍有源摘要的 failed 记忆任务，沿用同一后台租约和最多三次尝试；不调用交易工具，也不重启旧投影转换。排队期间每 30 秒刷新状态，也可手动刷新。下方历史表格继续展示可编辑、可导出的完整原文；公开页面没有管理状态与重试入口。

管理接口为 `GET /api/history/short-memories/projections/status?config_id=...` 与 `POST /api/history/short-memories/projections/retry`（JSON 仅含 `config_id`），均需登录。原文和新策略视图在同一事务保存，发布失败时一并回滚。

“尚无已发布短期策略记忆”只说明没有可用策略视图，需要结合原文列表和状态判别：

- 原文列表为空：当前没有短期记忆原文。有效摘要可直接发布；失败整理重试不会凭空补造原文。
- 有原文而 `published.short_memory` 为空：当前没有满足来源范围和哈希检查的已发布正文。`pending` 是待处理记忆任务数；兼容字段 `not_generated` 不再统计退役的投影转换队列。
- `failed` 或 `errors` 非空：查看来源 ID、`attempts` 和 `error`；`read_errors` 则表示读取异常。已发布项通过 `published` 中的 `source_id`、`as_of` 确认来源和截至时间。

Agent 页短期记忆中的「成交事实快照」对应该条记忆保存的历史证据副本，不是实时执行状态，也不会作为短期策略记忆直接注入决策 Prompt。展开后原文在限定高度内滚动显示。登录后可点击「清除快照」并确认，只清除该条记忆的快照，保留策略正文、已发布策略视图及原始交易记录；短期记忆历史列表也提供相同操作。后续生成的新记忆仍会保存新快照。编辑策略正文不会把旧快照写回；删除整条记忆仍使用原有列表删除操作。

## 合约独立退出与平仓排查

`close_position_real` 的 `pos_side` 是持仓方向：`LONG` 退出多头、`SHORT` 退出空头，不能填写执行委托的买卖方向。在 `independent_exits` 模式下，退出单必须对应同一任务、账户、标的及方向的活跃周期；看见交易所持仓不代表这个任务已经拥有该周期。

独立退出的开仓回执确认成交后，即使持仓接口暂时查空，也会保留周期等待同步。已有周期首次查空会先复核，缺少本周期完整退出成交证据时，需后续维护轮次再次确认空仓，才清理独立退出单；不会仅凭一轮短暂空读撤掉止损。待核验时不重复下单，后续同步恢复后再操作。

提交或撤单回执缺少累计成交量、或成交量相较已核验记录倒退时，会继续按原订单 ID 核验，不将缺失量当作零成交。撤换止损期间遇到持仓空读或超时，会保留补单意图；恢复核验后按同一操作记录继续，避免丢失退出单或重复提交。待核验结果会阻止批次后续操作。

已核验当前方向无仓时，返回跳过，不创建订单。有仓但缺少当前周期时，v3 有效交易请求会核验授权范围、当前 owner 和真实资源，自动建立管理基线。人工建立的仓位和挂单可在原请求中管理；其他任务已占用的资源返回局部管理冲突。

主 Agent、小模型和绑定任务聊天默认只绑定 `execute_trade_actions`。单笔请求也是一项 actions 数组；例如 cancel、edit、open 可放在同一个 `contract_version=3` 请求里按顺序执行。整批静态授权通过后，逐项刷新动态准入，合法 cancel 不因后续 open 的余额或数量问题提前被拒绝。默认失败停止，不等待限价单成交，不自动回滚已完成项或续跑未执行尾部。

手动仓使用独立管理基线，不生成虚假的 Agent 入场、历史成交或完整周期收益。后台对账人工加减仓、改价、撤单及条件母子身份。来源、管理状态、可用能力和证据新鲜度分别展示；当前可见数量不会因旧周期缺失变成空仓。精简持仓和挂单文本使用“多头/空头”区分方向，不将空头写成“空仓”；共享管理显示“授权共管”，不追加管理者内部 ID。原身份仍保留在结构化数据及审计中。旧 `adopt_position_real` / `adopt_perpetual_position` 仅保留直接调用兼容，不进入默认目录。

批量返回 `not_executed` 表示某个更早的操作失败或结果未知，后续操作没有执行。先查看首个失败项的方向、标的、错误代码及核对提示，不要直接重放整批。只有被实时确认的无仓跳过项允许继续；真实失败、归属不明及结果未知仍停止。

## 独立退出 v2 升级与恢复

升级前备份数据库、任务配置及自定义提示词，停止旧调度进程后部署后端，再重建前端并启动新调度。模拟退出表事务迁移为可空计划数量，保留订单 ID、成交、索引和操作回执；旧记录补 fixed，不把旧 amount=0 改成动态 all。迁移本身不向交易所写入。已经保存的旧比例缩量 replacement 继续按原客户端 ID 查回恢复，新版本不产生新的自动缩量意图。

活跃 v2 订单存在时不能让旧版本接管数据库或恢复调度：旧代码会误解 all 的空数量、新条件 LIMIT 和母子身份。回滚须先核验活动周期已结束、全部挂单清理及操作已确认，保留升级后的全部成交及操作记录，再完成明确的兼容迁移；禁止用旧备份覆盖升级后的真实记录，也不要只覆盖代码降级。

跨轮允许先 open，核验成交后在本轮或后续轮次 close。fixed 档保持指定量；数量冲突由 quantity_conflict 单独报告，Agent 可 edit/cancel。市价 all 固定提交前核验量，条件市价 all 保持动态至触发，覆盖整个账户该品种该方向。归零清理仍包括本周期未成交入场，撤销期间迟到成交作为残仓继续管理，不自动追平。

edit 普通 LIMIT 返回 native，条件退出返回 cancel_replace 及旧新 ID。例如查询返回 algo:456 及其 regular:789 子单时：edit(algo:456) 提示 order_already_triggered；后续 edit(regular:789, remaining_amount=0.2, price=...) 修改活跃子单，不再传 trigger_price。cancel(algo:456) 通过已核验链路撤子单；关联缺失时保留待核验，不能宣布已全部撤掉。替代单超时后由系统按原 operation_id/客户端身份后台核验，禁止换 ID 盲目重复提交；未尝试的替代单不会在后台自动提交。

模拟使用行情区间，不能证明真实逐笔成交顺序；同根 SL 优先、条件 LIMIT 不回填触发前成交，超额固定档只记录实际退出量及未执行余量。验证记录见本变更的 [归档验证记录](../openspec/changes/archive/2026-10-11-refine-independent-trading-tools/verification.md)；全部使用隔离数据库和拦截式交易所，未向真实账户下单。

## 现货时间与额度

现货组合的市场数据按标的展示技术指标，相同消息摘要集中展示一次，并列出适用标的；不同摘要和过期缓存标记保留，单标的和其他模式的展示不变。

现货定投新增买单不再因为历史管理记录尚未核实而被统一下单入口阻断。下单仍校验本轮共享预算、任务总预算、当前可用余额、标的授权和同价挂单；同一操作不会重复提交，并发操作仍受账户与资产锁保护。原未核实记录保留用于后续核验，卖出、撤单、改单、保护以及合约和模拟模式沿用原有规则。

```json
{
  "mode": "SPOT_DCA",
  "symbols": ["BTC/USDT", "ETH/USDT"],
  "dca_amount": 100,
  "dca_budget": 3000,
  "dca_schedule": {
    "frequency": "daily",
    "days": [0],
    "times": ["09:00", "21:00"],
    "timezone": "Asia/Shanghai"
  }
}
```

每周一 09:00 使用 `frequency: weekly, days: [0], times: ["09:00"]`。服务端与后台预览共同使用同一规则；`POST /api/config/schedule-preview` 返回接下来三次执行时间。

每个时槽产生一份组合额度，100 USDT 指所有标的的总额。成交、挂单占用与未知结果的预留都计入预算；撤单确认仅释放未成交部分。同一时槽的重试、多个工具调用、审批恢复和服务重启不创建新额度。下一时槽产生新额度，累计买入仍受总预算限制。观望也标记本时槽已运行；停机恢复仅补当前日或周内最近一个遗漏时槽。旧单时点字段继续兼容。

## 添加模型与供应商目录

在「模型与价格」新建服务端点 / 模型，先选预设或填写 API Base、服务接口和 API Key。地址或 Key 编辑完成并离开输入框后，自动获取该供应商返回的候选；可按 ID 或显示名称搜索，也可直接输入未列出的别名。读取结果不会自动选择第一项，也不会修改价格、推理设置或兼容模式。点击抽屉右上角「保存」后才进入既有配置保存流程。

编辑已保存渠道可直接读取同一连接的目录。复制渠道或清除 Key 后，需要明确填写 Key；切换地址/协议时，仅使用本次编辑中显式输入的 Key，页面预填的旧 Key 不会被隐式发送给新地址。更改连接会清空旧候选，关闭抽屉会取消请求。点击「刷新模型」可重新读取；同连接刷新失败时保留上次结果并标记过期，显示获取时间。空目录、接口不支持、无权限和部分结果均可继续手动填写。

候选来自配置的供应商 `/models`，与静态预设及 models.dev 价格目录独立。OpenAI 兼容和 DeepSeek 在填写的 Base 后追加 `/models`；原生 Anthropic 使用 `/v1/models` 并读取分页；Jev 使用供应商的 `/v1/models` 并只展示 `jev-*`。目录存在不代表模型一定可调用；推理探测仍需手动发起。

管理员只读接口：`POST /api/config/provider-models/discover`，响应为 `Cache-Control: no-store`。示例（无需 `model`）：

```json
{
  "api_base": "https://supplier.example/v1",
  "api_protocol": "chat",
  "compatibility_mode": "auto",
  "decisions_api": "bai",
  "credential": {"mode": "draft", "api_key": "YOUR_API_KEY"}
}
```

`credential` 三种互斥模式：`draft` 使用当前输入的 Key；`saved` 携带 `provider_id`，服务端只允许同地址、协议和兼容模式使用该渠道已保存的 Key；`none` 表示无 Key / 已清除，返回待配置错误。不会借用其他渠道凭据，也不会保存草稿、热重载、发起生成/评分或记录生成用量。

成功返回 `success`、`models: [{id, name, description}]`、`fetched_at`、`source: {api_base, url, protocol}`、`complete` 和 `warning`。真实空目录为 `models: []`；后续页失败、游标异常或触及限制时保留已读候选，`complete: false`，`warning` 携带 `code/message/retryable`，不得当作全量目录。总时限 15 秒、连接时限 5 秒、单页 2 MiB、最多 10 页 / 5000 个唯一 ID；不自动重试、不跟随重定向。

错误位于 `detail: {code, message, retryable}`，不回显凭据或上游正文。本地连接错误为 400、schema 错误为 422、已删除渠道为 404；上游鉴权拒绝、接口缺失、限流及坏响应为 502，总超时为 504。上游 401/403 不会转换成本地登录 401。旧 `GET /api/news/scorer-models?provider_id=...` 仍接受已保存渠道并返回原有条目结构，与新接口共用 Jev 读取逻辑；旧接口无法表达部分目录时返回脱敏错误。

## 价格与用量

每个本地渠道独立选择人工价格或 models.dev 映射，显式填写目录服务商和模型 ID。同名模型不会跨渠道覆盖。输入、输出、缓存读取和缓存写入按每百万 token 计价，留空表示未定价，显式 0 才表示免费。

目录默认每 6 小时同步，也可使用 `POST /api/pricing/sync` 手动同步；`GET /api/pricing/sync/status` 显示结果，`GET /api/pricing/catalog?q=...` 搜索目录。目录共享缓存，失败保留旧费率。修改映射后先保存再同步；人工覆盖优先于自动价。

调用开始时保存渠道、模型、用途、任务与价格快照，结束时记录用量和费用。支持交易分析、聊天、运行摘要、记忆、Jev 评分及消息摘要；已有历史无法可靠归属的用量标为未知渠道。用量记录独立于可清理的输入输出日志，修改费率不会重算历史。缺少价格或 token 时明确显示未知，不按免费处理；不同币种分开统计。

## 策略记忆与收益详情

记忆卡片和例行决策输入显示已发布纯文本，可整理近期操作、策略判断、关键价位和有效教训。例如：“撤销旧入场单后继续等待四小时收盘；关注支撑2385与突破2565。”不再用正则或额外模型调用强制提取“纯策略”版本。当前交易事实由最新账户状态提供；周期对账与原提交恢复在后台处理，历史文字不能代替本轮交易准入。

旧正文、原回执和已发布内容继续保存。新文本直接发布，程序检查来源哈希、账户和品种；旧 JSON 投影转换与 contract recovery 重排已退役，历史失败记录仅供诊断，不阻塞新正文发布。管理员可以从记忆卡片明确打开历史详情，读取原文及其当时的快照；历史时间不代表实时账户状态。任务运行审计保留完整工具调用和执行证据。

收益默认只显示权益变化、盈亏、回撤。权益变化与回撤使用所选区间的本地权益快照，未剔除出入金、划转或共享账户其他策略影响，快照最大回撤不等于逐笔盘中最大回撤。REAL 盈亏按当前交易所账户与标的，使用同区间全部已记录成交的已实现盈亏减已核验同结算币种费用，包含手动、其他任务和未确认任务归属的成交；不与权益变化、账户资金流水或完整周期盈亏相加。STRATEGY 继续按任务 ID 与标的读取本地模拟平仓记录。REAL 同步覆盖不足时显示已记录金额并提示覆盖缺口，不因归属整理积压隐藏已有事实；没有成交、缺失金额或待换算费用保持未知，明确记录的真实零值才显示 0。七天完整平仓和胜率直接由账户该标的成交重建，不等待任务平仓缓存；不完整的开平仓不计为完整周期。

收益详情按需展示成交、费用、归属、周期、同步覆盖和原始观察证据，默认不展示胜率、周期数、同步区间或完整 JSON，也不会把展开详情复制进下一次记忆。管理员只读接口：`GET /api/stats/performance/{config_id}?hours=168` 返回三类指标；`GET /api/stats/performance/{config_id}/details?hours=168` 返回同次取证口径的摘要与详细账本；`GET /api/history/short-memories/{id}/details` 返回保留的历史原文与截至时间。接口沿用登录权限，支持 REAL/STRATEGY；区间限制为 1–8784 小时。


### 自动管理的保存、暂停与退出

任务和 MCP 配置默认使用 `visible_first_claim`，不再需要额外管理范围清单。后台发现已有资源或首次有效交易请求时认领当前账户授权可见的资源，纯查询不认领。合约 Hedge 按方向管理，One-way 按 BOTH 管理；现货按物理账户基础资产管理，跨报价共享预留，不能重复出售。同一物理账户的多 Key 可通过保存账户的明确 `physical_account_id` 关联，不能凭 Key 不同推断账户不同。

关闭启用开关暂停决策，原 actor、操作 ID 和历史来源继续保留审计。其他合法连接无需释放或交接即可共管，旧 exclusive_scope 也按共享管理执行。更换账户、缩小范围或删除配置仍不能丢弃活跃资源和原未决写入的核验责任。私有恢复信息如需交接，接收方只能查询明确接受的恢复身份；共享管理不公开其他私有回执。后续成功明确修改生效，旧 worker 不能恢复旧参数。保存失败保留草稿与原证据。

管理员在任务编辑页或 MCP 配置卡片的“管理状态与交接”查看 owner、认领时间及受限恢复身份。只读接口 `GET /api/management/{config_id}`；明确释放 `POST /api/management/{config_id}/scopes/{claim_id}/release` 传 `confirmed: true`；交接同路径 `/transfer` 传 `target_config_id` 和 `accepted: true`。MCP owner 使用 `mcp:profile_id`。管理操作的详细证据可展开读取。典型界面：[390px 中文](screenshots/visible-management-390-zh.png)、[交接详情](screenshots/visible-management-transfer-1440-en.png)。

工具定义与回执的可复现大小见 [本次验收记录](../openspec/changes/simplify-trading-tools-and-auto-management/verification.md#可复现大小测量)：20 项 Paper 的实际默认回执仅含一次可选账户摘要，完整逐项账本继续可查。现货 v3 新增卖出与保护能力，schema 较旧买入接口更大；工具数与 schema 字节分别记录。


### 人工平仓、重开与退出覆盖

人工全平后，后台核验仓位归零、实际退出成交和旧周期残单，继续清理已登记到旧周期的入场/退出单。平仓后又重开时，新仓位与新入场挂单保留新的成交边界；旧 dynamic all 条件单不会被当作新仓位的有效保护，旧周期清理也不撤掉已核验属于新周期的单。边界或某张订单尚未核验时显示具体待核验目标，不猜测撤单，也不把历史“无开放周期”表述为实时空仓。

撤单清理期间出现晚到入场成交，后台保留该笔成交及实际残仓，回到持仓管理；不会自动补平，也不会提前把周期标为完成。fixed档维持指定数量，人工加减仓后不自动等比例重配；多个固定退出单超过当前仓位时显示数量冲突，Agent按最新状态修改或撤销。动态all覆盖按交易所原生语义及当前剩余仓位估计，条件限价触发仍须成交。界面覆盖与ACTIVE状态均是最近一次核验结果，不保证触发、成交或完整退出。


## 纯文本记忆与接口直返（2026-10-15）

短期记忆采用一份纯文本摘要：Agent 完成决策和工具执行后保存本轮策略压缩，再整理最近 4 小时内含本轮的全部压缩摘要、旧版最近 7 天成交/平仓操作记录与上一轮有效短期记忆。不单独查询新闻。模型不返回 JSON、来源哈希或多份投影，也不进行格式/内容纠正调用。非空、完整响应及无工具调用仍是基本要求；传输重试、费用审计、租约和失败保留旧记忆继续生效。

新记忆与新策略摘要直接发布文本，程序保存账户范围、来源哈希和执行关联；沿用已有存储表保留历史，不再生产旧投影转换或 contract recovery 任务。已有有效已发布内容仍可读，人工编辑/删除使旧来源失效，迟到结果不能覆盖变更来源。最近三条策略摘要的展示与 4 小时整理窗口分别处理。“重试失败整理”只重排仍有源摘要的失败记忆任务，不重排旧投影。原文和发布记录原子保存，失败不重放交易。

工具回执默认使用简短卡片，展示名称、真实状态和简短结果；完整结果及审计按需展开。Paper 银行、破产、下海和双榜规则见 [账户生命周期](PAPER_ACCOUNT_LIFECYCLE.md)。本轮中英文桌面/手机验收截图在 `docs/screenshots/account-lifecycle/`。
