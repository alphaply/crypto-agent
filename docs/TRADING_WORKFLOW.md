# 交易、记忆和指标流程

## 实盘 TP/SL

`open_position_real` 的每笔订单必须提供 `action`、`entry_price`、标的币数量 `amount`、`stop_loss`、`take_profit` 和 `reason`。多单要求 SL < 入场 < TP，空单反之；价格与数量必须为有限正数，交易所精度调整后再次校验。系统不会悄悄交换或移除错误的止盈止损。

计划先写入 SQLite `real_protection_plans`，然后提交限价入场。订单响应、状态变化和保护调整写入 `real_protection_events`。成交后，独立维护任务创建交易所条件市价止损、止盈，先确认止损。LLM 不负责轮询触发价格。

当前支持 Binance USD-M 线性永续和 OKX 线性永续。工具输入为标的币数量，发送 OKX 等合约订单时按 `contractSize` 转换为合约张数。Binance 使用 `closePosition`；OKX 单向模式使用 `closeFraction=1`，双向模式按当前仓位数量设置并在部分成交或减仓后重建覆盖。关闭委托采用平仓方向/只减仓语义，避免反向开仓。

保护粒度是**该配置、该交易对、同一方向的整个仓位**，包括该方向已有仓位。一个交易所 API Key 对应的同一品种不能同时由两个配置托管保护。使用不同 API Key 连接同一交易所账户仍可能无法识别为同一账户，不应这样重复托管。

- `WAITING`：计划存在，尚未观察到持仓或保护安装尚未完成。
- `ACTIVE` 且 `error` 为空：最近一次维护已核验两侧保护，不是此刻的实时成交证明。
- `EXITING`：触发、穿过止盈止损或故障退出，正在撤销剩余入场单、平残余仓位、清理保护单。
- `DONE`：持仓为空，相关入场和保护订单已完成清理。

模型每轮能看到价格、计划状态、最近核验时间、保护订单 ID 和错误信息。计划在重启后继续核对；未知下单结果按持久化客户端 ID 查询，不盲目重发。版本检查阻止过期计划覆盖新计划。交易所持续不可用或无法确认客户端订单时保留错误和计划，不伪装成成功。

`update_position_protection_real(pos_side, stop_loss?, take_profit?, reason)` 调整已有仓位或托管中的未成交计划。省略的价格保持不变。相同价格的保护单复用，改变时先装新单、核验，再撤旧单；新止损被拒绝时保留旧止损。初次为已有仓位建立保护须同时指定 TP/SL。仍有未成交入场单时，新价格也必须适用于这些入场价。

修改入场价格/数量使用“撤单确认 → 携带 TP/SL 重新开仓”。主动部分或全部退出继续使用 `close_position_real`，`entry_price=0` 为市价退出；提交平仓委托不再直接记录成已平仓。不得直接撤销托管保护单来改变计划；维护任务会按保存的计划恢复它。

首次保护安装有轮询与网络延迟，并非原子附带单。维护循环每 5 秒扫描，线程池繁忙、网络超时和交易所限速会延长实际间隔。已经安装的保护由交易所触发；停止服务不撤销它，但无法继续安装、改单或清理兄弟订单。无法确认任何止损时，系统先核对未知提交，必要时尝试撤销入场并只减仓退出；网络不可用时退出也可能失败。止损成交价格和损失仍受跳空、滑点影响。

Web 内运行调度器时，关闭 Agent 分析调度不会关闭已有保护维护。分离部署须保持独立调度器服务运行，`RUN_SCHEDULER_IN_WEB=false` 的 Web 进程不承担维护。不要在托管未结束前删除配置、更换账户凭据或改掉交易模式。

## 模拟交易

`open_position_strategy` 同样强制正确的 TP/SL，保留挂单有效期。`update_position_protection_strategy(order_id, stop_loss?, take_profit?, reason)` 按订单管理模拟仓位或未成交计划，确认状态未被并发改变后写入。模拟成交与止盈止损仍由一分钟行情维护检查，不把整个日线高低点误当作当前时刻成交。

## 每轮记忆

每次生成并保存新的 `strategy_logic` 后，压缩器接收“旧工作记忆 + 新策略逻辑 + 本轮工具结果”，**替换为有界的新记忆**，不无限拼接。建议结构为当前假设、候选计划/失效条件、执行事实、废弃观点/待核实事项。工具成功挂单也不等于成交；下一轮账户快照始终优先。

压缩失败时仍写入带“待核实”标记的最新策略，避免继续展示已失效旧计划。额外成本是每个有效分析轮次增加一次短期记忆压缩。四小时任务仅作为旧流程/漏更新的补充，不覆盖更新的每轮记忆。默认 Prompt 不再重复插入相同短期记忆。

## 每日复盘

每日总结输入包括当日策略记录、本地订单记录、已保存成交、已关闭持仓、模拟平仓、保护状态变化。实盘和现货会额外读取交易所该日成交，即使当天没有打开 Dashboard。时间窗口与现有数据库的北京时间日期一致。

交易所读取最多 5 页，输入明示不能保证完整历史；展示明细最多 200 条，并说明省略数量。该账户该品种可能含手工/其他策略成交，不全部归因于本 Agent。本地历史、订单和持仓可能重复描述同一交易，禁止重复累加；费用按币种列示，缺失盈亏不编造。策略分析轮数与成交次数分别处理。总结包括市场/策略演变、真实执行、偏差和教训、下一日条件。

## 周期与指标

没有自定义时段时，20 分钟决策频率仍在 `:00 / :20 / :40` 运行。默认周期为 `15m / 1h / 4h / 1d / 1w`；已有显式设置不被覆盖，30m、1M仍可选。`1w` 是交易所锚定周线，不是滚动7日。

### 自定义运行时段

在后台编辑 REAL / STRATEGY 任务，打开「调度设置」，可设置默认间隔并添加最多 20 条 `run_schedule` 规则。每条规则包含名称、星期（周一为 0）、时区、开始/结束时间和间隔分钟数（15–1440）。上面的规则优先；未匹配时使用默认间隔，按应用 `TIMEZONE` 当天零点对齐。已有任务不添加规则便保持原有行为，SPOT_DCA 继续使用原来的定投日程。

预设会替换编辑器中的规则，并将默认间隔设为 30 分钟，保存任务后还需点击页面上的「保存配置」生效：

| 优先级 | 时段 | 间隔 |
| --- | --- | --- |
| 1 | 北京时间周六、周日 00:00–24:00 | 30 分钟 |
| 2 | 纽约时间周一至周五 09:30–16:00 | 20 分钟 |
| 3 | 北京时间周一至周五 08:00–16:00 | 30 分钟 |

纽约时段只是可编辑的美盘参考窗口，自动处理夏令时。北京时间周末优先，因此纽约周五下午进入北京时间周六后，改用周末间隔。

时段包含开始、不包含结束，从开始时间计算间隔；例如 09:30 起每 20 分钟在 09:30、09:50、10:10……运行。开始晚于结束表示跨午夜，例如周五 22:00–02:00 覆盖到周六凌晨；全天填 00:00–24:00。切换规则时重新按新规则的开始时间对齐，所以相邻两次执行可能短于设置的间隔。这是时间槽调度，不是“上一轮结束后再等待 N 分钟”；运行中的同一任务仍不会并发重入，离线错过的分析时间槽不会批量补跑。Prompt 中的下次运行时间使用同一规则计算。

降低决策频率只减少 Agent 分析调用，已有止盈止损保护仍独立扫描。修改代码部署后需重启后端及调度器；保存任务规则本身沿用现有配置刷新机制。

Dashboard 的 K 线刷新保留画布实例和浏览范围；切换交易对或 K 线周期时重置范围，主题和尺寸变化不重新创建图表。浏览器回归测试使用独立模拟页面：先运行 `npm run dev --prefix frontend -- --port 5179`，再运行 `uv run --with playwright python tests/browser_dashboard.py`（需已安装 Edge），不调用真实交易接口。

| 周期 | 作用 |
| --- | --- |
| 15m | 入场位置、近期波动与交易触发 |
| 1h | 交易条件、支撑阻力和失效 |
| 4h | 趋势/震荡环境 |
| 1d、1w | 背景和更大级别风险，不重复展示10根K线 |

指标仅使用已收盘K线，输入注明最后收盘时间、排除的未收盘K线、数据年龄与EMA预热不足。当前报价与指标收盘价可能不同，不能把这种差异当作数据错误。短期样本不足的EMA/RSI/布林/MACD明确缺失，不用0伪装有效指标。

- EMA 保留20/50/100/200，不优化拟合近期盈亏；注明预热不足。
- 布林采用20周期、2倍总体标准差，增加 `%B` 和最近120根带宽分位。触轨不自动代表反转。
- VWAP 统一按UTC日内重置，以K线典型价近似，注明锚点；不同周期的典型价近似仍可能不同。
- SMC 摆动点要等右侧K线确认后才参与结构事件；结构和区域带年龄、时间及ATR距离。OB去重，展示优先选附近区域，超过6ATR的区域不挤占短线提示。
- IFVG 要求收盘突破缺口边界，反向再次失效后排除，不把一次影线填补自动算作有效反向缺口。
- Volume Profile 明示统计窗口及OHLCV分配近似，不能叫做真实持有人筹码成本。
- 多空比注明人群/周期；OI单点没有变化率和合约单位换算时不能单独作为方向依据。

这些改动提高执行与证据一致性，不代表已经证明策略具有正期望。测试使用隔离数据库、模拟交易所，以及安装版本CCXT的真实请求构造器；没有用真实账户开单验证。部署需重启后端/调度器以加载代码并自动创建新表。
