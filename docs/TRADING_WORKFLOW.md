# 交易、记忆和指标流程

## 统一交易入口 v3

主 Agent、small Agent 和绑定任务聊天默认只绑定 `execute_trade_actions`。单笔和混合操作都使用 `contract_version=3`、1–20 项平铺数组；兼容 handler 仍可直接调用，但不进入默认模型目录。账户、执行引擎及管理者由可信运行上下文决定，动作不能覆盖 config_id、profile、用户、live/paper 或凭据。单标的可省略 symbol，多标的任务必须每项指定已授权 symbol。

一次调用顺序执行，先检查整批结构、权限及已知模式能力，再在每项执行前读取最新数量、余额、杠杆和预留。合法 cancel 可以先释放资源，后续 open 的动态准入失败只停止后项，不回滚撤单。实盘入场保持原有限价能力；paper 入场可用 market/limit。不会运行任意代码、展开结果引用、等待限价成交或后台续跑尾部。

所有 amount 使用基础币数量。合约 LONG/SHORT 是持仓方向；现货 side=LONG，open 买入，close 卖出。固定 amount 不隐式转换为 all；close_all=true 仅在当前模式支持时使用。edit.remaining_amount 始终是目标未成交量，按最新已成交量换算原生总量；省略的价格、数量和保护参数保留最新已核验值，包括人工改动。

| 模式 | open | close | protect |
| --- | --- | --- | --- |
| REAL/STRATEGY independent_exits | limit，禁止附带 TP/SL | 现有六种独立退出类型；all 限 market/条件市价 | 不提供，使用 close |
| REAL 附带 required/optional | limit；required 必须 SL+TP | market、limit、stop_market | 整仓附带保护，省略腿保留 |
| STRATEGY 附带 required/optional | limit、原有效期 | market | 指定模拟 order_id 的保护 |
| live spot/SPOT_DCA | limit，共享原组合预算 | 原生 market/limit/TP/SL/OCO，固定量 | 原生现货退出组，固定量 |
| paper spot/swap | market/limit；原 amount/quote_amount/margin_amount 及合约杠杆规则 | market/limit/原条件市价，原周期 all | 原成对/单腿保护；省略腿保留 |

以下单项与撤单后开仓示例适用于 REAL 独立模式；symbol 从可信单标的任务补入：

```json
{"contract_version":3,"actions":[{"action":"open","side":"LONG","amount":0.2,"price":100,"reason":"限价入场"}]}
```

```json
{"contract_version":3,"actions":[{"action":"cancel","order_id":"algo:example-stop","reason":"撤旧单"},{"action":"open","side":"LONG","amount":0.2,"price":100,"reason":"释放资源后入场"}],"include":["account"]}
```

默认 stop_on_error 在 failed/pending/unknown 后停止，尾部标为 not_executed。显式 independent 仅在明确失败时保留原无依赖项继续策略；pending/unknown 立即停止本批。depends_on 只能引用此前索引且前项必须 completed，submitted 不满足。用户逐项拒绝始终停止后续金融动作。审批恢复及相同父请求复用原父子身份，不重下单。账户摘要由 include=["account"] 显式请求，末尾最多一份；摘要读取失败不覆盖交易结果。模型响应为逐项简洁文本，内部及 MCP structuredContent 保留结构化结果，详见[回执与恢复](TRADE_RECEIPTS_AND_RECOVERY.md)。

v1/无版本的嵌套 order 与 amend_entry/amend_exit/update_protection，v2 独立动作以及旧单项、execute_trade 入口保持原参数、数量语义和请求哈希。不要将旧请求改写成 v3 后复用原 operation_id。

## 现货组合任务

后台任务选择 `SPOT_DCA` 和现货交易所配置后，「现货标的」通过交易所公共接口加载可交易市场，支持搜索、按计价币筛选和分页，选择 1–10 个 `BASE/QUOTE`，例如 `BTC/USDT`、`ETH/USDT`、`SOL/USDT`。同一任务须使用同一计价币及现货交易所配置；系统自动转大写并去重，保存新增或变更标的时在服务端再次验证。`symbols` 保存完整标的清单，旧字段 `symbol` 保留首个标的以兼容单标的配置、历史记录和旧客户端。REAL / STRATEGY 仍为单标的任务。

旧单标的现货任务若误沿用 `swap` 交易所配置，读取或导入时会为它派生独立的 `spot` 配置副本，保留原凭据与共享合约配置；下一次正常保存配置时持久化。新任务须明确绑定现货配置。

Agent 每轮读取全部标的行情、各自余额及挂单，通过统一入口限价买入、管理挂单和原生退出，或不操作。现货下单须指明配置内的标的；未配置标的会被拒绝。合法金融动作自动纳管当前授权可见资产，人工底仓与本任务历史买入成本分别保留。

`dca_amount` 是每次计划时槽的组合额度，由所有标的共享。例如 09:00 额度为 100 USDT，BTC 与 ETH 的已成交、挂单及待确认预留合计不得超过 100；21:00 时槽获得新的 100，仍受 `dca_budget` 总预算约束。同一时槽的多次工具调用、模型重试、审批恢复和重启共用持久化预算周期，观望也记为已运行。

`dca_schedule` 支持 `frequency: daily | weekly`、`days: [0..6]`（周一为 0）、`times: ["09:00", "21:00"]` 和 `timezone: "Asia/Shanghai"`。后台显示未来三次执行时间；旧 `dca_freq / dca_time / dca_weekday` 继续转换为单时点规则。停机恢复仅补当前日或周最近一个漏跑时槽，其余标记跳过。未绑定调度时槽的旧调用继续使用原有自然日/周预算兼容逻辑。

`dca_amount` 设为 0 时不允许新增买入。可选 `dca_budget` 是所有标的共用的累计买入上限。挂单和结果待核验的委托占用额度，撤单确认后才释放未成交部分；已成交部分仍计入支出。实际订单还需满足可用余额与交易所最小数量、精度等限制。

没有任务级分析周期时，现货使用 `4h / 1d / 1w`：4h 观察执行条件，日线与周线判断较长趋势。已有显式周期保留，可在任务中修改；K 线分析周期和 `dca_freq / dca_time / dca_weekday` 执行日程分别配置。现货行情使用中长期趋势、动量、波动与量能指标，不注入合约资金费率、持仓量或多空比。

单标的旧配置继续支持 `initial_qty / initial_cost`，表示任务开始前已有的数量与成本；`manual_avg_cost` 与初始数量同时填写时，初始成本为两者乘积。统计会在初始值上累加本任务自有订单的成交数量与成本，例如初始 1 BTC、成本 50,000 USDT，之后本任务买入 0.1 BTC、成本 6,000 USDT，统计为 1.1 BTC、成本 56,000 USDT，不会因填写初始值而忽略后续成交。交易所账户实际余额单独显示，其他任务或手工交易不计入本任务成交成本。

多标的无法把一份历史持仓成本可靠分配给不同币种，因此多标的任务禁用这些字段，API 导入非零值也会拒绝。已有手工初始持仓的单标的任务会阻止直接增加第二个标的，避免静默丢失成本；须先核对并单独保存初始持仓设置的调整，也可保留原任务、另建组合任务。各币种余额与成交单独读取。任务导出、完整备份及重新导入均保留标的清单和自定义周期。

看板展示组合汇总与逐标的持仓卡片，K 线可切换配置内标的；读取不完整时提示缺失币种，无法确认的市值和收益显示为未知，不按零值计入汇总。普通按标的清理历史会保留现货下单记录，用于累计预算与撤单归属核验，不会把预算重置。

### 通过 API 配置现货标的

以下接口均需要登录得到的 Bearer token。公共市场目录不使用交易私钥，支持 Binance 与 OKX；返回的市场必须处于可交易状态，现货与合约目录分开缓存 5 分钟。

```http
GET /api/config/market-symbols?exchange_profile_id=my-spot-profile&market_type=spot&quote=USDT&keyword=BTC&limit=50&offset=0&symbols=BTC/USDT,ETH/USDT
Authorization: Bearer <token>
```

响应包含 `symbols`（当前页的 `symbol/base/quote/market_type/display_name`）、`total`、`has_more`、`offset`、`limit`、`quote_currencies`、`cached`。`selected_symbols` 和 `invalid_symbols` 单独校验查询参数 `symbols`，不受搜索条件与分页影响。`limit` 范围为 1–200，翻页使用 `offset`。配置尚未保存时可省略 `exchange_profile_id`，改用 `exchange=binance` 或 `exchange=okx` 获取公共目录；若传入配置 ID，必须存在且市场类型匹配。

只修改一个已有现货任务的标的，不必提交完整配置或密钥：

```http
PATCH /api/config/my-spot-task/symbols
Authorization: Bearer <token>
Content-Type: application/json

{
  "symbols": ["BTC/USDT", "ETH/USDT", "SOL/USDT"],
  "expected_symbols": ["BTC/USDT"]
}
```

响应为 `success/config_id/mode/symbol/symbols`；其他任务设置、模型与交易所配置、密钥均保留。建议携带 `expected_symbols`：若保存前标的或顺序已改变，返回 `409`，刷新后再提交。省略该字段表示直接替换当前清单。空列表、超过 10 个、混合计价币或不可交易标的会被拒绝。完整 `PUT /api/config` 及配置导入同样执行服务端校验。

尚有本任务持仓、挂单或待核验资金记录的币种不能移出任务；关联历史资金的账户、模式也不能直接切换，返回 `409`。更换交易所配置凭据或通过完整配置删除任务同样受保护。需要校验标的时，交易所目录暂不可用会返回 `502`，本次变更不会保存；仅修改标题、预算或停用任务，不改变标的与账户时无需请求目录。新建、变更标的或交易账户、重新启用任务时会重新校验。

配置字段示例（模型与交易所凭据沿用后台绑定）：

```json
{
  "config_id": "spot-portfolio",
  "mode": "SPOT_DCA",
  "symbol": "BTC/USDT",
  "symbols": ["BTC/USDT", "ETH/USDT", "SOL/USDT"],
  "market_type": "spot",
  "market_timeframes": ["4h", "1d", "1w"],
  "dca_amount": 100,
  "dca_budget": 3000,
  "dca_schedule": {"frequency": "daily", "times": ["09:00", "21:00"], "days": [0], "timezone": "Asia/Shanghai"},
  "initial_qty": 0,
  "initial_cost": 0
}
```

## 批量操作与退出方式

默认使用上述 v3。REAL / STRATEGY 的旧 `contract_version=2` 独立动作和无版本嵌套格式仍作为直接兼容入口，不可在同一 envelope 混合。数量均使用基础币，LONG/SHORT 表示持仓方向。MCP 使用同一模式能力，详见 [MCP](MCP.md)。

整批先校验参数和模式，再按请求数组顺序逐项执行；默认失败、待核验或未知时停止。显式 execution_policy=independent 在明确失败时可继续无依赖项，结果未知仍停止本批；depends_on 指定必须 completed 的前项。规范 Agent/Chat 多工具列表按实际依赖逐项准入，不因历史拒绝全局停止；Chat 用户拒绝仍停止本轮后续写入。各项保留必要前置检查，提交后直接使用交易所接口响应，不追加查询、轮询或等待，超时也不补查。结果按原顺序汇总一次返回，已完成操作不回滚。这不是交易所原子事务，提交限价开仓后不能假定已成交并立即退出未成交数量。后台按原身份核验已尝试项，不补发尾项；未知状态不能更换 ID 反复提交。示例见[回执与恢复](TRADE_RECEIPTS_AND_RECOVERY.md)。

回执恢复只更新已有证据的对应操作项，保留先前失败项和 `not_executed` 未执行项。缺少请求信息或任一应执行项缺少确认时仍返回 `unknown`；已确认部分操作、其余明确未执行时返回 `partial`，后续依赖操作仍停止。恢复不会重放未执行动作，也不会把部分结果标为整批完成。

任务「基本设置 → 退出管理方式」对应 `exit_mode`：

| 设置 | 行为 |
| --- | --- |
| `attached_required` | 开仓须同时提供 TP/SL，继续使用原有保护维护。新建任务默认值。 |
| `attached_optional` | 可单独提供或省略开仓 TP/SL；没有设置的项目不会自动创建保护。旧 REAL 默认值。 |
| `independent_exits` | 入场不接受附带 TP/SL；成交后用独立退出委托指定数量、价格和退出类型。 |

旧 STRATEGY 未配置此字段时保持 `attached_required`。已有持仓、挂单、活动保护计划或待核验操作时不能切换；无法确认实盘账户已清空也会拒绝切换并返回 HTTP 409。SPOT_DCA 不使用这些合约退出设置。

独立模式允许同轮多次 `open` 分批入场，Hedge 账户允许同币多空；One-way 对向持仓或待成交入场会阻止冲突开仓，已知混合方向的 v2 批次在首次写入前拒绝，系统不自动切换账户模式。Agent 可本轮开仓，下轮再设置退出；本轮已经核验成交也可立即 `close`。提交成功不能当作成交，退出只针对已有归属仓位。

默认入口 `execute_trade_actions` 的 `edit` 动作通过 `order_id` 修改入场和退出的目标未成交量 `remaining_amount`，并按当前模式支持价格或触发价；`cancel` 动作撤销挂单。旧 `update_exit_order` 等入口保留兼容。看板同时展示委托价和触发价、固定/全部、实际成交及覆盖估计。覆盖不是成交保证，特别是 SL LIMIT 触发后仍可能无法成交。

固定 `amount` 档不再自动缩量或补量。单笔量不能超过当前已核验仓位，但同组挂单合计可超过仓位（例如 0.7 + 0.6 对应 1 BTC），`quantity_conflict` 单独提示冲突，由 Agent 决定 edit/cancel，最终接收和执行以交易所为准；此提示不冒充 pending，不阻止合法管理操作。普通 LIMIT、TP、SL 分组观察覆盖。仓位归零后清理同方向同周期的剩余入场和退出单，核验完成后才允许下一周期；撤单期间迟到的入场成交继续作为残仓管理，不自动平掉。暂时空读或未知状态不能当作归零。

新 `close` 明确二选一：`amount > 0` 或 `close_all=true`。市价 all 取提交前仓位快照，之后新增入场不被这张订单追平；条件市价 all 在触发时动态全平，包括同周期后续加仓，等待期间计划 amount/remaining 为 null，不用零表示。例：1 BTC 设置 TP 0.2、0.3、最后 all；SL 同样可设置固定档及 all。最后一档是独立触发条件，跳空可先触发，不保证前两档依次成交。原生 all 面向交易所账户的该品种该方向，要求完整归属；之后外部手工加仓也属于交易所全平方向范围，不能隔离成某个入场批次。

| order_type | 委托价 price | trigger_price | close_all | Binance USD-M 通道 |
|---|---|---|---|---|
| market | 不传 | 不传 | 提交前快照 | `/fapi/v1/order` MARKET |
| limit | 必填 | 不传 | 不支持 | `/fapi/v1/order` LIMIT |
| stop_market | 不传 | 必填 | 原生动态 | `/fapi/v1/algoOrder` STOP_MARKET |
| stop_limit | 必填 | 必填 | 不支持 | `/fapi/v1/algoOrder` STOP |
| take_profit_market | 不传 | 必填 | 原生动态 | `/fapi/v1/algoOrder` TAKE_PROFIT_MARKET |
| take_profit_limit | 必填 | 必填 | 不支持 | `/fapi/v1/algoOrder` TAKE_PROFIT |

普通 LIMIT 允许可成交或亏损侧价格；条件单按 LONG/SHORT 和止盈/止损校验触发方向，默认 `CONTRACT_PRICE`，历史记录保留原工作价基准。fixed 在 One-way 使用 reduceOnly，在 Hedge 使用 positionSide；原生 all 使用 closePosition，不带 quantity/reduceOnly。依据：[普通下单](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/New-Order)、[条件下单](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/New-Algo-Order)、[修改普通 LIMIT](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/Modify-Order)。

旧工具 `take_profit_limit + price` 仍是普通 LIMIT；旧 `amount=0` 在首次提交时固定为仓位快照，重放不重新计算。不能仅凭缺少 trigger_price 猜测新旧版本。新接口不用 amount=0 表示 all，亦不模拟交易所不支持的 all LIMIT。

模拟条件 LIMIT 分为等待触发、触发后的限价委托和实际成交；不会用触发前的同根行情倒填成交。固定超额档实际成交封顶于剩余仓位，未执行余量单独记录，不反向开仓、不按计划量虚记盈亏。同根行情沿用确定性的 SL 优先顺序，无法还原真实 tick 顺序或保证实盘成交顺序。

## 实盘 TP/SL

本节描述 `attached_required` / `attached_optional` 的附带保护模式。默认入口的每项 `open` 提供持仓方向 `side`、限价 `price`、标的币数量 `amount` 和 `reason`；兼容入口 `open_position_real` 保留原 `action`、`entry_price` 参数。`attached_required` 要求同时提供 `stop_loss`、`take_profit`；`attached_optional` 可省略或单独提供。多单止损须低于入场、止盈须高于入场，空单反之；价格与数量必须为有限正数，交易所精度调整后再次校验。首次开仓未提供的保护不会自动创建；可选模式下同方向加仓省略参数继承现有保护，填写则先更新该项整仓保护再加仓，工具返回有效价格。

订单跟踪计划先写入 PostgreSQL `real_protection_plans`，然后提交限价入场。订单响应、状态变化和保护调整写入 `real_protection_events`。成交后，独立维护任务只为已提供的止损或止盈创建交易所条件市价单；首次开仓两者都未提供时仅跟踪成交，不创建保护单；加仓继承的保护继续有效。LLM 不负责轮询触发价格。

当前支持 Binance USD-M 线性永续和 OKX 线性永续。工具输入为标的币数量，发送 OKX 等合约订单时按 `contractSize` 转换为合约张数。Binance 使用 `closePosition`；OKX 单向模式使用 `closeFraction=1`，双向模式按当前仓位数量设置并在部分成交或减仓后重建覆盖。关闭委托采用平仓方向/只减仓语义，避免反向开仓。

保护粒度是**该配置、该交易对、同一方向的整个仓位**，包括该方向已有仓位。一个交易所 API Key 对应的同一品种不能同时由两个配置托管保护。使用不同 API Key 连接同一交易所账户仍可能无法识别为同一账户，不应这样重复托管。

- `WAITING`：计划存在，尚未观察到持仓或保护安装尚未完成。
- `ACTIVE` 且 `error` 为空：最近一次维护已核验已配置的保护；没有设置的项目仍无保护，不是此刻的实时成交证明。
- `EXITING`：触发、穿过止盈止损或故障退出，正在撤销剩余入场单、平残余仓位、清理保护单。
- `DONE`：持仓为空，相关入场和保护订单已完成清理。

模型每轮在挂单行中看到订单 ID、方向、价格、数量及对应的本地保护状态、核验时间和错误信息，不再追加独立保护摘要或原始 JSON；重复目标价格省略，未出现在快照中的本地计划以及目标/实际价格差异仍标注待核对。提交保护单获得权威 ACK 后直接返回受理事实，不为了返回补查订单或仓位。后续状态由后台按原订单/客户端身份自动核验，用户无需再次调用工具。计划在重启后继续核对；未知下单结果按持久化客户端 ID 查询，不盲目重发。版本检查阻止过期计划覆盖新计划。交易所持续不可用或无法确认客户端订单时保留错误和计划，不伪装成成功。

默认 `protect` 动作以 `side` 调整已有仓位或托管中的未成交计划；兼容入口 `update_position_protection_real(pos_side, stop_loss?, take_profit?, reason)` 保留。省略的价格保持不变，可首次只设置止损或止盈。相同价格的保护单复用；修改保护沿用原安装与清理顺序，金融工具直接依据每个交易所接口响应推进，不能为本项再查询确认。缺少确定响应时及时返回并保留原身份，后续由后台核验。Binance 不允许新旧单并存时存在先撤旧单后的短暂保护空窗；撤单结果未知不能继续创建。仍有未成交入场单时，新价格也必须适用于这些入场价。

撤单确认优先使用订单 ID 匹配的终态回执；Binance 条件单的 `algoId` 与 `code=200` 成功回执也作为确认依据，避免查询接口或挂单列表延迟导致 agent 必须再次调用。回执丢失或不完整时保留 pending/unknown 和原身份，及时返回；后台只读核验不重发原撤单。接口返回订单不存在本身不视为撤单成功。

默认 `edit` 动作修改授权管理范围内限价入场，调用交易所原生改单。`remaining_amount` 是期望未成交量，执行时加上最新已成交量形成原生总量；省略项保留当前参数。兼容入口 `update_entry_order_real(order_id, entry_price?, amount?, reason)` 的 `amount` 仍是包含已成交部分的总标的币数量，必须大于已成交数量。新入场价必须满足当前已设置的止盈/止损约束；整仓保护价格由 `protect` 调整。ACK 已证明修改结果时直接返回 `confirmed`；证据不足保存为 `pending`，后续后台核验，不能重复提交绕过未知状态。

主动部分或全部退出使用 `close` 动作，明确指定数量或当前模式支持的 `close_all=true`。兼容入口 `close_position_real` 保留 `entry_price=0` 的市价退出语义；提交平仓委托不直接记录成已平仓。直接撤销保护单不等于修改保存的整仓保护目标；需要通过 `protect` 调整目标。

首次保护安装有轮询与网络延迟，并非原子附带单。维护循环每 5 秒扫描，线程池繁忙、网络超时和交易所限速会延长实际间隔。已经安装的保护由交易所触发；停止服务不撤销它，但无法继续安装、改单或清理兄弟订单。无法确认任何止损时，系统先核对未知提交，必要时尝试撤销入场并只减仓退出；网络不可用时退出也可能失败。止损成交价格和损失仍受跳空、滑点影响。

Web 内运行调度器时，关闭 Agent 分析调度不会关闭已有保护维护。分离部署须保持独立调度器服务运行，`RUN_SCHEDULER_IN_WEB=false` 的 Web 进程不承担维护。不要在托管未结束前删除配置、更换账户凭据或改掉交易模式。

## 模拟交易

上述交易所原生改单和下述合约成交账本仅接入 REAL 永续合约。SPOT_DCA 保留现货成交记账与定投预算，不使用合约 TP/SL；STRATEGY 按任务选择的退出方式模拟执行，不向交易所发送订单。

`open_position_strategy` 校验当前模式所需的 TP/SL 并保留挂单有效期。附带模式使用 `update_position_protection_strategy(order_id, stop_loss?, take_profit?, reason)` 按订单管理保护。`close_position_strategy` 在附带模式下按当前市场价和 `amount` 部分或全部退出已成交仓位；条件退出需独立模式，不能把旧 `entry_price` 正值静默当成市价成交。独立模式维护汇总持仓及分批退出单，部分退出保留剩余数量与成本，并记录本次实际盈亏。模拟成交及触发检查使用维护时段内行情，不把整个日线高低点误当作当前时刻成交。

## 长期交易规则

交易 Agent 和绑定任务聊天不再注入既有规则；自动规则维护已暂停，短期记忆模型也不再提供 manage_trading_rules。历史规则、人工锁和版本记录保留，人工规则管理接口不变。程序风控与工具校验继续生效。

后台「记忆中心 → 交易规则」可按任务编辑内容、启停、人工锁定并查看历史。人工新增默认锁定；模型不能修改或停用锁定规则，管理员仍可编辑。每条内容最多 1200 字符，每个任务最多 30 条启用规则，停用保留记录。并发编辑遇到过期版本返回 HTTP 409，页面保留草稿并要求重新打开最新版本，防止覆盖他人修改。规则存储于 `trading_rules` / `trading_rule_revisions`，启动时自动创建；不把短期行情、未经核实成交或临时计划写成长期事实。

每次记忆整理正常一次模型调用，不带工具、不读取完整规则列表，仅合并旧 memory 与当前窗口摘要和实际证据。失败保留旧记忆，自动队列退避重试最多 3 次后停止；网络请求重试仍受配置和单次最多 3 次请求限制。

## 决策上下文与短期记忆

每轮默认提供当前市场和账户、最新完整短期记忆（含覆盖区间与更新时间）及最近三轮策略摘要（按时间排序）。配置摘要模型返回的正文完整传入，不追加或替换为原始长篇分析。只有识别到旧版硬截断标记或空策略记录时，才从已有完整来源恢复；没有完整来源的旧内容不能补造。短期记忆概括状态与教训，最近三轮补足记忆整理间隔内的观点变化；均属于历史计划和执行记录，不能代替本轮账户事实。各记忆来源独立读取，行情或新闻读取失败不会把本地记忆和历史清空。

自定义 Prompt 可使用 `{recent_summaries_text}` 和 `{short_memory_text}`；这些默认区块未写入模板时自动补充，已存在则不重复追加。旧 `{history_text}` 渲染为空，Daily Memory 章节及仅含该占位符的空标题区块会在渲染时清理。绑定交易配置的聊天读取同一上下文并沿用交易审批；默认分析聊天不调用交易工具或写入交易 Agent 记忆。

每轮交易结束将完整决策与工具执行回执交给配置的摘要模型（如 DeepSeek），结合策略 Prompt 生成纯文本 `strategy_logic`；自定义 Prompt 和模型配置实际生效。原始分析保存于 `content`，调用顺序、工具参数与真实回执保存于 `decision_json`，不再生成结构化报告，不按字符数裁切。摘要调用失败时明确标记 `【策略压缩失败；以下为未压缩原始记录】` 并保留完整源记录。单轮摘要调用在「Agent 运行」独立记为 `strategy_summary`，可核对模型、输入、输出和费用。每轮摘要成功落库后由独立步骤更新短期记忆；摘要失败不触发该轮记忆更新。成功挂单不等于成交，失败或待核验回执不得写成已执行；维护已有入场挂单同样需评估成交风险，等待确认的条件不得通过提前挂单绕过。

每次运行完成并保存有效压缩摘要后，短期记忆使用同一 config_id 最近 4 小时内含本轮的全部有效压缩摘要、旧版最近 7 天成交/平仓操作记录、上一轮有效记忆。自动与手动整理共用素材构造，本轮摘要只出现一次，不另外查询新闻，也不拼接单独的最新回执或规则证据。模型输出一份完整纯文本摘要。按 config_id + run_id 幂等处理，同一任务串行更新，保留窗口、版本和证据来源。每日与固定四小时批次不再生成或注入。

`execution_fills` 按账户（交易所 ID/API Key 摘要）、品种和成交 ID 去重；`execution_order_links` 关联托管订单及主动退出订单；`execution_position_history` 将已归属的开仓到平仓成交重建为一条完整交易周期，保存开平时间、成交均价、数量、止盈止损、退出原因、手续费和已实现盈亏。WebSocket 用户成交流提供及时更新，独立 REST 同步补漏并判断完整性；正常至少间隔 30 秒，网络/队列可能延迟。首次回看 7 天，旧版 24 小时断点会自动补齐到 7 天，随后重叠回读断点；按日分段、满页拆分时间窗口，单次最多 100 次请求。失败保留已验证区间，同一毫秒超出分页上限明确标为不完整。无法关联的手工、其他策略或旧订单成交不冒认为本 Agent。

实盘完整周期统计读取 `execution_position_history`；短期记忆另外读取最近 7 天成交活动和同步缺口，不再把 `position_history` 的持仓快照或单个平仓成交分片当成完整交易。同步未覆盖时显示“账本尚无完整周期”，不会据此断言过去 7 天没有交易；成交源缺少盈亏时保留为未知，不按 0 计入胜率和累计盈亏。

记忆整理区分事实、推断与计划，保留来源窗口和必要待核实事项；记录读取失败不补零。没有有效压缩摘要的窗口不生成新记忆，旧记忆继续保留，不能据此断言没有交易。

模型调用失败、空输出、截断、拒绝或返回工具调用时保留旧记忆；不要求 JSON，不进行格式或“纯策略”内容纠正。记忆待处理记录与摘要一起落库，重启后只重试记忆，不重放交易。旧规则部分成功回执保留审计，不重新执行。纯分析聊天不写入交易 Agent 记忆。

## Agent 运行记录

后台「Agent 运行」在登录后展示功能上线以来的实际模型消息、角色、工具 schema、输出、调用状态和 token 数，每任务保留最近 100 次、最长 30 天，可核对完整 Prompt 与真实工具回执。查看记录不会重新分析或下单，历史调用未保存的输入不补造。调用开始时快照已配置费率，结束时按 token 数估算费用；有服务商费用时优先采用，页面标记费用来源。缺少用量或价格时估算未知，计入已报告的缓存用量，未报告的缓存无法猜测，改价不回算已记录调用。规则部分成功和记忆失败应结合独立复盘结果与工具回执核查。具体设计见 [Prompt 与角色分工](PROMPT_DESIGN.md)。

## 历史每日归档

Daily memory 的生成、注入与 UI 入口已停用，生成接口返回 410；旧数据保留供备份与历史兼容读取。新运行统一保存决策原文、纯文本策略摘要和逐轮短期记忆。

系统没有额外内置固定的保证金上下限、账户风险百分比、最低盈亏比、滑点预算或止损后冷却时间。这些交易偏好仍由任务提示词和 Agent 决策控制。交易所及提示词已有的基础校验（价格、数量、方向、账户模式、订单归属和状态）继续生效。

采样记录包含观察到的最大/最小浮盈亏、发现平仓后 15/60 分钟附近已收盘的一分钟价格，供复盘参考。这不是逐笔真实 MFE/MAE，也不证明继续持仓一定更好。新表在应用初始化时创建，旧版未保存归属的订单不会被猜测归属。代码更新后需要正常重启后台加载新的工具和维护任务；测试不连接实盘或修改交易所订单。

## 周期与指标

已有运行间隔和自定义时段保持原值，例如 20 分钟任务仍在 `:00 / :20 / :40` 运行。新建合约任务默认 60 分钟，使用 `market_profile=hourly`：`1h / 4h / 1d` 各拉取 600 根用于指标计算，向模型展示最近 `24 / 12 / 7` 根已收盘 K 线。旧任务保留 legacy 行情输入与显式配置；现货默认 `4h / 1d / 1w`，30m、1M仍可选。`1w` 是交易所锚定周线，不是滚动7日。

### 自定义运行时段

在后台编辑 REAL / STRATEGY 任务，打开「调度设置」，可设置默认间隔并添加最多 20 条 `run_schedule` 规则。每条规则包含名称、星期（周一为 0）、时区、开始/结束时间和间隔分钟数（15–1440）。上面的规则优先；未匹配时使用默认间隔，按应用 `TIMEZONE` 当天零点对齐。已有任务不添加规则便保持原有行为，SPOT_DCA 使用独立的多时点定投日程。

自定义时段预设仅替换编辑器中的规则，不改任务默认间隔。保存任务后生效：

| 优先级 | 时段 | 间隔 |
| --- | --- | --- |
| 1 | 北京时间周六、周日 00:00–24:00 | 30 分钟 |
| 2 | 纽约时间周一至周五 09:30–16:00 | 20 分钟 |
| 3 | 北京时间周一至周五 08:00–16:00 | 30 分钟 |

纽约时段只是可编辑的美盘参考窗口，自动处理夏令时。北京时间周末优先，因此纽约周五下午进入北京时间周六后，改用周末间隔。

时段包含开始、不包含结束，从开始时间计算间隔；例如 09:30 起每 20 分钟在 09:30、09:50、10:10……运行。开始晚于结束表示跨午夜，例如周五 22:00–02:00 覆盖到周六凌晨；全天填 00:00–24:00。切换规则时重新按新规则的开始时间对齐，所以相邻两次执行可能短于设置的间隔。这是时间槽调度，不是“上一轮结束后再等待 N 分钟”；运行中的同一任务仍不会并发重入，离线错过的分析时间槽不会批量补跑。Prompt 中的下次运行时间使用同一规则计算。

降低决策频率只减少 Agent 分析调用，已有止盈止损保护仍独立扫描。修改代码部署后需重启后端及调度器；保存任务规则本身沿用现有配置刷新机制。

Dashboard 的 K 线刷新保留画布实例和浏览范围；切换交易对或 K 线周期时重置范围，主题和尺寸变化不重新创建图表。浏览器回归测试使用独立模拟页面：先运行 `npm run dev --prefix frontend -- --port 5179`，再运行 `uv run --with playwright python tests/browser_dashboard.py`（需已安装 Edge），不调用真实交易接口。

| 周期 | 作用 |
| --- | --- |
| 15m | 入场位置、近期波动与交易触发 |
| 1h | 交易条件、支撑阻力和失效 |
| 4h | 趋势/震荡环境 |
| 1d、1w | 背景和更大级别风险，不重复展示10根K线 |

指标仅使用已收盘K线，输入注明最后收盘时间、排除的未收盘K线、数据年龄与EMA预热不足。任务与聊天的最新价格独立读取当前配置交易所、同一标的的 `ticker.last`，在指标计算后取样，注明取样时间及交易所报价时间（交易所未提供时标为 N/A）。报价失败或价格无效时，当前价显示 N/A，不用历史收盘价、其他交易所或零值替代。当前报价与指标收盘价可能不同，不能把这种差异当作数据错误；本轮报价是取样时的快照，不会在模型思考期间持续更新。短期样本不足的EMA/RSI/布林/MACD明确缺失，不用0伪装有效指标。

- EMA 保留20/50/100/200，不优化拟合近期盈亏；注明预热不足。
- 布林采用20周期、2倍总体标准差，增加 `%B` 和最近120根带宽分位。触轨不自动代表反转。
- VWAP 统一按UTC日内重置，以K线典型价近似，注明锚点；不同周期的典型价近似仍可能不同。
- SMC 摆动点要等右侧K线确认后才参与结构事件；结构和区域带年龄、时间及ATR距离。OB去重，展示优先选附近区域，超过6ATR的区域不挤占短线提示。
- IFVG 要求收盘突破缺口边界，反向再次失效后排除，不把一次影线填补自动算作有效反向缺口。
- Volume Profile 明示统计窗口及OHLCV分配近似，不能叫做真实持有人筹码成本。
- 多空比注明人群/周期；OI单点没有变化率和合约单位换算时不能单独作为方向依据。

这些改动提高执行与证据一致性，不代表已经证明策略具有正期望。测试使用隔离数据库、模拟交易所，以及安装版本CCXT的真实请求构造器；没有用真实账户开单验证。部署需重启后端/调度器以加载代码并自动创建新表。
## 加仓与 7 天周期补充

保护撤单直接使用匹配身份的权威 ACK 返回；缺少完成证据时保留原意图和待核验状态，系统后台自动读取，不要求模型重复提交或查询。后台回执核验不重发金融写入，也不提交原调用未尝试的替代单。

短期记忆整理的篇幅由配置的短期记忆 Prompt 指引，程序完整保存有效纯文本，不按固定字数裁切。输入仅为 4h 有效压缩摘要、旧版 7 天成交/平仓记录及上一轮有效记忆；不恢复全历史权益、回撤或规则列表。每轮交易保存决策原文与有效策略摘要后触发独立更新；历史文字不能替代本轮执行证据。

实盘附带保护模式下，同方向仓位共享 TP/SL：可选模式加仓省略参数继承，提供单项则更新该项整仓保护，另一项保留；更改保护必须核验后才增加委托。Dashboard 留空表示保留，取消必须显式选择。调整时校验保护版本，失败不提示已生效。

成交账本按账户/品种/方向的归零边界重建周期，保留加仓、部分退出、混合退出原因和保护版本；外部退出不凭价格推断 TP/SL，未知入场或混合归属周期不计入策略战绩。周期唯一 ID 来自首笔成交，避免同一个保护计划跨周期导致覆盖。7 天周期与 7 天成交活动分别统计。

数据库诊断、清理边界和同步副本实际发现见 [核查说明](DB_AUDIT_2026-09-08.md)。


### LLM 断线重试与数据刷新

- 后台 `llm_timeout_seconds` 是每次请求的客户端超时（秒），首次请求和重试使用同一设置；`llm_max_retries` 是每个模型的额外重试次数。SDK 内部重试关闭，由应用统一重试。
- `Server disconnected without sending a response` 表示上游服务或中间网关已经断开连接。即使客户端设置 1200 秒，上游也可能在约 340 秒提前断开；增加客户端超时不能覆盖上游连接限制。连接失败后仍采用短暂退避（1、2、4 秒），超时值不代表重试间隔。
- 主决策模型、小模型每次重试，以及切换兜底模型前，重新获取配置周期的 K 线并计算指标，刷新余额、持仓、挂单和提示词时间。消息读取全局已完成快照，不因任务切换或模型重试重复评分/摘要。
- 新快照替换旧提示词，保留已完成的工具调用与返回记录。失败流的部分回答不进入下一次请求，也不会由重试逻辑重新执行交易工具。
- 刷新缺少周期、K 线被标记过期、账户查询失败或提示词刷新异常时，中止本轮决策；不使用旧快照继续请求兜底模型。
- 日志记录每次请求的配置超时、实际尝试耗时和底层错误类型。部署后查看 `configured_timeout=1200s`，可确认运行进程加载的配置。
# 入场与保护改单工具

工具接口及参数语义通过实际绑定的工具描述提供；当前退出方式写入决策上下文，自定义提示词同样适用。有工具不代表交易所一定接受请求；模型应报告实际调用结果，不能根据旧摘要断言“环境没有执行通道”。用户明确要求不修改某挂单时仍应保持不变。

- REAL：默认 `edit` 动作修改授权范围内原生支持改单的限价单；`remaining_amount` 指目标未成交量，不能改变原方向。附带保护模式保留已有 TP/SL，整仓保护通过 `protect` 调整。
- REAL：默认 `protect` 按 `side` 调整 `stop_loss` / `take_profit`，省略项保留，管理同方向整个仓位及托管待成交计划。顺序批次不是原子事务；需要先调保护时，保护必须同时兼容旧、新入场及当前仓位，失败后停止并核对。
- STRATEGY：默认 `edit` 根据 `order_id` 修改未成交入场价、目标未成交量及当前模式允许的 TP/SL，省略项保留，方向、有效期不变。拒绝已成交、过期、其他配置/品种和超过模拟可用余额的订单。
- STRATEGY：附带保护模式下，已成交仓位通过带原 `order_id` 的 `protect` 修改保护；独立模式通过 `close` / `edit` 管理各档退出。两种模式都不能改写历史入场价格。旧直接工具保留原总 `amount` 和 `pos_side` 参数，作为兼容接口隐藏。
- 多单待成交价格要求 `SL < Entry < TP`，空单要求 `TP < Entry < SL`（只校验已设置项）。持仓保护以当前触发参考价校验，允许移动止损保护浮盈。LONG/SHORT是持仓方向，不是平仓买卖方向。
- 实盘入场改单只在 `confirmed` 时报告确认；`pending` 不可重复提交，`unchanged` 表示未改变。保护 `WAITING` 不是已安装保护，`ACTIVE` 且无错误仅代表最近核验通过。

长期规则保留人工编辑及版本存档，但不再注入决策模型；旧规则占位符渲染为空，已知遗留规则和小时级策略章节会被清理。默认提示词按退出模式区分决策规则，自定义文件保留；独立模式运行时追加跨轮执行及数量语义事实，账户快照提供退出单、覆盖与数量冲突。

任务运行时持续保存 `scheduler_runs.decision_json`，前端按轮次显示模型输出、推理文本或摘要、调用参数及工具回执；刷新页面不会丢失已记录的调用。只有推理 token 而没有文本时显示用量及服务商未返回文本的说明，不生成额外推理。历史完成记录继续读取 `summaries.decision_json`。
# 决策输入中的当前交易状态

REAL/STRATEGY 独立退出模式使用共享 `DecisionTradeState`：持仓、有效订单、SL 覆盖估计、
固定数量冲突及范围明确的执行异常。有效订单按通道和当前 ID 去重，触发母单与执行子单保持关联。
本轮账户快照说明可见量，本地证据说明管理者与执行；冲突保留各自观察时间。只读快照不认领仓位，默认金融动作在已授权的可见范围内首次认领并建立管理证据。
结构化未知数量为 null，Prompt 显示“未知”，不补零；读取失败不同于已确认无异常。正常等待触发不属于未决写入。
持仓使用单行文字，挂单使用完整 ID、用途、数量、价格、状态表格；真实来源时间、覆盖和异常单列。条件限价保留触发价与限价，all 标明触发时该方向全部，父子身份与精确量价保留，省略重复内部字段。见 [样例](DECISION_CONTEXT_EXAMPLE.md)。

## 纯文本记忆与接口直返（2026-10-15）

短期记忆采用一份纯文本摘要：Agent 完成决策和工具执行后保存本轮策略压缩，再整理最近 4 小时内含本轮的全部压缩摘要、旧版最近 7 天成交/平仓操作记录与上一轮有效短期记忆。不单独查询新闻。模型不返回 JSON、来源哈希或多份投影，也不进行格式/内容纠正调用。非空、完整响应及无工具调用仍是基本要求；传输重试、费用审计、租约和失败保留旧记忆继续生效。

新记忆与新策略摘要直接发布文本，程序保存账户范围、来源哈希和执行关联；沿用已有存储表保留历史，不再生产旧投影转换或 contract recovery 任务。已有有效已发布内容仍可读，人工编辑/删除使旧来源失效，迟到结果不能覆盖变更来源。最近三条策略摘要的展示与 4 小时整理窗口分别处理。“重试失败整理”只重排仍有源摘要的失败记忆任务，不重排旧投影。原文和发布记录原子保存，失败不重放交易。
