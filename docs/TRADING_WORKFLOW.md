# 交易、记忆和指标流程

## 实盘 TP/SL

`open_position_real` 的每笔订单必须提供 `action`、`entry_price`、标的币数量 `amount` 和 `reason`。`stop_loss`、`take_profit` 均为可选，也可只提供其中一个。多单止损须低于入场、止盈须高于入场，空单反之；价格与数量必须为有限正数，交易所精度调整后再次校验。首次开仓未提供的保护不会自动创建；同方向加仓省略参数继承现有保护，填写则先更新该项整仓保护再加仓，工具返回有效价格。

订单跟踪计划先写入 SQLite `real_protection_plans`，然后提交限价入场。订单响应、状态变化和保护调整写入 `real_protection_events`。成交后，独立维护任务只为已提供的止损或止盈创建交易所条件市价单；首次开仓两者都未提供时仅跟踪成交，不创建保护单；加仓继承的保护继续有效。LLM 不负责轮询触发价格。

当前支持 Binance USD-M 线性永续和 OKX 线性永续。工具输入为标的币数量，发送 OKX 等合约订单时按 `contractSize` 转换为合约张数。Binance 使用 `closePosition`；OKX 单向模式使用 `closeFraction=1`，双向模式按当前仓位数量设置并在部分成交或减仓后重建覆盖。关闭委托采用平仓方向/只减仓语义，避免反向开仓。

保护粒度是**该配置、该交易对、同一方向的整个仓位**，包括该方向已有仓位。一个交易所 API Key 对应的同一品种不能同时由两个配置托管保护。使用不同 API Key 连接同一交易所账户仍可能无法识别为同一账户，不应这样重复托管。

- `WAITING`：计划存在，尚未观察到持仓或保护安装尚未完成。
- `ACTIVE` 且 `error` 为空：最近一次维护已核验已配置的保护；没有设置的项目仍无保护，不是此刻的实时成交证明。
- `EXITING`：触发、穿过止盈止损或故障退出，正在撤销剩余入场单、平残余仓位、清理保护单。
- `DONE`：持仓为空，相关入场和保护订单已完成清理。

模型每轮能看到价格、计划状态、最近核验时间、保护订单 ID 和错误信息。提交保护单后会在约 1.25 秒内做数次只读确认，以兼容交易所短暂的读写延迟；这些确认不会重复下单。超过该窗口仍不可见时保留待核验状态，后台维护继续查询，用户无需用相同参数再次调用工具。计划在重启后继续核对；未知下单结果按持久化客户端 ID 查询，不盲目重发。版本检查阻止过期计划覆盖新计划。交易所持续不可用或无法确认客户端订单时保留错误和计划，不伪装成成功。

`update_position_protection_real(pos_side, stop_loss?, take_profit?, reason)` 调整已有仓位或托管中的未成交计划。省略的价格保持不变，可首次只设置止损或止盈。相同价格的保护单复用，改变时优先先装新单、核验，再撤旧单。Binance 拒绝并存时，核验旧单取消后再创建新单，此路径存在短暂保护空窗；撤单未确认不继续创建，无法确认止损时沿用故障退出机制。仍有未成交入场单时，新价格也必须适用于这些入场价。

撤单确认优先使用订单 ID 匹配的终态回执；Binance 条件单的 `algoId` 与 `code=200` 成功回执也作为确认依据，避免查询接口或挂单列表延迟导致 agent 必须再次调用。回执丢失或不完整时，同一次调用内进行有界轮询（累计等待约 14.75 秒，不含请求耗时），不重复提交撤单；仍无法核验则保留未确认状态，由后续维护继续处理。接口返回订单不存在本身不视为撤单成功。

修改本配置创建的限价入场使用 `update_entry_order_real(order_id, entry_price?, amount?, reason)`，调用交易所原生改单，不执行撤单重开。`amount` 是包含已成交部分的总标的币数量，必须大于已成交数量。新入场价必须满足当前已设置的止盈/止损约束；保护价格继续使用专用工具调整。只有查询确认后才返回 `confirmed`；超时保存为 `pending`，后续查询确认，不能重复提交绕过未知状态。

主动部分或全部退出继续使用 `close_position_real`，`entry_price=0` 为市价退出；提交平仓委托不直接记录成已平仓。不得直接撤销托管保护单来改变计划；维护任务会按保存的计划恢复它。

首次保护安装有轮询与网络延迟，并非原子附带单。维护循环每 5 秒扫描，线程池繁忙、网络超时和交易所限速会延长实际间隔。已经安装的保护由交易所触发；停止服务不撤销它，但无法继续安装、改单或清理兄弟订单。无法确认任何止损时，系统先核对未知提交，必要时尝试撤销入场并只减仓退出；网络不可用时退出也可能失败。止损成交价格和损失仍受跳空、滑点影响。

Web 内运行调度器时，关闭 Agent 分析调度不会关闭已有保护维护。分离部署须保持独立调度器服务运行，`RUN_SCHEDULER_IN_WEB=false` 的 Web 进程不承担维护。不要在托管未结束前删除配置、更换账户凭据或改掉交易模式。

## 模拟交易

上述原生改单和下述合约账本仅接入 REAL 永续合约。SPOT_DCA 保留现货成交记账与定投预算，不使用合约 TP/SL；STRATEGY 保留原有的必填 TP/SL 模拟执行流程。

`open_position_strategy` 同样强制正确的 TP/SL，保留挂单有效期。`update_position_protection_strategy(order_id, stop_loss?, take_profit?, reason)` 按订单管理模拟仓位或未成交计划，确认状态未被并发改变后写入。模拟成交与止盈止损仍由一分钟行情维护检查，不把整个日线高低点误当作当前时刻成交。

## 每轮记忆

REAL 每轮直接注入当前账户、品种最近 **24 小时**的已归属成交事实，最近 20 条明细及窗口内全部已保存成交的统计；未结束的保护计划不受窗口限制。工作记忆压缩也接收这份证据，但不能替代下一轮直接读取的事实。开平仓链完整时额外重建成交均价、持仓时长、退出用途及费用；部分成交条数不是完整交易笔数。换账户不会沿用旧账户的直接成交事实，旧文字记忆仍必须按最新快照复核。

`execution_fills` 按账户（交易所 ID/API Key 摘要）、品种和成交 ID 去重；`execution_order_links` 关联托管订单及主动退出订单；`execution_position_history` 将已归属的开仓到平仓成交重建为一条完整交易周期，保存开平时间、成交均价、数量、止盈止损、退出原因、手续费和已实现盈亏。WebSocket 用户成交流提供及时更新，独立 REST 同步补漏并判断完整性；正常至少间隔 30 秒，网络/队列可能延迟。首次回看 7 天，旧版 24 小时断点会自动补齐到 7 天，随后重叠回读断点；按日分段、满页拆分时间窗口，单次最多 100 次请求。失败保留已验证区间，同一毫秒超出分页上限明确标为不完整。无法关联的手工、其他策略或旧订单成交不冒认为本 Agent。

实盘完整周期统计读取 `execution_position_history`；短期记忆另外读取最近 7 天成交活动和同步缺口，不再把 `position_history` 的持仓快照或单个平仓成交分片当成完整交易。同步未覆盖时显示“账本尚无完整周期”，不会据此断言过去 7 天没有交易；成交源缺少盈亏时保留为未知，不按 0 计入胜率和累计盈亏。

每次生成并保存新的 `strategy_logic` 后，压缩器接收“旧工作记忆 + 新策略逻辑 + 本轮工具结果”，**替换为有界的新记忆**，不无限拼接。建议结构为当前假设、候选计划/失效条件、执行事实、废弃观点/待核实事项。工具成功挂单也不等于成交；下一轮账户快照始终优先。

压缩失败时仍写入带“待核实”标记的最新策略，避免继续展示已失效旧计划。额外成本是每个有效分析轮次增加一次短期记忆压缩。四小时任务仅作为旧流程/漏更新的补充，不覆盖更新的每轮记忆。默认 Prompt 不再重复插入相同短期记忆。

## 每日复盘

每日总结按北京时间目标日 00:00 至次日 00:00 读取当日策略记录和执行证据。REAL 使用该日交易所成交补抓后的专用账本；现货与模拟保留本地订单、成交、持仓和保护事件等证据。读取不依赖打开 Dashboard，今日尚未结束时不能声称整日同步完整。

REAL 统计目标日全部已保存且已归属的成交，明细最多 200 条并报告省略数量；`window_complete` 表示读取区间是否覆盖目标日，不代表所有历史订单都已归属。Binance 额外读取账户/品种资金流水（最多 50 页），按流水类型和资产单列，不能与本 Agent 成交盈亏重复相加；OKX 资金流水适配尚未提供，明确标记不可用。现货保留最多 5 页的当日成交查询并标注完整性未证明。缺失盈亏/费用标记未知，不跨币种相加。总结区分分析轮数、成交条数和完整交易，包含策略演变、真实执行、偏差和下一日条件。

系统没有额外内置固定的保证金上下限、账户风险百分比、最低盈亏比、滑点预算或止损后冷却时间。这些交易偏好仍由任务提示词和 Agent 决策控制。交易所及提示词已有的基础校验（价格、数量、方向、账户模式、订单归属和状态）继续生效。

采样记录包含观察到的最大/最小浮盈亏、发现平仓后 15/60 分钟附近已收盘的一分钟价格，供复盘参考。这不是逐笔真实 MFE/MAE，也不证明继续持仓一定更好。新表在应用初始化时创建，旧版未保存归属的订单不会被猜测归属。代码更新后需要正常重启后台加载新的工具和维护任务；测试不连接实盘或修改交易所订单。

## 周期与指标

没有自定义时段时，20 分钟决策频率仍在 `:00 / :20 / :40` 运行。默认周期为 `15m / 1h / 4h / 1d / 1w`；已有显式设置不被覆盖，30m、1M仍可选。`1w` 是交易所锚定周线，不是滚动7日。

### 自定义运行时段

在后台编辑 REAL / STRATEGY 任务，打开「调度设置」，可设置默认间隔并添加最多 20 条 `run_schedule` 规则。每条规则包含名称、星期（周一为 0）、时区、开始/结束时间和间隔分钟数（15–1440）。上面的规则优先；未匹配时使用默认间隔，按应用 `TIMEZONE` 当天零点对齐。已有任务不添加规则便保持原有行为，SPOT_DCA 继续使用原来的定投日程。

预设会替换编辑器中的规则，并将默认间隔设为 30 分钟，保存任务后还需点击页面上的「保存配置」生效：

| 优先级 | 时段 | 间隔 |
| --- | --- | --- |
| 1 | 北京时间周六、周日 00:00–24:00 | 30 分钟 |
| 2 | 纽约时间周一至周五 09:30–16:00 | 20 分钟 |
| 3 | 北京时间周一至周五 08:00–16:00 | 30 分钟 |

纽约时段只是可编辑的美盘参考窗口，自动处理夏令时。北京时间周末优先，因此纽约周五下午进入北京时间周六后，改用周末间隔。

时段包含开始、不包含结束，从开始时间计算间隔；例如 09:30 起每 20 分钟在 09:30、09:50、10:10……运行。开始晚于结束表示跨午夜，例如周五 22:00–02:00 覆盖到周六凌晨；全天填 00:00–24:00。切换规则时重新按新规则的开始时间对齐，所以相邻两次执行可能短于设置的间隔。这是时间槽调度，不是“上一轮结束后再等待 N 分钟”；运行中的同一任务仍不会并发重入，离线错过的分析时间槽不会批量补跑。Prompt 中的下次运行时间使用同一规则计算。

降低决策频率只减少 Agent 分析调用，已有止盈止损保护仍独立扫描。修改代码部署后需重启后端及调度器；保存任务规则本身沿用现有配置刷新机制。

Dashboard 的 K 线刷新保留画布实例和浏览范围；切换交易对或 K 线周期时重置范围，主题和尺寸变化不重新创建图表。浏览器回归测试使用独立模拟页面：先运行 `npm run dev --prefix frontend -- --port 5179`，再运行 `uv run --with playwright python tests/browser_dashboard.py`（需已安装 Edge），不调用真实交易接口。

| 周期 | 作用 |
| --- | --- |
| 15m | 入场位置、近期波动与交易触发 |
| 1h | 交易条件、支撑阻力和失效 |
| 4h | 趋势/震荡环境 |
| 1d、1w | 背景和更大级别风险，不重复展示10根K线 |

指标仅使用已收盘K线，输入注明最后收盘时间、排除的未收盘K线、数据年龄与EMA预热不足。当前报价与指标收盘价可能不同，不能把这种差异当作数据错误。短期样本不足的EMA/RSI/布林/MACD明确缺失，不用0伪装有效指标。

- EMA 保留20/50/100/200，不优化拟合近期盈亏；注明预热不足。
- 布林采用20周期、2倍总体标准差，增加 `%B` 和最近120根带宽分位。触轨不自动代表反转。
- VWAP 统一按UTC日内重置，以K线典型价近似，注明锚点；不同周期的典型价近似仍可能不同。
- SMC 摆动点要等右侧K线确认后才参与结构事件；结构和区域带年龄、时间及ATR距离。OB去重，展示优先选附近区域，超过6ATR的区域不挤占短线提示。
- IFVG 要求收盘突破缺口边界，反向再次失效后排除，不把一次影线填补自动算作有效反向缺口。
- Volume Profile 明示统计窗口及OHLCV分配近似，不能叫做真实持有人筹码成本。
- 多空比注明人群/周期；OI单点没有变化率和合约单位换算时不能单独作为方向依据。

这些改动提高执行与证据一致性，不代表已经证明策略具有正期望。测试使用隔离数据库、模拟交易所，以及安装版本CCXT的真实请求构造器；没有用真实账户开单验证。部署需重启后端/调度器以加载代码并自动创建新表。
## 加仓与 7 天周期补充

保护撤单后在同一次调用中进行有界状态确认（最多约 4.75 秒退避），兼容撤单响应丢失与查询延迟。未确认时保留撤单意图，维护任务继续查询；15 秒后仍查询到未结束订单时才允许再次撤单，不要求模型重复提交整套保护。超过等待窗口仍无法核验会如实报告未完成。

每轮记忆的字数与输出结构由配置的短期记忆 prompt 决定，输入内容仅包含时间、旧记忆、新策略、工具结果及成交事实，不再额外嵌入冲突的 600 字固定结构要求。

实盘同方向仓位共享 TP/SL：加仓省略参数继承，提供单项则更新该项整仓保护，另一项保留；更改保护必须核验后才增加委托。Dashboard 留空表示保留，取消必须显式选择。调整时校验保护版本，失败不提示已生效。

成交账本按账户/品种/方向的归零边界重建周期，保留加仓、部分退出、混合退出原因和保护版本；外部退出不凭价格推断 TP/SL，未知入场或混合归属周期不计入策略战绩。周期唯一 ID 来自首笔成交，避免同一个保护计划跨周期导致覆盖。7 天周期与 7 天成交活动分别统计。

数据库诊断、清理边界和同步副本实际发现见 [核查说明](DB_AUDIT_2026-09-08.md)。


### LLM 断线重试与数据刷新

- 后台 `llm_timeout_seconds` 是每次请求的客户端超时（秒），首次请求和重试使用同一设置；`llm_max_retries` 是每个模型的额外重试次数。SDK 内部重试关闭，由应用统一重试。
- `Server disconnected without sending a response` 表示上游服务或中间网关已经断开连接。即使客户端设置 1200 秒，上游也可能在约 340 秒提前断开；增加客户端超时不能覆盖上游连接限制。连接失败后仍采用短暂退避（1、2、4 秒），超时值不代表重试间隔。
- 主决策模型、小模型每次重试，以及切换兜底模型前，重新获取配置周期的 K 线并计算指标，刷新余额、持仓、挂单和提示词时间。新闻沿用新闻模块自身缓存策略。
- 新快照替换旧提示词，保留已完成的工具调用与返回记录。失败流的部分回答不进入下一次请求，也不会由重试逻辑重新执行交易工具。
- 刷新缺少周期、K 线被标记过期、账户查询失败或提示词刷新异常时，中止本轮决策；不使用旧快照继续请求兜底模型。
- 日志记录每次请求的配置超时、实际尝试耗时和底层错误类型。部署后查看 `configured_timeout=1200s`，可确认运行进程加载的配置。
