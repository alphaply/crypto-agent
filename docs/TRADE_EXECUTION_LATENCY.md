# 工具执行耗时与精简结果

## 现场证据

2026-10-17 北京时间，ETH 调用 15:01:41.821 开始，15:16:24.874 才创建下单记录，15:16:27.160 发出下单，15:16:27.238 取得成功回执，15:16:31.501 返回。工具耗时约 889.68 秒，交易所下单请求约 78 毫秒。现场有 5,147 条历史计划事件，67,293,929 字节。

历史归属整理原来由 ledger 初始化触发，每页限制不限制一次调用的总工作；来源变化又会使全量暂存失效。管理入口持有账户锁时进入历史处理，计划保存也同步重建收益历史。现有日志不能精确区分本次各阶段耗时；事后数据库无锁等待，不足以证明故障期间无竞争或断言死锁。

## 本次处理边界

金融调用只处理当前动作的必要事实、权限、预留和写入。交易所接受指令，保存原操作及订单身份后返回提交成功，不再为了确认提交而 GET 订单、等待成交或跑全量历史。

正常后台成交、持仓和收益更新保留。成功提交不等于成交；后续读取失败不改写提交成功。同一原操作重放不会再下单，未知结果仍沿原身份恢复，不把网络超时当明确失败。

前端交易工具逐项直接显示操作、标的、方向、委托数量、价格和成功／失败，不显示原始 JSON、核验树、审计入口或重复数量。字段缺失不编造；未决结果不硬标成失败。一般查询工具和既有授权审计 API 保留。

## 后台索引与恢复

升级需执行 migration `0009_incremental_ownership_work.sql`。它在原来源事务内维护 `ownership_sources`，用每个来源的版本捕捉新增、更新、删除与作用域移动，包含较小 ID 晚提交的情况；原始数据不删除。旧索引暂存只在首次转换成增量模式时重新初始化。

`ExecutionLedger` 构造只读轻量检查点。后台通过 `index_saved_plans()` 显式推进，单次同时遵守 `RUNTIME_SCAN_BATCH_SIZE`（默认 32）、`RUNTIME_INDEX_SCAN_SECONDS`（默认 0.25 秒）及 4 MiB 投影读取预算。时间片在原子工作之间检查；单条数据库操作保留独立的数据库请求超时，不把即将耗尽的 0.25 秒时间片当作 SQL 超时。来源采集后，在分页条数允许时至少尝试一次发布，防止扫描耗尽时间片后永久停留在来源阶段；仍有待处理来源时继续阻止发布。不是操作系统实时截止保证。相同归属投影只发布一次，已完成来源保留紧凑版本记录，源变化不触发全历史重扫。

索引与金融锁分离，索引工作权争用时退出，下一次调度继续。当前计划保存把受影响收益范围写入 `execution_history_work`，重复工作合并；后台保存成功且版本仍相符才清除。平仓重建先借助事务内同步维护的来源投影筛选同一持仓阶段，再流式读取历史保护记录；无法投影的原始记录仍按原路径校验，大记录仍完整读取。收益重建失败保留原结果和待处理工作。应用重启继续已有进度，无需清理原始历史或重发交易。

回退应用时保留新增表和原身份，切勿删除订单、成交或未决证据；旧应用可能恢复原延迟。Web 和 scheduler 必须使用兼容镜像。镜像发布与生产更新是两个动作。

## 隔离验收 profile

本 profile 在正式组合验收前固定，使用本机 Docker PostgreSQL 17、一次性 `latency_test` 数据库内的独立测试 schema、合成账户及假的交易所，绝不使用生产账户或原服务器凭据。

- 数据：不少于 5,147 条、67 MB 原始历史，含重复快照及当前订单；新事件、旧行修改/删除、跨符号移动、晚提交、重启和双工作者争用。
- 索引：测试批次 128、预算 0.2 秒；单次处理计数不得超 128，观测单片小于 2 秒（包含本机 Docker I/O）。测试固定断言增量新增的 SQL 小于 100 次、无变化推进小于 15 次；必要来源最终全部覆盖。
- 前台：可控闸门阻塞后台历史时，前台必须先于闸门释放完成合法动作；无全历史调用、无 ACK 后确认 GET、无重复写入。假交易所无外部延迟时观测调用小于 5 秒；真正金融互斥的等待预算不因本测试放宽。
- 资源：单次客户端历史投影读取不超过 4 MiB，不开额外无界线程；后台与金融使用既有容量调度。现场 RSS/线上响应时间不由本机结果推断。
- 回归：真实隔离 PostgreSQL 下验证账本、共享管理、固定数量退出、原身份恢复及 ACK 行为；前端测试、构建和中英文桌面/窄屏检查。

分段日志使用 `execution_stage`，区分 `financial_lock_wait`、`current_observation`、`exchange_submit`、`financial_callback`、`ack_persist`、`tool_return`、`history_index` 和 `history_rebuild`。记录 monotonic 耗时与结果，不打印凭据或完整回执。

实际测量、测试结果和发布阶段由本变更的 verification 记录补充；本 profile 不代表生产已上线。
