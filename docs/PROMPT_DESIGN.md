# 交易 Prompt 设计

当前流程（2026-10-09）为决策模型与工具调用 → 策略摘要 → 短期记忆更新。决策结束后，由配置的摘要模型按策略 Prompt 生成纯文本摘要；原文、推理、工具参数和真实回执独立保存，不由摘要替换。随后将本轮及前 4h 摘要、工具回执和当前短期记忆交给记忆模型更新。

Prompt 长度减少不代表总调用费用或交易亏损会按相同比例下降；实际费用还取决于模型、调用频率、工具返回内容及推理和输出长度。

## 精简范围

- 压缩内置合约和现货模板，保留决策所需的账户、持仓、挂单、市场和记忆上下文。
- 决策模型按任务 Prompt 输出；摘要模型只归纳完整决策和工具执行证据，不强制填充报告字段或生成预测。工具回执不能用模型文字替代。
- 现货运行时去除重复的持仓和操作方法说明；现货仍以该模式实际可用工具为准。
- 退出上下文只标明当前 `exit_mode`，不重复教授工具参数。
- 管理页新建自定义 Prompt 的示例尾部同步缩短，去掉每轮规则复盘指令。
- 默认决策带最新市场与账户，不再读取和拼接七天日报。REAL/STRATEGY 独立退出模式使用当前交易状态与策略投影（见下）；其他模式继续读取完整短期记忆和最近三轮策略摘要。
- `finalize` 将完整决策与工具执行回执交给摘要模型，结合配置的策略 Prompt 输出纯文本 `strategy_logic`。摘要连接字段优先级为任务专属、全局摘要配置、任务交易模型；reasoning、兼容模式和提示词角色配置保留。
- 已删除报告 schema、强制报告工具和格式纠正模型调用。摘要只校验非空及响应完整性，失败保存完整原始证据并跳过本轮记忆更新；记忆失败独立重试，不重放交易。

内置篇幅指引采用软目标：策略摘要100–200字、最多4条短句；短期记忆300–500字、最多6条短项。指引也附加到已有自定义模板，显式字数偏好保留。通过合并重复、替换过时状态和省略逐笔账本实现压缩，不限制或裁切输入、模型输出；必要风险条件可以超出目标。`finish_reason=length` 表示服务商输出预算用尽，推理模型的预算可能同时用于思考；可在调用详情检查停止原因、输出/推理配置与用量，再调整摘要渠道的 `extra_body` 输出额度或推理配置（字段取决于服务商），应用不会自动增加额度或改变推理模式。

Markdown 保留单个 `~` 价格区间（如 `2500~2507`），双 `~~` 按正常删除线显示；不删除数字之间的分隔符。

## 记忆与规则

交易 Agent 与绑定任务聊天不再注入长期规则，工具注册及执行入口均禁止 `manage_trading_rules`。在旧自定义 Prompt 中要求交易模型修改规则也不会得到该权限。交易工具继续负责订单归属、数量、价格、方向、保护状态及执行结果校验。

短期记忆模型仅维护动态 memory，不提供规则工具，不查询或改写规则。每轮策略摘要成功保存后入队，输入本轮及前 4h 摘要、完整旧记忆和实际执行证据，正常一次模型调用生成新记忆。同任务串行处理，成功结果按 operation_id 复用。手动整理默认使用 4h 滚动窗口，旧整点四小时批处理不再自动触发。

应用不再用固定字符数裁切旧记忆、决策、执行回执、来源证据或模型输出。策略模型按配置 Prompt 做语义压缩；自定义字数偏好作为模型指令保留，返回的完整正文不会再被程序切片。4h 整理保留窗口内全部已保存策略摘要；最近三轮与七天成交窗口定义时间/记录选择范围，其中每条正文和已读取成交、周期及观察记录保持完整。聊天滚动记忆同样传入完整原始消息和旧记忆，完整保存有效输出；`CHAT_CONTEXT_SUMMARY_MAX_CHARS` 仅兼容为触发整理的阈值。只有成功整理且记录覆盖游标的旧消息才由滚动记忆替代；未覆盖消息保留完整正文。

模型仍有自身上下文和输出上限；若服务商明确返回 `length`、`max_tokens` 或其他不完整状态，记忆更新失败并保留旧记忆，不能把半段文字当作成功结果。单轮策略压缩失败时记录失败调用，并以 `【策略压缩失败；以下为未压缩原始记录】` 明确标注完整源记录回退。读取最近策略、窗口整理和日报时，已有模型策略摘要原样使用，不追加或替换为长篇原始分析；只有明确的旧版 `【决策摘录】` 硬截断记录或空策略记录，才使用同轮 `summaries.content` 恢复已有来源，保留执行记录并标明旧回执缺失或已截断。恢复只作用于读取结果，不改写历史行。历史已经截掉且没有完整来源的内容无法凭空恢复。数据库、记忆 API、导出和展开查看保留完整正文。

非独立模式的记忆输出仅要求 {"summary":"最新短期动态记忆"}，不再生成规则结论、修改理由或程序回执尾段。即使旧自定义 Prompt 返回 rule_review/reason，也只读取 summary；如果返回工具调用则拒绝，不执行、不继续工具循环。独立模式在同一次调用中额外生成策略投影，原文 summary 仍完整保存。既有规则记录和人工管理能力保留，自动规则维护暂停。

每次记忆请求只选择一种程序输出契约。独立模式必须输出 `summary`、`memory`、`projections`：summary 为完整记忆原文，memory 为新记忆的纯策略内容，projections 逐一对应本次提供的待转换来源 ID/hash；没有待转换来源时明确返回 `projections: []`，仍必须提供 memory。内置指令不再同时要求单 summary 与完整投影两种格式。自定义 inline/file 模板和历史正文完整保留为素材，其旧 JSON 示例不能覆盖程序契约；字面 JSON 花括号不阻止 `{content}` 注入，user 角色兼容模式在素材结束后重申相同契约。

独立模式在完整、无工具调用响应的 JSON 或字段结构校验失败后，可启动一次格式纠正阶段。如果结构、来源身份/哈希、覆盖和引用均有效，但 strategy_text 混入执行限制或解锁结论，则可启动内容分离纠正：要求模型重新输出完整对象，把执行叙述放入 unlinked_execution_notes，可信身份放入 execution_refs，保留策略条件及完整 summary。格式与内容纠正共享至多一次纠正阶段，原请求、纠正请求及传输重试合计最多三次实际模型请求；正常成功仍为一次。只传入可信错误类别和字段路径，沿用原来源快照。截断、拒绝、工具调用、伪造来源/引用、遗漏来源及额外权限字段直接拒绝；纠正结果仍须通过完整校验，不由程序删句、补空策略或宣布交易获准。每次请求独立保存阶段、序号、原始输出、失败原因与已返回用量，首次失败不因随后成功而改写为成功。

模型调用失败、空输出、不完整响应或无效记忆不覆盖旧记忆。自动队列每个任务最多尝试 3 次，失败后分别等待至少 60 秒、300 秒，第三次失败标为 failed，不再自动重试；每次整理按渠道配置处理有限传输重试，独立模式可增加上述一次纠正阶段，两者共享最多 3 次模型请求。成功生成与存储使用稳定 operation_id，存储重试不重复付费生成。旧 partial 记录及规则回执保留兼容，不自动重放。记忆与策略摘要跟随 LangSmith 主开关，不再被 langchain_background_tracing 屏蔽；输出校验失败在父运行标记 error，保留响应及停止原因、推理用量和显式请求参数，本地调用和费用同样记录。队列错误保留原始失败原因。

Daily memory 不再自动生成或注入交易和聊天上下文；历史数据库记录保留，旧日报接口只用于兼容既有数据。记忆更新失败保留旧记忆，持久队列只重试整理任务，不重新执行交易。已产生规则工具回执但最终记忆失败的 `partial` 结果不自动重试规则写入。

## 共享消息上下文

消息源配置由所有任务、聊天及 MCP 共享，默认每 1h 更新，回看 24h，最多取 80 条候选、保留相关度最高的 20 条。保留原有加密新闻、宏观日历、政策、地缘消息和 Polymarket 配置，律动使用官方 JSON API（API Key 在消息聚合页配置），Binance 使用官方签名公告流。Binance 流使用后台选择的 Binance 账户访问公告，未配置或连接失败在来源状态中展示。

相关度支持 TypeSafe 官方 Jev System One API（`/v1/systemone`）及 B.AI Decisions API（`/v1/decisions`），由渠道的 `decisions_api` 选择，独立于聊天模型；旧渠道默认保留 B.AI。默认五档评分映射为 0–100，阈值 60。后台可编辑评分说明和 2–10 档标准。评分缓存包含正文、模型渠道、接口类型和评分标准，变更后失效。Jev 只评分，筛选后由单独配置的生成模型写统一摘要。读取共享摘要不会重新抓取、打分或调用摘要模型。

分数和概率保留原始值，用概率加权期望进行一致性校验，并根据返回数字的小数精度计算允许舍入区间。超出区间仍记为评分失败，管理员可查看分数、概率、加权结果和校验诊断；公开快照仅包含评分公开字段。配置 LangSmith 时记录整轮及各阶段、每条评分的追踪；追踪写入失败不改变业务结果。消息聚合页另有持久化阶段进度、统计图表和最近 20 轮历史。

消息更新成功后原子发布快照；所有来源或评分失败、摘要失败均保留上一份快照并标记过期。首次尚未生成时明确显示等待，关闭管道后不向任务继续注入旧消息。新闻正文按外部资料处理，不具有修改指令、风控或工具权限的效力。

## 查看实际输入与成本

后台 `/console/config` 的「Agent 运行」需要登录，可筛选交易决策（`decision`）、报告整理（`strategy_summary`）、记忆复盘（`memory_review`）、聊天（`chat`）、聊天压缩（`chat_summary`）、消息评分（`news_score`）和消息摘要（`news_summary`）；`daily_summary` 仅为旧用途兼容。查看实际模型渠道、消息及角色、工具 schema、完整输出、状态和已返回的 token 数。查看记录不会重新抓行情、重跑模型或执行工具。

原始记录从功能上线后的调用开始，不补造旧 Prompt；每任务保留最近 100 次，最长 30 天。累计记账独立保存在 `durable_usage`，清理原始详情不删除累计统计。调用开始保存渠道与模型费率快照，结束按返回的输入、输出、缓存读取和写入 token 估算，避免缓存和推理 token 重复计费；服务商返回费用优先。缺失用量或必要价格保持未知，明确的 0 才表示免费，不同币种分别汇总，后续改价不回算旧调用。旧 `token_usage` 仅导入一次并标记历史估算，不补造渠道信息。

模型渠道默认手动价格，可选择按明确的 models.dev 渠道和模型映射同步。自动同步默认 6h，目录缓存 1h；未匹配、网络失败均保留已有自动价格，手动模式不被同步覆盖。同名模型的不同渠道分别存价。用量页按渠道、模型、任务和用途汇总，并显示未计价调用。估算仍可能与服务商实际账单不同。

## 模板与升级

内置合约模板和 `backend/agent/prompts/real.txt`、`strategy.txt` 保持一致。任务配置的自定义正文继续保留；升级不得用仓库默认文件覆盖数据卷中的自定义 Prompt。删除的“决策与复盘要求”也不再被运行时追加到自定义正文。

任务编辑器可选择“内置默认（随版本更新）”，以空 `prompt_file` 使用当前交易模式的最新内置模板。已有任务继续使用原选择；若要用这次完整的新正文，需要切换该选项并保存，或自行将新正文合并到原自定义文件。

`{short_memory_text}` 和 `{recent_summaries_text}` 继续提供默认决策上下文，缺失区块按既有兼容机制补充。旧 `{history_text}` 渲染为空；旧模板中的 `## Daily Memory` / 每日记忆章节，以及仅含该占位符的标题区块，在生成 Prompt 时移除，不改写自定义源文件。部署后须重启后端与独立调度器，加载新的角色权限、共享服务和记录功能。

### 记忆代码职责

- `backend/agent/decision_context.py`：读取动态 memory/近三轮策略摘要的适用视图，清理退役模板区块，统一渲染并补齐缺失上下文。交易和绑定任务聊天共用此路径。
- `backend/agent/context_projections.py`：来源哈希、纯策略投影、执行引用解析、后台转换与重试；不执行交易。
- `backend/utils/trade_context.py`：本地证据加载、当前交易状态纯投影及渲染；不调用交易所或模型，不提供第二套准入判断。
- `backend/agent/memory_service.py`：组织成交证据、复用已完成整理结果、校验租约并保存 memory；手动整理使用滚动窗口。
- `backend/agent/memory_updates.py`：逐轮持久队列、串行调度及有界重试，不依赖交易图。
- `backend/agent/memory_agent.py`：无工具的记忆模型调用，处理模型配置、审计、输出验证及有界格式纠正。
- `backend/agent/memory_contract_recovery.py`：输出契约修订及旧缺字段失败的定向重新排队，不调用模型或交易工具。

已删除日报生成、旧固定四小时调度及补跑、同步逐轮写入等未使用路径。历史日报数据及读写/导出接口保留用于归档，生成接口继续返回 410；旧日报 Prompt 配置不再作为有效模型入口或文件引用校验。`AgentState` 不再携带永远为空的 `history_context`。

交易决策不再注入长期规则、固定小时级策略指令或 `exit_mode` 提示。旧 `{trading_rules_text}` 和已知长期规则/小时策略章节在渲染时清理，不改写自定义源文件。开仓 TP/SL 必填、可选及独立退出的区别由按配置生成的工具参数和说明表达；原始运行时校验继续生效。

### 独立退出模式的当前状态与策略投影

默认决策状态由账户快照和同账户、标的的执行证据组成：当前持仓、按通道/当前 ID 去重的有效订单、
SL 未覆盖估计、固定数量冲突，以及影响本轮的缺项。历史回执字典和聊天的重复核验段落不再自动注入。
本轮完整 ToolMessage 继续传给调用者；显式 `get_trade_operation` / MCP `get_operation` 和历史页面保留原始回执。
绑定聊天每个新用户回合使用同一状态构建器，同回合的新工具事实保留在启动快照之后。

正常输入使用确定性文本和表格（完整三单夹具、观察时间和体积比较见 [精简样例](DECISION_CONTEXT_EXAMPLE.md)）：

```text
持仓：多仓 0.07｜均价 2415｜浮盈约 +7.93 USDT｜本任务
当前挂单（数量单位：标的币）
ID | 用途 | 数量 | 价格 | 状态
algo:1000002617965160 | 多仓止盈市价 | 0.07 | 触发 2545 | 待触发
algo:1000002618311010 | 多仓止损市价 | 0.07 | 触发 2357 | 待触发
regular:8389766294627213395 | 多仓限价入场 | 0.1 | 限价 2385 | 挂单中
止损未覆盖估计：多仓 0；空仓 0
当前相关执行异常：无（当前数据源读取完整）。
策略背景：等四小时收盘确认前不加仓。
```

异常输入只增加相关缺项，例如 `SHORT / algo:old-A / fill_unverified`，说明撤单终态的执行量仍缺失，
影响同方向数量或清理依赖；One-way 标明共享净仓影响。已确认的平仓事实不因清理未完被改写成未成交。
结构化数据中的 `null` 显示为“未知”，不补零；读取失败不会显示“无异常”。旧错误文字、旧允许/禁止建议不能代替当前执行证据。
完整订单 ID、精确数量/价格、触发价与限价、all/fixed、父子单关联及异常归属保留；重复快照字段与 client_id 不常规展开（缺订单 ID 时保留 client 身份）。来源观察时间按交易所快照/本地核验集中展示，差异保留，未知时间不伪造。格式化不调用模型。

记忆整理的两条入口均传递可信 config/symbol，按原操作身份读取最新结果；引用不受4h窗口或最近20条限制。
原始结果和最新证据分别传入实际记忆消费者，不仅用于页面 `current_receipt`。同身份最新结果优先，
批次子项按保存的 index 关联，not_executed 保持未执行，不能用0.30或新账户的空仓解决原0.37事件。

`decision_context_projections` 保存版本、来源种类/ID/内容哈希、strategy_text、execution_refs、
unlinked_execution_notes 及处理状态。模型仅分离策略背景和执行陈述；执行引用必须来自可信工具链，
不能添加权限、跨任务来源或伪造身份。原始 memory 和 strategy_logic 不就地清洗。
决策每次纯读取同任务/账户/标的、ready 且哈希匹配的已发布策略文字，并独立重新解析执行引用；真实已解决的问题无需等待模型重新整理。短期记忆、摘要及执行证据各自降级，单项失败不清空其他有效正文。
“等四小时收盘前不加仓”保留为策略条件，“旧 unknown 所以禁止加仓”不进入策略文字。

正常一次 memory_review 同时生成新记忆及近期来源投影，元数据随幂等结果和调用审计保存。
缺少投影时由现有 worker/租约批量转换最新记忆和最近三轮；没有新交易摘要也能处理。
新来源排队、失败、重试和重启期间，默认输入保留最新有效已发布记忆与最近三条已发布摘要，按来源时间选择并注明截至时间，标题为“近期已发布策略摘要（最多三条；历史计划，不是成交证明）”。没有可用版本时才显示一行“尚无已发布…”，不逐来源注入整理占位符，不回退旧混合正文。来源仍存在且 hash 匹配的较早任务完成后可发布，但不能顶替更晚来源。
转换采用版本/哈希幂等与最多3次任务尝试、60/300秒退避；人工原地编辑改变哈希后由 worker 重新排队。新记忆原文和策略视图原子提交；事务内先重新核验来源哈希及当前范围，失败回滚并可复用已保存模型结果。

输出契约修订独立于已发布视图版本，升级不使 ready 内容失效。后台 tick 在同任务租约内，仅将旧修订、明确的 `ProjectionReview` 缺字段终止失败重排一次，同时保留旧错误/尝试次数。投影必须仍有同范围、同哈希原文；记忆生成任务必须仍有有效摘要和可信账户关联（旧任务无关联元数据时，使用旧修订的同哈希投影佐证，无法确认则不恢复）。无关错误、completed/partial、新修订失败及已失效来源不自动复活。同修订再次耗尽三次工作尝试后保持 failed，不因重启无限恢复。

“无原文”“有原文未发布”“整理失败”需分别诊断；管理状态的 `not_generated` 指已有有效来源尚无投影，不等于没有短期记忆原文。现有管理投影重试只重排有效 failed 投影，不能重新生成不存在的原文；本次针对性后台恢复才会重新整理符合条件的旧失败生成任务。只有摘要且没有可恢复生成任务时可先发布摘要，短期记忆保持真实缺失状态。状态、恢复诊断及错误不进入策略正文，字段说明和上线核对见 [工作台说明](WORKBENCH.md#决策摘要和记忆)。
