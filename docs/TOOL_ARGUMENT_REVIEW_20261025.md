# 交易工具参数检查（2026-10-25）

这次检查针对模型把 `action` 写成 `action_type`，以及使用 `edit` 时缺少 `order_id` 的两类报错。它们在旧代码中会被拒绝，但模型实际看到的工具说明没有充分强调字段名称、订单身份来源和改单字段含义。

## 修正

- 内置 Agent、Chat 和 MCP 使用同一份参数说明，明确版本为整数 `3`，动作字段平铺，改单和撤单必须引用当前真实订单 ID，保留查询或回执中的前缀。`operation_id` 是请求身份，不能代替订单 ID。
- 模型实际绑定的参数结构补充 `action`、`order_id`、`reason` 和改单价格字段的说明，并提供改单格式示例；示例中的订单占位符必须替换为真实查询结果。
- v2/v3 动作在分派前识别这两类错误，返回包含动作索引和修正方法的参数错误。仍然拒绝错误输入，不自动把 `action_type` 改名，不猜测订单 ID，不替换交易动作。
- 有效请求的默认字段、序列化和请求身份不变，模式支持范围与交易执行规则不变。清理现货下单函数中已经失效的局部 `ccxt` 导入与 `writing` 变量。
- 更新 MCP 与 QQBot 接入文档。升级后客户端需要重新连接、刷新工具列表，避免继续使用缓存的旧说明。

## 验证

在隔离的 PostgreSQL 17 数据库上，交易工具、MCP 目录、v2/v3 合约、请求重放与恢复等相关回归共 **241 项通过**。新增回归检查实际 Agent 工具消息、实盘/Paper MCP 调用入口和转换后交给模型的 schema；错误批次不触发订单执行，正确请求保留真实订单身份。

扩大回归发现两项历史测试与当前代码不符，在修改前的 `fefcba6` 中也分别复现：

1. 现货超时测试仍要求保留未知状态预算锁，与已归档的 `2026-10-19-simplify-spot-budget-and-management` 需求冲突。测试更新为验证当前失败回执、预算释放以及相同请求不会重复下单，没有恢复旧业务规则。
2. 入场准入测试替换了包含实际准入检查的执行服务，使检查被绕过。测试保留真实开仓服务，只替换离线交易所与准入结果，验证先前撤单保留、后续开仓被拒绝且没有交易所写入。

上述检查使用离线交易所，不发送真实订单，也没有测量真实模型调用的错误率。说明更清楚可以减少填错，但不能保证模型永远生成正确参数；缺少必要字段时仍会拒绝执行。
