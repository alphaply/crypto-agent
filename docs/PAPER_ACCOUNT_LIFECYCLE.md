# Paper 账户与共享管理

## 银行、转账和破产

后台统一配置借款开关、额度和日利率（0.01 表示每天 1%）。按未还本金单利计息，借还款、调息按实际持续时间分段；北京时间每日 00:00 结算上一日利息。调息不追改已产生利息，首次升级不补造历史利息。后台维护扫描无持仓、有负债及破产账户；重启后补结未结算时段，同一周期同一日界只扣一次。

扣息是否触发破产按账本实际现金判断，不先减去挂单占用。例如实际现金 100U、挂单占用 95U、利息 10U，扣息后现金为 90U，不会仅因可用现金不足而破产；订单后续仍按原有资金检查执行。实际现金不足时仍完整扣息，例如 3U 扣 10U 后为 -7U，并进入破产状态；即使还有持仓，也不能因加载账户或收款自动解冻。无持仓后的原有净权益破产判定保持不变；不完整估值不会当作零。破产后不能开平仓、撤改单、设置保护、借还款或转出，已有订单不成交。仍可查询、接收转账并继续计息。收款不自动解除破产。

历史上若仅因挂单占用被误判为破产，系统会核对本轮完整扣息记录：当时实际现金没有扣成负数、只是低于仍保留的挂单占用，没有其他明确破产原因，且当前现金非负、可核验净权益为正时，恢复正常状态。恢复只纠正错误冻结，保留现金、债务、已付利息、持仓、挂单、账户周期和下海次数，并留下恢复记录，不需要下海重置。存在真实现金不足的扣息记录，或账户周期、历史证据不完整时，不按挂单误判恢复；原有持仓误判恢复也排除真实欠息破产，后来收款不能抹除真实欠息事实。

下单前及交易回报会提醒有计息负担的账户留出未占用 USDT 现金付息，开仓、入场挂单及入场改单均适用。提醒按后台实际日利率和结算时间估算，完整一天利息与下次扣息分别展示；首日按实际时长折算，已还清本金但仍有累计未结利息也会提醒。提醒里的可用现金扣除挂单占用，仓位保证金不当作现金。该口径用于安排资金，不改变上面的扣息破产判定；不会强制冻结预留资金、拒绝订单或擅自缩减用户指定数量。

`paper_transfer(user_id, recipient_user_id, amount, operation_id)` 支持同 namespace 已开户用户和 bot 账户双向转 USDT，借来的可用现金也可转。收款使用稳定身份，付款身份来自可信授权。金额必须是正有限数且最多八位小数；零、负数、布尔值、非有限数及超过可用现金均拒绝。可用金额扣除挂单预留；两个账户、转账事件和回执在同一事务提交。重试沿用原 operation_id，不重复扣收，不能改变金额或收款人后复用 ID。

转账回执给出完整付款与收款身份、USDT 金额、转后可用现金及挂单占用，有计息负担时附带付息提醒。转账等待期间付款账户若已下海重置，旧请求不能动用新周期资金；已完成转账的重试仍返回原回执。

## 已有仓位调整与挂单维护

`configure_paper_account(action="update", leverage=...)` 只修改后续入场的默认杠杆。已有 Paper 合约逐仓仓位使用独立工具 `adjust_paper_position`，从当前 `get_account_state(include=["positions"])` 取 `resource_id` 作为 `position_id`，同时传可信 `user_id` 与稳定 `operation_id`。它不改变现货或真实账户，也不放入交易批次。

`action="set_leverage"` 只传新的整数 `leverage`。仓位数量和开仓价不变，基础保证金按「开仓价 × 数量 ÷ 新杠杆」重算，差额在现金与该仓位保证金之间多退少补，手动追加保证金保留。`action="add_margin"` 或 `"reduce_margin"` 只传正数 USDT `amount`，分别从可用现金补入或从该仓位退回现金。调低杠杆或加保证金时，可用现金不足明确失败；释放保证金不能低于基础保证金或使仓位立即爆仓，不自动缩量。相同意图重试不重复划转，旧周期仓位身份不能操作新周期。

实际改变杠杆时，如同标的同方向仍有与新杠杆冲突的待成交 Binance 入场单，明确返回冲突订单 ID，要求先处理这些挂单；系统不自动修改挂单。工具成功回执区分杠杆前后、保证金前后、额外保证金、现金变化和调整后可用现金，不把调仓资金说成新成交或盈利。破产冻结仍禁止这些金融调整；有计息负担时继续提示留出可用现金付息。

后台使用同场所的最新 ticker / 必要盘口撮合，限价检查买卖盘口，止盈止损检查实际采样价格。报价在等待账户锁或执行前超过 15 秒，已有挂单、OCO 和资金占用保持原状，等下一轮新报价，不因一次报价过期而撤销或拒绝原委托，也不使用过期报价强平。期间短暂触价后回撤不按历史 K 线补成交。

## 用户主动下海

仅破产用户本人主动说“下海”明确请求重置时，机器人调用 `configure_paper_account(action="reset")`。不主动邀请、不自动重置、不增加后台审批或重复确认，bot 自己不可下海。

重置终止旧挂单、清理持仓库存和预留，现金、负债、参数及本轮收益恢复后台当前开户配置，建立新账户周期。下海次数只增加一次且不限次数；旧交易、转账、利息与重置证据保留。旧订单、旧批次和旧操作重试不得使用新周期资金。

交易榜按本轮收益率排名，排除转账及重置补款，扣除手续费与利息；下海榜按累计次数排名。初始 10000U 亏光后重置，再赚 2000U，本轮显示 +20%。估值不完整或计分资本非正时不伪造收益率；公开榜沿用参赛偏好及账户隐私。

## 真实账户多连接共管

同一真实账户内已授权 MCP 连接和 Agent 可以管理相同资源及其他连接建立的订单，不要求先释放旧 owner。旧 visible_first_claim/exclusive_scope 的唯一管理者不再作为准入限制；原提交者保留为审计来源。账户、市场、交易对、read/trade/cancel、启停与聊天审批继续校验。Paper namespace/user 和 STRATEGY 账户继续隔离。

合约按真实持仓模式协调，现货按同一基础资产跨报价币共享库存和预留。提交阶段仍有跨进程协调、当前数量/版本校验及幂等保护。另一连接后续成功明确修改保护或订单后，旧 worker 不得恢复旧参数；未知原提交仍按原身份核验，不能换连接重发或自动续跑批次尾项。共管不公开另一 principal 的私有操作回执。

## 界面和升级

工具结果默认以简短卡片展示名称、状态与结果，失败/待确认原因直接可见；完整结果和已有审计按需展开。后台账户表显示破产状态、账户周期与下海次数，现金允许显示负数。

升级先运行仓库的显式 PostgreSQL 迁移（新增 0007、0008），再启动应用；应用不会临时建表。存在负现金或新周期后不要直接回退到旧解析逻辑，也不要删除 claims、预留、未知回执或新账户周期来解决问题。按既有备份和发布流程操作，镜像发布不代表重启生产。

QQBot 需要同步人格、skill 分发包及[自主交易定时任务提示](qqbot/自主交易定时任务.txt)到已有机器人任务。源文件与分发包更新不会自动修改外部已部署任务；验收时观察实际工具调用和本轮具体交易/观望依据，不承诺每轮必成交。
