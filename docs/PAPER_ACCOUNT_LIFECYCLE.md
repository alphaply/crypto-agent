# Paper 账户与共享管理

## 银行、转账和破产

后台统一配置借款开关、额度和日利率（0.01 表示每天 1%）。按未还本金单利计息，借还款、调息按实际持续时间分段；北京时间每日 00:00 结算上一日利息。调息不追改已产生利息，首次升级不补造历史利息。后台维护扫描无持仓、有负债及破产账户；重启后补结未结算时段，同一周期同一日界只扣一次。

现金不足也完整扣息，例如 3U 扣 10U 后为 -7U，并进入破产状态。完整估值确认净权益不大于零也会破产；不完整估值不会当作零。破产后不能开平仓、撤改单、设置保护、借还款或转出，已有订单不成交。仍可查询、接收转账并继续计息。收款不自动解除破产。

`paper_transfer(user_id, recipient_user_id, amount, operation_id)` 支持同 namespace 已开户用户和 bot 账户双向转 USDT，借来的可用现金也可转。收款使用稳定身份，付款身份来自可信授权。金额必须是正有限数且最多八位小数；零、负数、布尔值、非有限数及超过可用现金均拒绝。可用金额扣除挂单预留；两个账户、转账事件和回执在同一事务提交。重试沿用原 operation_id，不重复扣收，不能改变金额或收款人后复用 ID。

## 用户主动下海

仅破产用户本人主动说“下海”明确请求重置时，机器人调用 `configure_paper_account(action="reset")`。不主动邀请、不自动重置、不增加后台审批或重复确认，bot 自己不可下海。

重置终止旧挂单、清理持仓库存和预留，现金、负债、参数及本轮收益恢复后台当前开户配置，建立新账户周期。下海次数只增加一次且不限次数；旧交易、转账、利息与重置证据保留。旧订单、旧批次和旧操作重试不得使用新周期资金。

交易榜按本轮收益率排名，排除转账及重置补款，扣除手续费与利息；下海榜按累计次数排名。初始 10000U 亏光后重置，再赚 2000U，本轮显示 +20%。估值不完整或计分资本非正时不伪造收益率；公开榜沿用参赛偏好及账户隐私。

## 真实账户多连接共管

同一真实账户内已授权 MCP 连接和 Agent 可以管理相同资源及其他连接建立的订单，不要求先释放旧 owner。旧 visible_first_claim/exclusive_scope 的唯一管理者不再作为准入限制；原提交者保留为审计来源。账户、市场、交易对、read/trade/cancel、启停与聊天审批继续校验。Paper namespace/user 和 STRATEGY 账户继续隔离。

合约按真实持仓模式协调，现货按同一基础资产跨报价币共享库存和预留。提交阶段仍有跨进程协调、当前数量/版本校验及幂等保护。另一连接后续成功明确修改保护或订单后，旧 worker 不得恢复旧参数；未知原提交仍按原身份核验，不能换连接重发或自动续跑批次尾项。共管不公开另一 principal 的私有操作回执。

## 界面和升级

工具结果默认以简短卡片展示名称、状态与结果，失败/待确认原因直接可见；完整结果和已有审计按需展开。后台账户表显示破产状态、账户周期与下海次数，现金允许显示负数。

升级先运行仓库的显式 PostgreSQL 迁移（新增 0007、0008），再启动应用；应用不会临时建表。存在负现金或新周期后不要直接回退到旧解析逻辑，也不要删除 claims、预留、未知回执或新账户周期来解决问题。按既有备份和发布流程操作，镜像发布不代表重启生产。

QQBot 需要同步人格、skill 分发包及[自主交易定时任务提示](qqbot/自主交易定时任务.txt)到已有机器人任务。源文件与分发包更新不会自动修改外部已部署任务；验收时观察实际工具调用和本轮具体交易/观望依据，不承诺每轮必成交。
