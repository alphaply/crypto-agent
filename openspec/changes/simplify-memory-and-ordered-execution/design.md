# Design

## Context

动机及确认范围见 proposal.md。本变更横跨记忆生成、状态读取、金融执行和管理页面，需要同时处理旧契约兼容与并发边界。

已观察到的实现：
- `agent_graph.finalize_node` 在决策/工具执行结束后压缩策略，成功保存摘要时入队记忆更新。`memory_updates` 取本轮时间向前 4 小时窗口，手动整理在 `memory_service`。
- `memory_agent` 要求 JSON，独立模式还要求 memory/projections，并带格式和内容纠正。`context_projections`、`memory_contract_recovery` 将发布和旧契约修复耦合。当前两个历史证据格式函数返回空字符串。
- 旧版基线 `e600b5c` 的 `memory_service` 使用 `performance_context` 中的 7 天平仓记录，REAL 另有 `execution_ledger.recent_activity_summary` 的 168 小时成交证据。本次恢复这两个既有操作记录口径，不顺带恢复全历史权益统计，不扩为挂撤改单/失败请求全集。
- `tools_node`、`trade_batch`、`unified_trading.run_ordered_actions` 都已顺序执行。`PositionProtection._save` 检查 record_version；下单、发现管理状态、后台核验存在不同锁及写入路径。`run_once` 的兜底异常变成 unknown，部分适配器另有 TradeAttempt 阶段记录。
- `ExecutionLedger.sync` 在 ownership index 不完整时提前返回 `Ownership evidence indexing incomplete; exchange synchronization deferred`；`position_management._discover` 把不完整同步转为归属证据错误。因此不能把该错误当成交易所拒绝保护单的证据。
- `trade_summary` 虽限制字节量，仍保留嵌套结构、重复身份与内部核验字段。内部调用又使用结果计算停止状态，因此不能直接把底层回执替换成一句字符串。
- Paper 面板位于 `McpSettingsPanel` 内，依赖其 settings、刷新与 Key 弹窗；`AdminPage` 已有响应式配置 tabs。

提供的运行记录支持问题调查，但未取得足以锁定生产竞争写入者的证据，也不能据此认定重复成交。实现前需用隔离假交易所复现版本冲突的准确路径。

## Goals / Non-Goals

**Goals:** 让模型只负责压缩摘要和交易决策；执行器负责必要前置检查、顺序提交与简洁结果，后台负责后续核验。删掉仅服务于旧记忆 JSON 契约的代码，而非新增一套并行框架。

**Non-Goals:** 不改变交易策略、交易所、权限、数量和退出语义；不清空历史数据库，不增加新闻来源，不执行实际交易作为测试，不自动恢复未执行尾项。不在本次修改无关行情/新闻 Prompt 或整个项目架构。

## Decisions

### 1. 单一记忆输入与纯文本发布

自动和手动入口共享素材构造：4 小时压缩摘要、旧版 7 天成交/平仓记录、上一轮有效记忆。自动窗口以本轮已保存摘要时间为截至点，本轮恰好一次；手动沿用请求的整理截至点，使用同样 4 小时口径。7 天操作来源沿用原查询范围和时间口径，不用摘要条数代替时间窗口。保留记录实际时间与已知/未知区别；不新增跨账户或跨交易所回退。

模型一次正常调用输出完整文本；删除 JSON schema、来源哈希回传、内容“纯策略”正则拒绝与纠正调用。保留基本非空、完整响应、无工具调用检查，以及现有传输重试上限、费用审计、任务去重、租约和失败保留旧记忆。取消金融工具内的核验不改变记忆模型传输重试。

直接保存完整文本及程序生成的窗口/来源元数据。新内容不再依赖模型生成第二份投影才可读。近期策略摘要仍沿用既有最近三条的决策展示口径，直接读取有效压缩结果；它不同于记忆整理的 4 小时输入窗口。已有有效已发布内容继续可用，过时来源不能覆盖人工修改或较新记忆。

替代方案“只去掉最外层 JSON，继续让模型生成多份投影”不能减少主要复杂度，因此不采用。来源关联由程序保存，不将内部哈希交给模型复写。历史执行文字仅作为历史，当前权限/持仓事实继续由执行层给出。

### 2. 删除范围按消费者判断

退役 `memory_agent` 中的 JSON 解析/纠正和仅服务于它的 schema；移除生成新记忆所需的 projection 分支以及 `memory_contract_recovery` 的旧契约重排入口。`context_projections` 的历史读取和执行关联若仍被审计/当前状态使用，先将必要读取职责分离再删除生成链路。保留原始表和有效历史，不用删表完成代码清理。

移除或改写已失效测试与文案，特别是“只含纯策略”“前 4 小时维护规则”和 JSON 投影契约说明；保留失败不覆盖、范围隔离、原文完整性及人工编辑冲突测试。

### 3. 交易所接口结果直接返回，核验留在后台

保持串行循环、静态预检及每项提交前必要的权限、参数、目标、持仓和归属检查。取消工具调用内对本项提交结果追加 GET、轮询、sleep 等核验，包括超时后的补查；撤销原定每隔 1 秒最多 3 次的方案。下一项自身必要的前置检查仍保留，不以此前结果未知为由在本调用内启动恢复核验循环。

交易所有效受理响应返回“提交成功”，明确完成的撤单返回“撤单成功”；拒绝或接口异常返回“失败，原因：具体错误”。成功受理不代表已经成交。超时用“请求失败，原因：网络超时，提交结果未知，请勿重复提交”，不在前台等待确认。已成功受理不得因本地保存或维护异常改写成下单失败。

内部继续记录未提交、可能已提交和已受理阶段、原操作身份及幂等证据。后台核验保留；超时不能内部标记为确定未提交，也不能自动重发金融请求。默认失败停止尾项；显式 independent 对明确失败的原依赖策略保留，提交结果未知项停止本批。全部结果按原顺序汇总一次返回，成功项不回滚，未执行尾项不由后台补发。

### 4. 协调保护计划和归属同步写入

复用现有管理范围锁、账户锁及乐观版本检查，统一所有会更新同一计划的执行、发现和核验路径的锁顺序。版本检查继续作为跨进程防线。加载与持久化必须处于一致的协调范围；冲突后重读，不能把旧对象的版本号强行改成新值覆盖。

特别检查 `_discover`、`_save`、`recover_operation`、`management_action` 与前后置维护的嵌套调用，避免持锁期间调用另一路径更新同一计划却继续使用旧对象。用可控并发测试确定本次错误的可复现路径，不预设“第一笔一定撞第二笔”。仅凭错误字符串不能决定是否安全重试。

归属索引未完成时，在同一账户/标的/管理范围保留当前动作所需的前置索引检查和同步，保留既有有界扫描/资源限制，不追加 1 秒轮询或三次重试。必要证据仍缺失则立即返回未提交失败，后续同步由后台继续，后台不代为提交该保护动作。只有当前目标依赖已核实才继续；不能以无关全历史索引积压作为统一拒绝原因，也不能跳过真正的归属、权限或数量校验。错误输出区分“本地同步尚未完成，未提交”和“交易所已明确拒绝”。

### 5. 内部结构回执与模型文本分开

内部执行、审计、幂等重放、停止策略及费用记录继续使用原结构化事实。模型边界使用确定性文本渲染，不额外调用 LLM；`tools_node`、绑定聊天及 MCP 模型展示边界必须在渲染前完成状态判断，不能再从中文字符串猜测执行状态。保留现有机器消费的结构契约和 MCP structured content，模型可见文本简化。

每项一条，保留动作序号、目标/订单 ID、必要数量价格、真实结果、必要错误原因。缺失订单 ID 时以本项动作和参数标识，不输出 null；父子操作 ID、client ID、版本、重试计数、准入树、audit_reference 和重复账户快照不进入正常模型文本，但留在后台。需要修改替代单时保留实际可操作的新旧订单身份，不能为了省字丢失目标。

示例：
```text
1. cancel：订单 xxx，撤单成功。
2. open：0.08 ETH @ 2335，请求失败。原因：网络超时，提交结果未知，请勿重复提交。
3. open：0.05 ETH @ 2300，未执行，前序操作结果未确认。
```

保护同步失败示例：`close（止损）：0.08 ETH，失败。原因：持仓归属证据同步未完成，未提交。`

### 6. Paper 独立管理 tab

在 `AdminPage` 增加与 MCP 同级的 Paper tab，移走原内嵌面板。提取共享数据加载/密钥弹窗或使用共享回调，保证原 Paper 设置和“创建 Paper Key”仍可工作；不复制一套 MCP 管理业务，不改变密钥默认 namespace/scopes。沿用响应式 tabs 和中英文文案。

## Risks / Trade-offs

- [统一锁可能引入死锁或长时间占用] → 固定锁顺序，避免在数据库写事务中等待网络；用受控交错测试覆盖前台和后台。
- [字符串回执导致停止策略失效] → 先以结构化结果完成内部计算，再渲染模型文本，覆盖 Agent/chat/MCP 消费链。
- [旧版记录读取方式被误扩展] → 以 e600b5c 的 7 天成交/平仓来源为对照，只恢复用户确认的记录口径，不恢复全历史权益统计或全部工具日志。
- [退役投影导致有效记忆不可读] → 保留已发布内容和历史审计，切换新内容直接发布，验证重启和人工编辑。
- [前置必要证据仍不完整或接口超时] → 明确未提交失败或提交未确认，保存之前成功项及尾项未执行事实，不隐式补单。

## Migration Plan

1. 先建立隔离交易所测试及读取兼容性测试，再替换记忆生成/读取和模型回执边界。
2. 停止旧 JSON 投影任务生产及恢复扫描，保留历史诊断、有效文本、来源身份和旧请求哈希；新增文本格式标记仅由程序维护。
3. 移动 Paper 面板，更新说明及 README/docs。运行针对性后端测试、前端构建和管理页面人工验证。
4. 发布遵循仓库单独的 archive/release 流程；本次 proposal 不提交、发布或重启服务。回退需保留本次生成的原文和所有交易证据，不能清库或重放交易；旧程序依赖投影时应先确认其读取兼容，不能宣称二进制回退天然无损。

## Open Questions

- 本次生产版本冲突的精确竞争写入点仍待隔离复现；该调查只决定锁与对象刷新的具体改动位置，不改变已确认执行语义。
