# Design

## Context

见 proposal.md。前台直接读 localStorage 判断权限，而 axios header 依赖 App 的旧 state；两条记忆保存路径均缺少错误反馈。新闻存储含 ISO 偏移，模型压缩可能省略它。

## Goals / Non-Goals

实现跨标签页凭证一致、可见保存反馈及事件时区保真。不迁移数据库、不改写历史、不新增数据源或交易行为。

## Decisions

- 使用浏览器存储订阅作为统一登录状态，登录/退出同步写入，API 请求时读取最新凭证；防止旧身份校验失败清除新的登录。
- 沿用记忆 PUT 请求。确认成功后按 config_id/bucket_start 更新页面数据并刷新；失败在编辑框显示并保留草稿，禁用重复提交。
- 共用纯函数为 ISO 时间添加可读说明，保留原值和原偏移，不使用把无时区值默认为 UTC 的旧解析器。只为可明确解析的时间比较预定时刻与本次读取时间；该结果不代表实际公布。
- 新闻读取、摘要输入及文本上下文共用时间说明；统一模型规则进入决策、临时聊天及两个摘要阶段。摘要规则版本参与缓存键。
- 现有快照读取时补充时间说明，无需改写持久历史。新闻采集及评分范围保持原样。

## Risks / Trade-offs

- 模型自由文本仍可能犯错 → 给出程序计算的时间依据及显式规则，验证完整输入和 GDP 仅分析回放；不以字符串替换重写历史。
- 保存后行情请求慢 → 已确认正文先更新，保留现有刷新防竞态逻辑。
- 发布可能部分失败 → 既定脚本逐阶段停止并报告 Git/镜像状态，不操作生产容器。

## Migration Plan

无数据库迁移。验证后同步规范、归档并提交 beta，运行既定发布脚本（包含容量验收），推送不可变镜像和 latest。用户自行更新服务器。
