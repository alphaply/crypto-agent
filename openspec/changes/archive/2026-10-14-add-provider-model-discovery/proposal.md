# Proposal

## Why

当前新增模型需要手填模型 ID，容易拼错或依赖过期预设；已有 Jev 模型列表又要求先保存一个模型配置才能读取，无法帮助用户完成第一次添加。需要直接使用正在填写的供应商地址和凭据获取模型候选，减少配置步骤，并保留不提供列表接口的供应商的手动填写路径。

## What Changes

- 在新增和编辑模型抽屉中，连接信息完成填写后自动获取供应商模型列表，提供搜索、单项选择与手动刷新；无需先填写模型名或保存渠道。
- 支持项目已有的 OpenAI 兼容、DeepSeek、Anthropic Messages 和 Jev Decisions 渠道，按实际配置协议访问列表接口。列表来自目标供应商，不用快速预设或 models.dev 目录代替。
- 增加受现有管理鉴权保护的后端发现接口，支持当前草稿凭据和同一已保存连接的凭据；请求只读、错误脱敏，前端不直接请求供应商。
- 保留手动输入和当前已选模型；空列表、不支持、鉴权失败、限流或网络失败有明确状态，旧连接的迟到响应不能覆盖新连接。
- 统一 Jev 添加时的列表选择体验，保留已有消息评分查询接口兼容性。仅获取候选，不自动新增所有模型、保存配置、切换协议、修改价格或发起生成测试。
- 明确主规范中“在线探测”的边界：生成与推理能力测试仍须手动触发；自动只读列表发现不证明模型的工具调用、推理或其他能力已验证。

## Capabilities

### New Capabilities

- `provider-model-discovery`: 从当前渠道连接获取模型候选，覆盖草稿/已保存凭据、协议适配、搜索选择、失败回退及请求状态隔离。

### Modified Capabilities

- `model-reasoning-observability`: 明确只读模型列表发现与生成/推理能力探测的不同触发方式，保持协议和推理配置显式变更。

## Impact

- 前端：`frontend/src/pages/AdminPage.jsx` 的模型抽屉、新的共享模型选择组件与请求状态逻辑；`ScorerProviderFields.jsx` 的 Jev 列表入口合并。
- 后端：`backend/app/api/config.py`、专用请求/响应 schema 和 `backend/app/services/` 模型发现服务；复用现有运行配置读取、协议解析及 HTTP 客户端。Jev 连接校验需与模型执行校验分开。
- 接口：新增 `POST /api/config/provider-models/discover`；保留 `GET /api/news/scorer-models` 的现有返回结构和权限要求。
- 测试与文档：新增离线发现/鉴权/草稿测试，扩展模型抽屉浏览器夹具及 Jev 回归，更新 README 与管理工作台文档。
- 无数据库迁移，不改变现有单模型保存结构、渠道凭据复制规则、计价映射或运行中的任务。新增能力不引入新的第三方依赖。
