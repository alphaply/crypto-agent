# Design

## Context

动机及用户症状见 `proposal.md`。代码检查确认以下链路：

1. `memory_agent.MEMORY_REVIEW_POLICY` 包含单 `summary` JSON 示例；`run_memory_review()` 在独立模式把 `PROJECTION_POLICY` 追加在其后，要求覆盖前面的格式。两套输出要求同处一条程序指令，使用 user 角色时还会与自定义素材合并。
2. `context_projections.ProjectionReview` 强制要求 `summary`、`memory`、`projections`，`validate_review()` 还检查来源覆盖、身份、哈希、引用及执行禁令。用户提供的仅含 `summary` 的响应必然在结构校验处失败。
3. 通用 `invoke_with_retry()` 只重试选定的传输错误，不会针对该结构错误提供纠正信息。现有记忆调用通过 `MAX_MODEL_CALLS=3` 限制实际请求数。
4. 每轮记忆队列与投影后台转换分别记录三次失败后停止；旧 `publication_revision` 迁移已执行过时不会再次恢复新失败。决策读取只使用来源仍有效的 `ready` 投影，没有有效投影就返回用户看到的两个“尚无已发布”提示。
5. 正常每轮整理可原子保存新记忆及其投影；仅投影转换的 `process_projection_updates()` 只发布已有来源，不会凭空新增短期记忆。因此恢复必须同时考虑投影失败与记忆生成任务失败。
6. 现有测试覆盖合法完整投影、语义拒绝、已发布内容保留和退避，但没有覆盖模型先返回旧单 `summary` 契约后纠正，以及旧故障恢复后两个 Prompt 区块首次出现内容。

没有取得生产数据库和完整请求，不能仅凭空提示断言原文丢失。实施时用脱敏状态确认原文是否存在、来源是否仍有效、两个队列的失败原因；不要求在线交易或额外真实模型探测才能完成离线回归。

## Goals / Non-Goals

**Goals:**

- 输出要求、解析分支和发布前校验使用同一模式选择结果，正常成功仍只需一次请求。
- 在既有成本上限内修复可恢复的结构错误，失败保持可诊断且不污染持久化结果。
- 修复已部署数据中因旧契约失败而停止处理的来源，使首次发布可通过现有后台工作器完成。

**Non-Goals:**

- 不让决策 Prompt 读取时同步调用模型、修改队列或承担历史转换。
- 不将 `summary` 原文直接充当策略视图，不把缺失 `memory` 或 `projections` 赋默认值。
- 不更改交易执行、恢复许可、策略摘要生成协议、供应商协议/推理参数、用户自定义文件和已发布投影的 `VERSION`。
- 不自动重试所有历史故障、不重放 `partial` 规则写入、不构造不存在的成交或历史记忆。

## Decisions

### 1. 选择唯一输出契约并隔离自定义素材

把记忆的内容整理规则与输出 envelope 分开。请求构造先固定 `projection_context` 是否存在，再选择单 `summary` 或完整投影格式；程序指令只携带所选格式，不再使用“覆盖前面格式”的拼接方式。投影格式的字段说明与校验模型保持一致，并通过测试校验 required 字段、空来源情况和嵌套结构，避免手写示例再次漂移。

自定义 Prompt、原文及历史证据仍完整提供并明确标为素材。程序输出约束作为所配置指令角色的有效要求；user 兼容模式在素材块结束后再次明确使用同一契约，不能出现两种有效输出要求。保留 inline/file 的现有选择优先级以及 summarizer 的角色和渠道配置；不修改用户磁盘文件或用正则删除历史正文。原文摘要与纯策略投影的内容职责、篇幅指导分别说明，避免把“保留执行事实”误当成策略正文要求。

待转换来源为空时仍要求本次新记忆的 `memory`，`projections` 必须显式为 `[]`；有来源时逐一输出真实 ID/hash，不允许省略。非独立模式继续兼容既有单 `summary` 和已有的旧规则说明字段忽略逻辑。

备选：仅把投影说明移到末尾仍留下双重契约；给必填字段默认值会产生空或未经隔离的策略内容；强制服务商原生 JSON Schema 将扩大兼容范围，均不采用。

### 2. 至多一次格式纠正，共享实际请求预算

仅在投影模式，且响应已完整结束、未拒绝、没有工具调用时，将 JSON 解析或 schema 结构失败归类为可纠正格式错误。来源覆盖、身份/hash、执行引用和执行许可语义失败继续直接拒绝；供应商截断、拒绝及工具调用不进入格式纠正。

第一次可纠正错误且预算尚有余量时，在相同来源快照和输出契约下发起一次纠正生成。纠正指令只加入可信的错误类别和字段路径，如“缺少 memory、projections，需返回整个对象”，不把完整异常或模型返回内容提升为指令，也不重复附加完整历史上下文。修正响应从完整性到语义重新校验。第二次结构失败即停止该次整理，不再纠正。

`MAX_MODEL_CALLS=3` 覆盖首次调用、原请求传输重试和纠正请求的传输重试，所有实际 `llm.invoke()` 共用同一个计数器；纠正阶段至多一次启动，不因外层重试重置。保留渠道传输重试策略，但最多只使用剩余预算，不修改全局 LLM 错误分类使其他调用重试校验失败。正常完整响应为一次调用。

备选：无反馈原样重试不能明确修复原因；独立嵌套三次纠正与三次网络重试会放大成本；无限纠正会阻塞记忆队列，均不采用。

### 3. 独立记录尝试，严格发布

为每次实际调用记录相同 `operation_id`、所选输出契约、实际尝试序号、初次/格式纠正阶段、结构或语义错误类别、缺失字段路径。原始响应和已返回 usage 按现有审计/费用路径保存一次；首次失败保持 error，随后成功拥有独立记录，不将失败调用追溯改成 success。

`MemoryReviewResult` 只在完整验证成功后返回 completed 与 projection metadata；格式失败不缓存为成功。保留 `organize_memory()` 的成功结果复用、发布时来源/账户/标的核验、租约检查以及新记忆与投影的原子保存。未成功发布时已有有效内容保持可用；没有有效旧版时继续如实说明，管理状态提供具体错误而非伪造内容。

### 4. 对旧契约故障定向恢复，保留重试上限

引入独立于策略视图 `VERSION` 的记忆输出契约修订标记，以增量列或等价持久化标记覆盖 `decision_context_projections` 和 `memory_update_jobs`。新入队或开始尝试的工作标为当前修订；旧行初始为旧修订。这避免把本次修复后发生的新失败误判为历史故障，并保证已有 `ready` 视图持续可读。

后台工作器在当前任务租约内，对旧修订、终止 failed、来源仍有效且错误明确属于 `ProjectionReview` 缺少 `memory`/`projections` 的行执行一次 compare-and-set 重新排队。旧错误识别要求明确的校验器标题和对应字段 missing 诊断，不能只搜索正文中的字段单词；新错误使用稳定类别。事务中一起保存修订标记、恢复前错误/尝试信息并置 pending、attempts=0、next_attempt=0，避免重启或并发工作器反复复活失败任务。

对投影行验证原始来源 hash、当前任务/账户/标的。对记忆任务验证摘要来源、任务/标的及可信账户关联，无法确认当前范围时不自动恢复并保留诊断。completed、partial、ready、已失效或已删除来源、其他账户和无关错误均不重置；旧 pending 任务按现有退避继续，开始下一次尝试时记录当前契约版本。两个队列都沿用每项最多三次工作尝试和既有退避，修复后再次耗尽则停留 failed，管理端人工重试入口保持可用。

后台 tick 不依赖新交易产生：已有短期记忆和摘要可直接转换；没有短期记忆但存在本故障导致的有效失败记忆任务时，通过原四小时证据窗口完成整理和原子保存，再补齐摘要投影。成功结果仍按 operation_id 复用，已发布较新内容按来源时间优先。只有摘要、没有可恢复记忆任务的情况不伪造历史记忆，可继续发布摘要并由正常整理流程生成后续记忆。

备选：提升策略视图版本会使所有正常旧视图失效；全量重置 failed 会重跑鉴权、权限和语义故障；只依赖用户点投影重试无法恢复尚未生成原文的失败记忆任务，均不采用。

### 5. 验收包含实际读路径

使用临时数据库和离线模型响应，从用户的单 `summary` 响应开始复现，再返回合法完整结果；通过后台工作器、持久化和 `load_decision_memory()` 验证两个区块有真实策略内容与来源截至时间，绑定聊天和定时决策共享读路径。

覆盖已有原文但无 ready、无记忆原文但有有效失败生成任务、三个近期来源全部失败、无来源、已有 ready、手工修改/删除和账户切换等情形。模型持续错误时验证有界失败和无成功写入；有效策略条件保留，旧 unknown 禁令、原始回执和完整错误栈不回到决策 Prompt。

### 6. 批次依赖契约与运行时对齐

用户补充的 `TradeActionsSchema` 报错已用纯 schema 验证复现：省略策略或显式 `stop_on_error` 携带 `depends_on` 被拒绝，显式 `independent` 携带合法此前索引可通过。现有 JSON Schema 把依赖展示为可空且缺少字段联动说明，运行时却拒绝 null。

将依赖定义为可省略的严格整数列表（显式 null 无效），保留 `model_fields_set` 驱动的省略序列化，避免改变旧操作哈希。字段描述和工具示例明确显式策略、零起点、更小且不重复索引以及 completed 条件；执行模式 independent_exits 不代表批次策略 independent。校验错误拆分为空值/策略不符/非法索引，指向具体动作，给出修正要求。错误仍发生在任何交易写入前；不自动补 independent、删除依赖、继续执行或绕过审批。Agent 和 MCP 使用同一规范定义与验证，运行时执行循环不变。

## Risks / Trade-offs

- [纠正增加请求成本] → 只对选定结构错误启动一次，并与传输调用共享三次硬上限，审计区分每次费用。
- [模型仍不遵守契约] → 严格验证及有界失败继续生效；恢复状态可诊断，不能承诺所有渠道必然成功。
- [旧错误字符串存在不同表现形式] → 对明确签名做定向匹配与回归，无法确认的行保留人工重试能力，不扩大自动恢复范围。
- [旧任务缺少可信账户信息] → 无法核对范围的行不自动恢复，避免把历史其他范围内容发布到当前任务。
- [重启或并发导致重复恢复/付费] → 事务标记、同任务租约、稳定 operation_id 和成功结果复用共同约束。
- [原文实际不存在] → 如实保持无已发布提示，不把“没有错误”作为“记忆已恢复”的验收结果。

## Migration Plan

1. 在临时数据库验证两种旧失败状态及当前 ready 状态，确认迁移增量且重复执行幂等；保存失败诊断及来源信息。
2. 按正常 apply 完成代码与离线回归；本提案阶段不修改生产数据、不调用真实交易或付费模型。
3. 部署修复版本后，在现有后台 tick 中执行一次定向恢复；管理端确认 pending/failed/已发布数量与真实来源时间，再核对下一轮默认上下文的实际内容。发布镜像与生产重启仍遵循仓库独立流程。
4. 回滚代码时保留增量标记和审计，已发布视图版本及旧原文不变；禁止通过删除数据库或清空标记触发无界重跑。旧版本可能再次出现格式失败，需保留失败状态供后续处理。
