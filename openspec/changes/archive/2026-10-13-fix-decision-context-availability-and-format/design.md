# Design

## Context

动机见 proposal。已检查 `context_projections.py`、`decision_context.py`、`memory_service.py`、`memory_updates.py`、`database_memory.py`、`trade_context.py`、history 管理接口及相关测试。

- 投影按任务、账户、来源 ID/hash、版本保存。`load_strategy_views` 先取当前一份记忆和最近三轮摘要，再以 ready 判断可读；只有记忆尝试查找较早 ready 来源。执行引用解析与两类文字共用异常出口。
- `persist_projections` 用“当前最近来源”检查结果，导致模型调用期间新摘要到达后，已经完成的较早来源可能被跳过。
- 每轮记忆通常新建稳定来源 ID；滚动整理可更新同 bucket。现有保存原文和附加策略视图分属两次提交，存在新原文可见但对应视图不可见的间隙。
- 手工修改和删除通过原始来源内容 hash / 存在性使投影失效，这一语义需要保留。
- 管理端已有记忆整理操作；后台采用同一任务租约、有界尝试和退避。不能在 Prompt 读取路径等待或调用 LLM。
- 持仓、订单、coverage、issues 已经有结构化事实，现有渲染直接 json.dumps。

## Goals / Non-Goals

**Goals:** 已发布内容持续可读、正确处理候选和并发、独立降级；当前事实精简且不丢操作信息；离线验收真实生成的 Prompt。

**Non-Goals:** 不重新设计记忆模型或交易准入，不引入新后台模型链路、字符截断、真实交易/模型验收，不改变其他退出模式的显示。用户已明确授权完成规划后直接 apply。

## Decisions

### 1. 复用 ready 投影作为持久化已发布内容

独立读取每类来源的全部 ready 候选，与其原始来源关联，校验任务、账户、标的、版本和 hash，再按来源截至时间选最新一份记忆 / 最新三份摘要。整理队列只负责新候选；最新来源 pending 不影响旧 ready 内容。来源不存在、人工改动 hash 或范围不符的内容不再使用。时间按原来源而非 updated_at 排序，较晚完成的旧任务不能顶替新内容。

新增轻量发布/修复迁移标记，在既有表增量迁移，保留现有 ready 视图版本；已有失败转换在首次升级获得一次有限重试机会（最多沿用三次），不在每次启动或每轮决策重置次数。继续用同一租约、幂等结果和 worker；管理端可显式重新排队失败来源。

选择复用已有投影而非复制第三份记忆表，避免手工删除和历史清理产生新的孤儿副本。读取不调用 ensure/转换或更新队列，纯读 published 内容。

### 2. 发布和原文写入的一致性

近期摘要转换按提供的 source ID/hash 重新读取原始来源校验，不再要求它仍位于当前最近三条。用数据库事务一次提交已校验来源集合；手工修改/删除竞态通过事务内重新校验拒绝过期结果。

给短期记忆存储增加可选的已校验 projection 元数据，仅内部整理调用传入。新记忆原文与对应 ready 策略视图在同一事务内落库；失败回滚全部，原记忆仍可读，操作结果缓存供后续重试使用。直接历史写入和普通模式沿用原契约。记忆服务不再在提交原文后另行附加视图。

### 3. 独立读取与管理状态

策略文本、近期摘要、执行引用各自处理错误。单条损坏跳过并记录诊断，其他有效内容继续可见。先保存读到的文字，再解析引用；执行证据失败按原操作身份返回 resolution=unavailable，不擦除文字。当前未发布来源中的执行引用仍参与异常解析，避免遗漏新执行问题。

Prompt 只给已发布正文和真实截至时间，标题改为“近期已发布策略摘要（最多三条；历史计划，不是成交证明）”。没有发布内容时用单行“尚无已发布…”；后台失败与排队不再逐来源注入正文。数据库整体无法读取时仍如实报告读取失败，不能凭空创造内容。

新增管理鉴权保护的 GET `/api/history/short-memories/projections/status?config_id=...` 和 POST `/api/history/short-memories/projections/retry`（仅 config_id），提供可读版本截至时间、pending/failed 数、错误和重排队数，不调用模型。记忆管理页在选定任务后展示这些状态与失败重试入口；公开记忆接口不新增内部错误。点击现有“整理”仍遵循既有执行语义。

### 4. 纯函数格式化交易事实

`render_positions` 输出单行方向、数量、均价、浮盈和归属，避免占位符外层再出现“持仓：持仓：”。浮盈按约数保留两位，数量和价格使用十进制无无意义尾零表示，不能按固定小数位截断微小数量。

`render_orders` 输出紧凑 Markdown 表格：`ID | 用途 | 数量 | 价格 | 状态`。用途包含方向和入场/止损/止盈/平仓及订单类型；条件限价同时写触发和限价。fixed 显示剩余标的币量，all 为“全部（触发时）”；已触发子单如有已确定量同时注明。不默认展示 client_id、null、内部 source/snapshot_* /verified 字段。不同归属、父子身份等关键差异以行内短注保留。

在两个区域按真实来源集中列观察时间（上海时区并明确时区）；来源时间不一致用范围或分别展示，不把本地核验时间当成交易所时间。未知时间明确未知，不填渲染时刻。

coverage 和 issues 分别用短句：保留缺口、fixed 数量超额、影响方向/净仓范围、目标身份、缺失事实和最后已知量；不输出内部去重 identity 或整个回执。无异常只有数据完整时可写。特殊触发限价未成交风险保留一条提示。

### 5. 验收与兼容

用冻结状态的单元测试验证每个重要字段，而非依赖旧 JSON 子串。使用原用户三单例子作文本夹具，保留完整 ID、价格和量，并断言文本字符数显著减少（目标低于旧 JSON 的 60%，记录实际字符/可用本地 tokenizer 计数，字符不冒充 token）。测试 Agent 与绑定 chat 实际 Prompt 一致，其他退出模式不受影响。

## Risks / Trade-offs

- [历史从未有 ready 内容] → 后台有界补齐和管理端重试；不会把原执行禁令当作策略视图回退，也不会宣称原文丢失。
- [旧已发布策略较陈旧] → 保留真实截至时间，不称为最新三轮，新的有效结果完成后替换。
- [手工改写与模型完成竞态] → 发布事务内核对原始身份/hash；自动短期记忆更新与 ready 视图一次提交。
- [格式压缩掩盖未知与交易数量] → 测试 all/fixed、父子 ID、两种价格、极小值、归属、读取失败和数量冲突，不删实际异常。

## Migration Plan

1. 添加幂等元数据迁移和 published 读取；保留现有 ready 版本，不重做成功内容。
2. 接入事务发布、独立降级、后台有界修复及管理入口，再替换状态渲染。
3. 离线执行记忆/状态/Prompt/绑定聊天回归、管理 API 与 UI mock 验收，保存示例及 verification。
4. 更新文档。回滚可恢复旧代码并保留新增可空/默认字段与原数据；回滚会重新出现原有可用性问题，但不恢复/重放交易。
5. 本次只 apply；后续 archive 请求再按主规范同步和 Git/Docker 发版。
