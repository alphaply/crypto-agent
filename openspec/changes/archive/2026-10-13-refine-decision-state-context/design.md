# Design

## Context

动机见 `proposal.md`。本设计涉及上下文组装、交易证据和记忆持久化，包含兼容及升级路径，因此需要独立设计文档。

已经确认的代码路径：

| 路径 | 当前行为及影响 |
| --- | --- |
| `agent_graph.start_node` → `latest_operation_receipts` → `independent_exit_context` | 当前订单描述后附加完整历史回执；同一退出单又在独立退出段落重复展示 |
| `trade_recovery.latest_operation_receipts` | 按任务取 `updated_at` 最近 20 条后再筛标的，不按当前相关性或引用身份查证 |
| `chat_graph.model_node` → `recovery_context_text` | 绑定聊天复用启动上下文后，再追加完整历史核验块 |
| `reconcile_pending_trade_operations` 的独立实盘分支 | 遍历所有历史操作；有 scoped evidence 时连已完成操作也重新投影 |
| `recover_operation` | 本地投影路径也设置新的 `query.observed_at` 并更新回执；旧周期的限制与新生成时间容易混用 |
| `exit_context` | `plan.error` 可直接使周期显示待核验，与按结构化依赖判断的执行准入不一致 |
| `memory_updates.process_memory_update`、`database_memory.get_summary_logic_between` | 两条记忆入口读取摘要均缺少 `config_id`/`symbol`，后者也通过 `append_execution_receipts` 拼接证据；不能假定滚动入口没有回执 |
| `decision_record.read_decision_record` / `append_execution_receipts` | 最新结果只补到 `messages.current_receipt`，记忆输入使用原 `execution_results`；仅补 SQL 字段仍不足以修好证据传递 |
| `decision_context` | 默认注入最新完整记忆和最近三轮原始摘要；单独移除历史 JSON 仍会留下自由文本禁令 |

已有 `trade_cycle_evidence`、`trade_operation_evidence`、`trade_receipt_revisions` 支持跨周期追溯；订单证据分类和按动作准入已经存在。本次复用这些能力，不以模型文字判断交易权限。

现有规格要求“核验结果到达 Agent”“各入口状态一致”，没有要求默认提供全部历史。delta specs 明确展示层次，并补上记忆消费者及时间语义。

## Goals / Non-Goals

**Goals:**

- 默认交易状态随当前持仓、订单和真实相关异常变化，不随已结束历史条数增长。
- 从当前证据形成唯一的执行异常视图；自由文本不能增加交易禁令或解除执行层限制。
- 记忆模型可以整理策略背景，执行疑虑的存续和解除由程序读取证据决定。
- 保留原始回执、原始记忆、原始摘要和按需历史查询；本轮工具回执继续完整传给调用者。

**Non-Goals:**

- 不改变策略、仓位上限、杠杆、自动止盈止损时机、固定/all 数量语义或交易权限。
- 不取消真实 unknown/pending，不清库、删除旧周期、换 ID 重发或自动执行以前未执行的动作。
- 不引入每轮新的模型预检、恢复 Agent、交易令牌或人工解锁。
- 不重写摘要报告体系；`strategy_logic` 保持纯文本，新增的是内部决策输入投影。
- 不重做前端历史页面、MCP 输出格式或聊天记录压缩体系；本次修改默认注入，用户明确查询的历史和原聊天消息继续保留历史属性。
- 默认新视图限于 REAL/STRATEGY 的独立退出模式；共享读取函数的修复不得改变现货和附带保护的执行语义。

## Decisions

### 1. 由共享状态投影连接证据与决策输入

新增小型 `backend/utils/trade_context.py`，分开本地证据加载、纯状态投影和文本渲染。输入为本轮账户快照、任务/账户范围、相关周期和订单证据；输出为 `DecisionTradeState`，由定时决策和绑定聊天共享。使用已取得的快照及执行层提供的只读证据，不在文本渲染器中查交易所、恢复周期、撤建或调用模型。

内部结构建议如下，字段名称允许实现时与现有类型统一：

| 部分 | 需要表达的内容 |
| --- | --- |
| `scope` | 可信运行环境注入的 config、账户、标的及持仓模式；不让模型覆盖 |
| `positions` | 当前方向、数量、成本、盈亏、任务归属状态、真实观察时间 |
| `orders` | 当前有效 ID、普通/条件通道、方向和用途、状态、触发/限价、fixed/all、剩余量、观察时间 |
| `coverage` | 当前 SL 覆盖估计、未覆盖量、数量冲突；不是保证成交或额外交易禁令 |
| `issues` | 稳定身份、原因、缺失事实、作用范围、相关动作影响、观察时间、执行层恢复状态 |
| `evidence_state` | 分项来源、完整性、读错误、证据版本及生成时间；未知量不得补零 |

活跃单以当前通道和有效订单身份去重。原生条件单的触发母单/执行子单关联保留，异常中可以引用订单，但不再复制整条订单或回执。当前交易所可见但无法证明属于本任务的仓位或订单明确标识归属，不把账户总量冒充可管理量。

本轮已获取的交易所持仓/挂单负责说明“现在看见什么”；本地证据负责订单归属、累计执行和未决写入。两者冲突时保留分项时间和相关异常，不让任一来源静默覆盖另一来源。新的必要只读查证使用既有执行层预算；本轮无法取得完整证据时直接标识缺项，交易工具仍独立核验。

备选：在 prompt 中再写一次优先级。未采用，因为无法消除冲突源，仍需模型逐条解释历史。

### 2. 按当前影响选择异常，不按最近操作选历史

候选来源为当前活跃周期、相关未决订单/操作，以及仍可能影响当前账户标的的新周期残留。数据库读取必须覆盖历史中未解决的关联，不使用最近 20 条作为候选边界；允许索引、分页或聚合，但不可静默截掉真正相关异常。

复用 `classify_order`、`unresolved_orders` 和 `assess_admission` 的依赖语义，避免在上下文中重新用 `plan.error`、顶层 status 或错误字符串分类。执行层继续拥有最终准入判断。

| 证据情况 | 默认呈现 |
| --- | --- |
| 正常 open / waiting_trigger，相关状态已核验 | 活跃订单；无待核验标签 |
| 确认未接受且无执行影响 | 不进入当前异常；原拒绝按需查 |
| 已终态、执行量核实且无残留影响 | 退出当前视图，审计保留 |
| 提交结果未知、撤建未完成、终态成交量未知 | 精确到原操作/目标订单的异常 |
| 平仓完成但旧 all 或入场清理仍有影响 | 保留平仓事实，只展示剩余清理影响 |
| 当前归属、仓位或订单证据缺失/冲突 | 对应范围的数据缺口；不输出全面允许或全面禁止 |
| 仅历史 `continuation` 未刷新 | 不继承旧规则；当前所需证据确实缺失时单独形成缺口 |

模型尚未选择动作时，只给出已知影响，例如“该 LONG 剩余数量尚未确认，相关减仓量需工具核验”。不能提前凭一个类别级 `blocked_actions` 判断所有 open/close/edit；Hedge 方向独立和 One-way 共享净仓继续由既有逻辑区分。

每个 issue 由可信范围、周期、操作/订单身份和原因构成稳定键。不同原操作引用同一清理问题时合并显示，内部保留关联；生命周期由关联证据决定，不能单看某一条 completed。读失败时保留最后已知量与时间，同时将当前量标为未知。

备选：删除所有旧周期，或只保留顶层 unknown/pending。未采用，前者会漏掉旧 all，后者会漏掉 completed + cleanup.pending。

### 3. 默认状态、工具回执和历史查询使用不同输出层次

- `agent_graph` 不再调用 `latest_operation_receipts` 注入历史字典；独立模式通过共享状态渲染持仓、订单及异常。
- `exit_context` 保留必要数量和覆盖语义，去掉完整 JSON 和基于历史 error 的全局待核验判断，与普通订单文本合并去重。
- `chat_graph` 移除重复的 `recovery_context_text` 注入。每个新的用户回合取得新的当前状态；同回合已返回的 ToolMessage 继续说明刚发生的事实，不能再用启动时缓存覆盖它。
- 显式 `get_trade_operation`、MCP `get_operation`、同 ID 重放及历史页面保留完整回执。`latest_operation_receipts` 如仍用于 UI，可继续作为历史列表接口，不能再用于当前异常全集或精确引用解析。
- 自定义 `{positions_text}`、`{orders_text}`、`{short_memory_text}`、`{recent_summaries_text}` 保持可用，在适用模式下填入新视图；不改用户模板文件，也不删除用户显式写入的策略纪律。

正常示例（合成，非现场交易结论）：

```text
账户快照：10:00:03 CST；订单观察：10:00:02 CST
持仓：LONG 0.15 ETH，成本 2415；本任务已确认归属。
入场单：regular:entry-A，LONG 0.10 @2385，未成交。
退出单：algo:sl-A，SL 市价，触发2357，固定0.15，等待触发。
退出单：algo:tp-A，TP 市价，触发2508，固定0.08，等待触发。
退出单：algo:tp-B，TP 市价，触发2545，固定0.07，等待触发。
SL 未覆盖估计：0；挂单不保证成交。
当前相关执行异常：无（上述数据源读取完整）。
```

异常示例：

```text
LONG 原操作 close-A 已确认成交0.15。
旧条件单 algo:old-A 的撤销后最终状态仍不完整，可能影响同方向新入场。
最后证据时间：09:59:58 CST；执行层正在按原身份核验。
```

备选：压缩历史 JSON 到固定字数。未采用，按字符截断会丢身份/影响范围，历史仍可占据大多数上下文。

### 4. 分开观察时间、读取时间和本地投影时间

保留兼容字段，添加明确的本地/交易所证据来源和投影时间元数据。`position.observed_at`、逐单 `fill_observed_at` 等保存真实观察；`receipt_updated_at` 或新增 `projected_at` 只表示缓存变化，不能用作证据新鲜度。

`read_exchange=False` 不伪造新的交易所查询成功；新增来源字段并保留原实际观察时间。显式读取调用的 `query` 描述此次调用，分项证据时间仍独立。对于无当前周期或当前范围读取失败的结果，旧限制只留在历史诊断字段，不能作为当前 `rules` 或 `blocked_actions` 发布。

不新增一个“超过 N 秒即禁止交易”的全局阈值。新鲜度依据本轮读取、实际观察时间、范围/版本及已知写入或成交变化表达；真正动作检查继续使用既有有界刷新和并发版本校验。

备选：只重命名“最新原操作核验记录”。未采用，标题变化不能修复混用的时间或过期判断。

### 5. 后台按未完成关联和证据变化更新回执

调整 `reconcile_pending_trade_operations` 的独立实盘分支，正常推进以下集合：执行未明、正常活跃订单需要同步结果、清理/替代/晚到成交未完成，以及关联证据发生实质变化的操作。completed 不等于完全退出维护；是否退休同时检查关联依赖。

复用 scoped evidence 关联，记录已投影的证据指纹/版本作为本地水位。比较内容覆盖原意图的执行、关联清理、身份及成交量；仅缓存生成时间、查询时间变化，或无关后继周期版本增长，不算历史操作的新事实。未变化的已终结操作不再追加修订或更新 `trade_action_runs.updated_at`。

显式查询仍能读取历史；若确有新证据，按已有并发校验保存新修订。新周期的当前准入是查询时的独立视图，不通过每次维护重写全部旧回执来传播。后台只读回执投影与既有维护写入职责保持分开。

备选：仅删除“completed”的扫描。未采用，因为会遗漏已成交但清理未完成的操作。

### 6. 记忆证据按原身份读取，不依赖 UI 覆盖字段

新增共享“记忆执行证据”读取接口，输入可信 config/账户/标的和引用身份，输出原结果、最新结果、来源、证据版本/时间及解析状态。通过 `trade_operation_evidence` 和原请求保存结构解析父批次与子项；不通过任意字符串相似、数量或价格猜归属。

- 每轮与滚动查询都携带 `config_id`、`symbol`；当前账户范围由配置解析，不从模型输出接受。
- `decision_record` 明确分开原 `execution_results` 和消费者使用的最新投影，保证记忆实际收到最新结果。不能只写 `messages.current_receipt`。
- 输入集合为本窗口实际工具调用，加上旧记忆/近期投影中的执行引用。窗口外或最近列表之外的引用按身份查询，不受最近 20 条限制。
- 恢复父批次只更新真实提交项；not_executed 尾项保持未执行。旧账户记录作为历史保留，不借新账户结果解锁。
- 无匹配或证据读取失败返回具体 unresolved/unavailable，不将 completed、空仓或时间过久单独视作问题解决。
- 将当前已解决身份和剩余相关异常作为明确证据交给记忆模型，要求用新事实替换旧描述；原始摘要/记忆正文不就地清洗。

备选：仅修改记忆 prompt 为“删除旧限制”。未采用，因为没有最新对应证据时模型仍只能猜。

### 7. 为记忆和最近三轮摘要保存可供决策读取的策略投影

仅修复证据输入仍依赖模型下一次成功整理，而且旧最近三轮摘要还可能复活限制。采用来源可追溯的投影，保留现有原文并增加内部结构：

```text
source_kind: short_memory | strategy_summary
source_id + source_hash + projection_version
strategy_text: 市场假设、价位、策略理由、观察条件、历史教训
execution_refs: 原操作/订单/周期引用（不含模型编造的许可结论）
unlinked_execution_notes: 未能对应的历史疑虑（诊断素材）
status: pending | ready | failed
```

使用一张添加式本地表 `decision_context_projections` 存来源身份、内容哈希、投影版本、载荷、整理状态和重试元数据；来源范围由程序绑定。现有 `short_memories.version` 是顺序版本，不能用作格式版本，也不能依赖它发现原地人工编辑，故同时校验内容哈希。后台回执投影水位使用独立内部元数据，与记忆表分开。

扩展既有 `memory_review` 的结构化响应，在同一次正常调用中输出兼容 `summary` 及策略投影、被处理近期摘要的投影和执行引用。新增元数据进入记忆审计/幂等结果持久化，源正文和 `strategy_logic` 保持完整纯文本，不恢复结构化交易报告。对不适用模式仍采用原输出路径。

每条近期摘要由 source_id 关联，不允许模型发明来源或越过 config/账户；执行引用通过程序和提供的候选证据核实。模型只分离策略文字和执行陈述，不能输出 allowed/blocked_actions 或决定 issue 已解决。明显混入执行许可判断的策略投影不标记 ready；测试覆盖自由文本禁令和与之相邻的合法策略条件。

决策读取时：

1. 加载与源哈希匹配的策略文字。保留最近三轮的时间顺序，但只使用其 ready 投影；原文仍供历史查看。
2. 对执行引用读取当前证据，已解决且无相关残留影响的引用不再形成异常；未解决且与当前相关的引用合入统一 issues 并去重。
3. 不输出“旧禁止 + 新允许”的双份文本，不把执行状态写进可长期复用的策略段。
4. 记忆模型失败时继续使用有效旧策略投影；执行限制仍由新证据决定，因此解除无需等待新的模型调用。

未关联的旧文字不是执行事实：保留为诊断素材并由后台尝试根据原摘要工具链和身份关联。只有当前结构化证据支持的缺项才形成范围明确的异常；无法证明当前影响时不生成全局禁令，也不声称旧事件已解决。原 .37 与另一 .30 空仓记录不能互相替代。

备选：正则删除所有包含“待核验”“不加仓”的句子。未采用，因为会误删“等四小时收盘前不加仓”等真实策略条件，且无法覆盖改写后的同义描述。

### 8. 旧正文转换在后台进行，失败不会重新注入混合文本

首次使用时将缺少投影的最新记忆和最近三轮摘要登记为待整理来源，复用既有记忆 worker、配置模型、任务租约和退避机制。一次批量整理当前所需来源，不遍历全部历史，不在交易决策前同步等待模型，也不因每个新回合重复调用。

没有新交易摘要时也允许处理这项纯投影任务；它不需要交易图，不触发策略交易。幂等键包括任务、投影版本和来源哈希；旧 `run-memory` 的已完成结果不能冒充新版投影。正常每轮整理可顺便完成缺失近期投影，不重复安排同一来源。

升级过渡中，未完成投影的旧混合正文只在历史中可见；默认输入明确“策略背景整理中/暂不可用”，继续提供当前账户、市场和结构化异常。已有 ready 策略投影可继续使用并显示原截至时间。失败遵循现有有限次数与退避，不增加无界后台调用。

人工修改记忆后按源哈希使派生投影失效、重排整理；用户模板中直接写入的策略指令保持不变。聊天本轮及用户明确请求的历史 ToolMessage 保留，不扩展为整个聊天档案自动改写。

备选：升级时先清空所有短期记忆。未采用，源证据及策略背景应可恢复，且不能把删除当成核验。

## Risks / Trade-offs

- [旧自由文本无法完全程序化拆分] → 模型只负责后台策略投影，程序决定执行引用和当前异常；未投影文本不默认注入，保留原文和失败诊断。语义误分类仍是测试与人工审阅重点，不能把 schema 校验当成语义正确证明。
- [升级初期可能暂时缺少部分策略背景] → 明示可用性，优先处理最新记忆和最近三轮；当前市场和账户照常呈现。该取舍避免过期执行禁令继续主导决策。
- [隐藏历史误漏真实旧单] → 候选覆盖未解决关联及跨周期残留，不按状态顶层、年龄或分页上限丢弃；用旧 all 和 completed + cleanup.pending 验证。
- [停止全历史刷新漏掉关联变化] → 投影水位覆盖实际关联证据；新证据到来更新原操作，重启恢复未完成集合，保留显式查询。
- [当前快照与本地证据异步] → 分项观察时间和版本，冲突显示局部缺口；提交前继续既有并发和执行核验，不承诺跨接口原子快照。
- [两个入口修好一个仍污染] → 定时决策、绑定聊天、每轮记忆、滚动整理、自定义占位符和近期摘要组成端到端验收矩阵。
- [投影新增模型负担] → 复用一次正常记忆调用批量处理，迁移按来源哈希幂等且有界；不引入每轮交易前的模型调用。

## Migration Plan

1. 添加式初始化投影表和回执投影水位元数据；旧表、首次回执和修订不删除。测试空库和升级库重复初始化。
2. 部署共享状态视图、证据身份读取和记忆投影生产/消费；在独立模式一起启用，避免只删除 JSON 却仍注入旧混合记忆。
3. 为各启用任务的最新记忆和最近三轮摘要登记后台转换，复用既有并发租约、重试和审计；模型不可用时按上述过渡行为运行。
4. 用合成样本核对默认 prompt：1 笔持仓、4 张活跃单，无关已完成回执不出现；真实相关异常仍可见。核对显式历史查询及本轮回执完整性。
5. 回滚时保留新增数据，旧版本可继续读取原始摘要和记忆；旧版不会识别新投影，可能恢复本次修复前的上下文问题，需明确记录。回滚不重放交易、不删除 unresolved，也不通过恢复旧字典来证明当前准入。

## Validation Approach

使用临时 SQLite、fake exchange 和固定模型响应，不运行真实下单或模型连接测试。验证当前视图的事实和范围不受无关历史增加影响，不能仅检查某个字符串变短。

| 场景组 | 必须观察的结果 |
| --- | --- |
| 14 条无 pending 回执、3 条旧限制、正常当前仓位 | 默认输入没有旧回执块/旧限制；当前单据准确且只展示一次 |
| 增加 100 条无关已完成历史 | 当前交易状态文本和异常集合不变 |
| 旧 all、未知平仓、终态缺成交、completed + cleanup.pending | 真实异常保留准确身份和作用范围；金融写入次数不增加 |
| query 新时间 + 旧观察时间、读失败、版本冲突 | 不伪装当前证据，不输出全面放行或陈旧封锁 |
| 四小时外旧 unknown 后被核验、批次子项 | 记忆拿到同身份最新证据，未执行尾项不改状态 |
| .37/.30 不同事件、跨账户/任务、无对应身份 | 不错误解决、不借用另一范围的证据 |
| 原记忆与最近三轮都含禁令，模型失败 | 已解决限制下一轮退出；有效策略条件保留，原文仍可审计 |
| 未投影旧数据、人工编辑、worker 重启/重复任务 | 源哈希失效生效，转换幂等且有限重试，无交易重放 |
| Agent/Chat/mock/REAL/MCP 及其他模式 | 当前事实对齐；审批、权限、幂等、数量及既有模式行为保持 |

优先扩展 `test_independent_exit_context.py`、`test_independent_receipt_recovery.py`、`test_decision_memory_context.py`、`test_turn_memory_and_review.py`、`test_memory_workflow.py`、`test_memory_update_retries.py` 和 `test_trade_evidence_concurrency.py`；新增聚焦端到端场景的测试文件，不以大量镜像实现的单元断言代替行为验收。
