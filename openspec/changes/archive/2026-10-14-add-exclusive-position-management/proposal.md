# Proposal

## Why

Agent 启动前已有仓位，或运行期间有人在交易所加减仓、提前平仓、修改订单及新增挂单时，现有系统会把外部成交或缺失周期视为归属冲突，可能拒绝后续仓位管理。用户已确认由指定 Agent 独占管理同一账户、交易对和方向；本变更同时修复 MCP 宕机，并简化被操作 ID、周期报错及完整账本淹没的记忆和收益展示，让 Agent 使用当前事实正常管理仓位。

## What Changes

- 为 REAL 合约独立退出任务及 MCP 合约配置增加显式启用的独占管理策略，管理范围包含已有仓位、范围内普通/条件订单和后续外部成交；同一范围只允许一个持久化管理者。
- 启动、后台维护和交易执行前自动发现并核验交易所变化；优先恢复原周期，无法恢复但已获独占授权时记录真实接管基线，不要求模型先执行手工接管或解锁。
- 将运行期间外部加减仓、先加后减、提前全平、新增/修改/撤销挂单纳入同一事实模型。新增订单保留来源、原生语义和订单身份，核验后可通过既有工具管理。
- 根据外部成交和剩余仓位推进周期闭合，核验残留订单和晚到成交；保留原操作幂等、旧周期历史及具体动作的证据限制。
- 自动同步不自动撤销外部订单，也不按比例调整固定退出量。Agent 根据最新状态提出交易意图；后台仅执行已授权的周期清理与持久化维护意图。
- 统一内置 Agent、绑定任务聊天、MCP 和前端的当前仓位、外部变化、可管理订单、保护覆盖与对账状态。
- 记忆正文只保留策略判断、关键价位和有效教训；不写入 operation_id、resolution、周期报错、恢复步骤、账本 JSON 或收益统计。当前持仓和挂单由最新交易状态提供，不能从“本任务无自有周期”推导为“交易所无持仓”。
- 收益默认只显示权益变化、盈亏和回撤，附简短统计区间/截至时间。详细成交、费用、完整周期、归属缺项及同步记录放到按需详情中；数据不足显示暂不可统计，不显示虚假的零收益。
- 周期对账、归属核验及原操作恢复交给后台和执行层；Agent 不再例行查询历史 ID 或在记忆中维护解锁清单。真实未核验提交仍按本次动作依赖限制，历史报错或读取失败本身不构成禁止交易。
- 包含当前 MCP 宕机修复：采集服务器本机健康、公网 TLS、反向代理及容器日志，修复已确认的入口或应用故障，并以公网 OAuth、MCP 和网页实际恢复作为验收。为 MCP 读取建立总预算、有限并发、市场目录缓存及阶段诊断；移除异步认证中的阻塞数据库访问和每次存储访问重复建表。验证慢请求不会耗尽 Web 的服务能力。
- 未开启独占管理的配置保留原归属及显式接管规则；保留现有工具参数、权限、审批和历史操作身份。

## Capabilities

### New Capabilities

- `exclusive-position-management`: 独占管理范围、启动接管、外部订单与成交持续对账、跨进程协调、权限及配置生命周期。
- `mcp-service-resilience`: 当前宕机的分层诊断、故障修复与公网恢复验收，以及读取预算、并发隔离和事实新鲜度。

### Modified Capabilities

- `independent-position-exits`: 经配置授权的外部仓位接管与周期恢复，外部平仓、重开和晚到成交的周期闭合规则。
- `trading-tool-contracts`: 已纳管外部订单的 edit/cancel、调用内部自动核验及稳定的操作回执。
- `decision-state-context`: 当前状态与策略记忆分离，记忆只承载策略判断、关键价位和有效教训；收益采用三类简明指标，账本及周期诊断按需查看，后台处理恢复而非让模型维护解锁流程。

## Impact

- 后端：任务/MCP 配置及校验、增量数据库结构、execution_ledger、position_adoption、independent_cycle_recovery、independent_exits、准入层、scheduler、工具注册及状态投影；memory_service、context_projections、decision_record、performance_context 的记忆素材、输出和统计展示；MCP auth/store/service/tools 和应用启动。
- 前端：任务与 MCP 配置的独占管理设置、仓位/挂单的来源和对账状态、策略记忆正文、简明收益及按需账本详情。更新 README、docs/MCP.md、docs/WORKBENCH.md 和部署排障说明。
- 验证：交易所离线适配器、跨进程竞争与故障注入、人工干预场景、幂等回放和 MCP/Web 并发可用性；以用户提供的 ETH 多仓/外部挂单及历史失败样本验证记忆无内部字段、收益不重复、当前仓位不被旧周期覆盖。
- 第一版覆盖 Binance/OKX 的 REAL + swap + independent_exits；现货库存归属、附带保护模式和多策略共享净仓分配保持原行为。
- 记忆与收益简化复用 REAL/STRATEGY 已有统计和策略投影；不改收益计算口径、不把共享账户权益变化伪称为 Agent 独立盈亏，不删除历史账本、原始回执或审计证据。
- 不删除周期，不增加自动开仓策略，不默认重发未知金融写入。MCP 故障修复在实施时须取得生产 TLS/代理/容器证据，不能把本地代码治理当作当前公网故障已修复。此轮只生成规划；生产配置修改、发布和重启须在后续实施中按实际授权执行。
